# 麦麦搬运喵（maimai-courier-plugin）

麦麦在群聊间分享消息的独立 MaiBot 插件。源群出现已选候选类型的消息后，由源群
Maisaka 依据可编辑标准自主决定分享或沉默；群友也可明确请求，通过 `forward_message`
把本群指定源消息转发到一个白名单目标群，可另附一条延迟 0.5 秒的评论。

**当前路径：插件进程内客户端 → 已有 SnowLuma 正向 WebSocket 服务端 → QQ。**
源消息、评论和必要平台查询都使用本插件自己的连接；不启动独立转发服务、不借用
适配器 API、不调用宿主 `send.*`，故障时也没有备用发送路径。

**本轮仅通过离线合成验收，真实 QQ 联验未授权、未执行。** 服务端契约 U1–U8 仍未确认，
实际启用前须满足 [真实联验清单](docs/real-qq-validation.md)。以下支持范围是实现契约，
不是线上效果保证；尤其图片安全获取、卡片展开和回执含义不能由模拟测试证明。

## 安装前提与资料

- 插件版本 `0.1.0`；清单声明 Host `1.2.5–1.99.99`、SDK `2.8.0–2.99.99`。
- 插件专属依赖只有 `_manifest.json` 声明的 `aiohttp>=3.14.3`，由宿主依赖流水线装载。
  无需旧服务的 `pyproject.toml`、`uv sync`、服务 CLI 或额外常驻进程。
- SDK 2.8.0 的公开源码与发布包接口已核对，**线上实际加载版本仍未确认**。宿主源码
  锁文件的 2.5.2 既不证明当前运行版本，也不满足本插件下限；部署前另行确认。
- 能力仅为 `message.get_by_id`（可信源查询）、`chat.get_all_streams`（来源会话）、
  `maisaka.proactive.trigger`（源群判断）。不声明 `api.call`、`send.*`、`chat.open_session`；
  Hook 名称不是能力。
- [直连运维清单](docs/direct-snowluma-operations.md)：端点、环境、账本、备份与停止条件。
- [CONTEXT.md](CONTEXT.md)：领域术语；[ADR 0007](docs/adr/0007-direct-snowluma-websocket-client.md)：当前架构决定。
- 当前行为以主规格 [跨群转发](openspec/specs/cross-group-forward/spec.md) 与
  [直连客户端](openspec/specs/snowluma-direct-client/spec.md) 为准；直连变更的提案、设计与
  验收记录已归档到 `openspec/changes/archive/2026-10-04-direct-snowluma-websocket-forwarding/`。
- 旧服务、依赖与测试完整保存在 [历史区](history/snowluma-forward-service/MANIFEST.md)，
  [隔离记录](history/snowluma-forward-service/ISOLATION.md) 说明其退出路径；不维护两套可部署产品。

本插件不 import、不复制、不依赖复读插件，不读取其他插件的配置、凭证或投递记录。
获得部署授权后，把活跃插件目录放到宿主插件目录，由宿主加载清单依赖。历史区仅供追溯，
不加入 Python 路径、不启动其中代码；本轮没有执行部署。

## 配置与启用门槛

四节配置的安全默认如下，与 `config.py` / `config.toml` 一致：

```toml
[plugin]
enabled = false
config_version = "1.4.0"

[auto]
enabled = true
message_types = ["forward"]
share_criteria = "结合消息内容与目标群，自行判断是否值得分享；不值得或无法判断时保持沉默，不必回复，不要编造消息内容。"

[scope]
source_groups = []
target_groups = []

[snowluma]
websocket_url = ""
token = ""
token_env_var = ""
```

- 总开关默认关闭，自动入口默认开启、仅选合并转发，白名单默认全空。关闭总开关时
  工具和观察 Hook 都不会建立发送连接、执行平台动作或自动判断；加载本身不联网。
- `snowluma.websocket_url` 是操作者确认的完整正向 WS 端点，默认空。明文 `ws` 只允许
  回环、私有或链路本地目标（主机名在建连前解析确认，解析出公网或失败即拒绝），
  公网目标必须使用可验证证书的 `wss`。不接受 `0.0.0.0` 等监听地址、URL 用户信息、
  查询串、片段或其他协议，不跟随认证重定向、不自动探测端点。
- `snowluma.token` 可直接填写令牌，非空且非全空白时优先使用。令牌明文保存于插件配置，
  请限制文件权限，避免把含真实令牌的配置提交到仓库或分享。
- `snowluma.token_env_var` 只填环境变量名；`token` 留空或全空白时才在建连时读取该变量。
  两种方式默认均为空；凭证只随认证头发送，不进入 URL、日志、账本或工具结果，
  不自动读取适配器凭证。缺值、认证失败或实际登录账号不能对应可信宿主账号时停止发送；
  配置令牌认证失败不会改用环境变量重试。
- 容器中的 `localhost` 指该容器本身，不是宿主机。跨容器/跨主机须由操作者提供
  实际可达的受保护端点，不能直接照抄截图端口：明文目标必须解析为回环、私有或
  链路本地，公网地址必须走可验证证书的 `wss`。
- 旧 `[service]` 不自动映射到直连地址，不要求填写旧服务身份或迁移确认；存在旧状态
  证据仍会阻断发送，见下文。
- `auto.message_types` 只接受 `text` / `image` / `forward`。空列表停止所有自动机会，
  不影响合法显式工具调用；未知类型明确拒绝。图文归 `image`，卡片优先归 `forward`。
- 分享标准最多 4000 字符，空/全空白回退上述默认。它只是源群模型的自然语言判断依据，
  不保证模型遵循，不改变权限，也不成为群友明确请求时的额外内容偏好门禁。
  开启普通文字或图片候选会增加模型调用。

先保持关闭，确认运行版本、U1–U8、端点与环境注入、本插件账本完整性及两级白名单，
获得真实测试授权后再启用。评论延迟、超时和容量均为代码常量，不是配置或模型参数。

## 群聊工具 `forward_message`

公开参数仅三个字符串：`message_id`（必填，本群源消息 ID）、`target_group_id`（必填，
目标白名单中且不同于源群）、`comment`（可选，默认空，普通文本）。

```json
{"message_id": "1234567890", "target_group_id": "222222222", "comment": "这条挺有意思"}
```

源群、平台和账号来自宿主 Planner Hook 签发的一次性来源凭据；模型不能用额外字段
伪造。插件先按可信会话查询宿主消息，再在自己的连接上核对账号、目标群名册和同账号
OneBot 源记录。来源对应不足、私聊、越权或目标不可确认都在发送前拒绝。模型不能
提供正文、资源 ID、媒体地址或任意平台动作。

自动入口只观察宿主 `chat.receive.after_process`，给源群一次判断机会；消息可读等待
最多 10 秒，去重为 10 分钟/4096 项的独立内存状态。直连收到的普通消息、自发事件或
通知不触发自动判断，不构成第二条宿主入站链；Planner 沉默时不转发、不评论。

## 支持与整条拒绝

实现支持可完整取得的普通文字、单图、多图、图文，以及唯一顶层原卡片，保持内容和段序：

- 图片要求宿主材料可恢复，并从可信 OneBot 源记录获得可安全重放的 HTTPS 媒体引用。
  插件不下载调用者指定文件或地址；网关 DNS/重定向后的安全获取必须先确认 U5。
- 普通消息提及是保真例外：转为 `［提及：显示名称（对象标识）］`、`［提及：对象标识］`
  或 `［提及：全体成员］`，不产生顶层 `at` 段；名称与标识压平控制字符、不截断、不虚构，
  原顺序和换行保持，转换不新增换行，不查询目标成员补全。
- 合并转发只复用可信源消息中的原资源引用；内部回复、提及、媒体和未知段原样随资源
  保留，不逐节点清洗、不重建、不上传节点。工具评论另发，不塞进原作者节点。
  卡片外层预览不保证逐字相同，内部呈现和提醒行为尚未真实验证。

普通消息夹带文件、视频、语音、回复等不支持段，图片缺媒体或含不安全地址，提及对象
不明、空内容、源不可定位，都整条拒绝。原卡片缺资源/缓存、多卡片或与其他顶层内容
混排同样拒绝；不丢段、拆段、生成摘要或把图片改成描述。此拒绝规则不递归套用卡片内部。
引用（reply）段的消息（例如群里回复聊天记录卡片的那条，气泡只显示被引用卡片的预览）
整条拒绝，并提示改用被引用卡片自身的消息 ID；卡片消息自身是唯一顶层卡片时正常转发。

## 顺序、结果与防重

顺序：可信本地预检 → 查已有账本 → 直连只读准备 → 复验并持久源占位 → 账号及实际
写入前最后复验 → 一次 `send_msg` → 有限只读回执核实并立即落账 → 非空评论等待
固定 0.5 秒 → 复验、评论占位、提交前复验 → 一次普通文本评论 → 保存结果。
空/全空白评论不等待、不占位、不发送；源失败、未知或落账失败不进入评论。

成功需要匹配动作响应及同一目标记录的 ID、目标群、发送账号、正整数平台群序列四项
证据；仅受理、写帧成功或非空不透明 ID 不算成功。其线上字段含义仍待 U7 确认。

八种工具 `status`：

- `sent`：源成功且已落账，评论未要求或也成功。
- `partial`：源已成功落账，评论未完成、明确未发或待核实。
- `already_forwarded`：已有源成功事实，本次零发送，也不补评论。
- `sending`：同键源在途，本次不重复发送。
- `rejected`：本次源未提交，来源、内容、权限、连接准备等拒绝。
- `failed`：源可证明未发送，只有后续显式新调用可以再尝试。
- `unknown`：证据不足或终态未落账，保持防重、人工核对，不自动重发。
- `ledger_unavailable`：源发送前账本不可用，关闭发送并人工核对。

`success=true` 对应 `sent` 或 `already_forwarded`，后者不表示本次新发送或曾要求的
评论一定完成。`sent/delivered=true` 仅说明源已有可靠投递证据；落账失败仍可能为真，
同时整体 `success=false`。`target_message_id`、`comment_message_id` 是已知真实目标 ID，
`stage/reason` 定位问题；源、资源和目标 ID 不可混用。

**评论持久性边界**：等待中撤权/卸载返回本次 `partial/comment_status=failed`，表示
确实没有提交评论；账本评论字段仍空，并没有持久记录本次未提交评论。以后重复调用
返回 `already_forwarded`，不补评论。已经提交评论但结果落盘失败时，本次是
`partial/comment_status=unknown/stage=comment_persist`，保留已知真实评论 ID，
不能声称评论结果可靠；账本在途评论重启恢复为 `unknown`。

## 本插件账本、历史与退出

唯一投递权威是宿主授予本插件目录内的 `delivery_ledger.sqlite3`，四字段键为
账号、源群、源消息 ID、目标群；评论、连接、请求或进程变化不改键，不同目标独立。
先取独占、检查历史与库完整性，再恢复；完整原库保留，确认新装才建库。
成功/未知无时间或容量清理，源/评论遗留 `sending` 保守恢复为相应 `unknown`。

发现 `service_binding.json`（包括临时文件）、主库以外的数据库/归档副本、孤留伴随
文件、链接文件、损坏库或命中状态类证据名字规则（导出临时名、归档扩展名、中文
“快照/归档/备份”标记等）的条目时关闭发送，保留全部证据；插件自身源码、文档、
配置与缓存不构成证据。插件不读真实服务库、不自动回迁、不新建空库绕过历史，也不
读取其他插件账本。备份和回滚均先停写、保留最新事实，详见运维清单。

卸载先阻止新提交，取消并有界等待自己的任务、关闭自己的连接和账本，所有工作共享
5 秒预算；残留工作逐条告警，有写入风险则保留账本独占，不假称已全部退出。已提交
动作按可靠回执或未知处理，本地取消不等于 QQ 撤回；不注销账号、不影响其他客户端。

目标 QQ 可见性需要真实联验；**目标群宿主消息记录与 Maisaka 历史同步不保证**。
冷目标不会被创建或唤起 Planner，不写宿主数据库、不伪造入站、不追加摘要；历史缺失
不是重发理由。
