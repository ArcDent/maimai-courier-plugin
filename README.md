# 麦麦搬运喵（maimai-courier-plugin）

麦麦在群聊间分享消息的独立 MaiBot 插件。源群出现已选候选类型的消息后，由源群
Maisaka 依据可编辑标准自主决定分享或沉默；群友也可明确请求，通过 `forward_message`
把本群指定源消息转发到与它同属一个转发分组的目标群，可另附一条延迟 0.5 秒的评论。

**当前路径：插件进程内客户端 → 操作者配置的单一 SnowLuma HTTP API 端点 → QQ。**
源消息、评论和必要平台查询都经本插件自己的端点按请求完成（`POST /{action}`、
`Authorization: Bearer`），不建立长连接、不启动独立转发服务、不借用适配器 API、
不调用宿主 `send.*`，故障时也没有备用发送路径。

**本轮仅通过离线合成验收与一次授权实测快照（ADR 0008），真实 QQ 联验未授权、未执行。**
除 U1（仅 Bearer 头认证）已在该实测实例确认外，服务端契约仍未确认，实际启用前须满足
[真实联验清单](docs/real-qq-validation.md)。以下支持范围是实现契约，不是线上效果保证；
尤其图片安全获取、卡片与单节点卡片展开、卡片内提醒行为和回执含义不能由模拟测试证明。

## 安装前提与资料

- 插件版本 `0.1.0`；清单声明 Host `1.2.5–1.99.99`、SDK `2.8.0–2.99.99`。
- 插件专属依赖只有 `_manifest.json` 声明的 `aiohttp>=3.14.3`，由宿主依赖流水线装载。
  无需旧服务的 `pyproject.toml`、`uv sync`、服务 CLI 或额外常驻进程。
- SDK 2.8.0 的公开源码与发布包接口已核对，**线上实际加载版本仍未确认**。宿主源码
  锁文件的 2.5.2 既不证明当前运行版本，也不满足本插件下限；部署前另行确认。
- 能力仅为 `message.get_by_id`（可信源查询）、`chat.get_all_streams`（来源会话）、
  `maisaka.proactive.trigger`（源群判断）。不声明 `api.call`、`send.*`、`chat.open_session`；
  Hook 名称不是能力。
- [直连运维清单](docs/direct-snowluma-operations.md)：端点、环境、账本、备份与停止条件。
- [CONTEXT.md](CONTEXT.md)：领域术语；[ADR 0008](docs/adr/0008-http-direct-client-and-forward-actions.md)：
  当前架构决定（HTTP 直连与三类分派，取代 ADR 0007）；[ADR 0010](docs/adr/0010-scoped-forward-groups.md)：
  转发分组决定（同组才能互投，取代源/目标平铺白名单）；[ADR 0011](docs/adr/0011-nested-card-rejection.md)：
  嵌套卡片发送前拒绝决定（卡片套卡片不再原样提交）；实测快照见
  [SnowLuma HTTP API 目录](docs/snowluma-http-api-catalog.md)。
- 当前行为以主规格 [跨群转发](openspec/specs/cross-group-forward/spec.md) 与
  [直连客户端](openspec/specs/snowluma-direct-client/spec.md) 为准；HTTP 直连与三类
  分派的变更已归档到 `openspec/changes/archive/2026-10-05-direct-snowluma-http-forwarding/`
  （内容已同步进主规格），旧 ws 直连变更的提案、设计与验收记录已归档到
  `openspec/changes/archive/2026-10-04-direct-snowluma-websocket-forwarding/`。
- 旧服务、依赖与测试完整保存在 [历史区](history/snowluma-forward-service/MANIFEST.md)，
  [隔离记录](history/snowluma-forward-service/ISOLATION.md) 说明其退出路径；不维护两套可部署产品。

本插件不 import、不复制、不依赖复读插件，不读取其他插件的配置、凭证或投递记录。
获得部署授权后，把活跃插件目录放到宿主插件目录，由宿主加载清单依赖。历史区仅供追溯，
不加入 Python 路径、不启动其中代码；本轮没有执行部署。

## 配置与启用门槛

四节配置的安全默认如下，与 `config.py` / `config.toml` 一致：

```toml
[plugin]
enabled = false
config_version = "1.7.0"

[auto]
enabled = true
message_types = ["forward"]
share_criteria = "结合消息内容与目标群，自行判断是否值得分享；不值得或无法判断时保持沉默，不必回复，不要编造消息内容。"

[scope]
groups = []

# [[scope.groups]]
# name = "研发群"
# source_groups = ["111111"]
# target_groups = ["222222", "333333"]
# private = false

[snowluma]
http_url = ""
token = ""
token_env_var = ""
```

`[scope]` 是**具名转发分组**：每个分组由 `name`、`source_groups`（源群号）、
`target_groups`（目标群号）与 `private`（私聊开关，默认 `false`）构成，
`[[scope.groups]]` 可写任意多项。

- **同组才能互投**：一次转发只要求「目标群与来源群属于同一个分组」。源群写进哪个
  分组，就只能投给那个分组的目标群；跨分组的目标（只在别的分组，或不在任何分组内）
  在发送前被整条拒绝。工具预检、源/评论提交前复验、自动入口的候选筛选与目标列举
  共用同一处判定。
- **同一源群只能属于一个分组**：源群跨组重复、组内重复、`name` 去空白后为空或跨组
  重复，都在**配置期**直接拒绝保存，不静默合并、不放行部分配置。
- **目标群可跨组重复**：同一个吃瓜群可以列在多个分组的 `target_groups` 里，各分组的
  源群都能投给它；源群也可兼作别组的目标群（实际投递仍受「目标 ≠ 来源群自身」兜底）。
- **`name` 只是给人看的标识**：不参与路由、权限或判断，只在日志与任务描述里以
  `分组=<name>` 前缀出现（压平空白与控制字符后）；不限长、不限字符集，但必填、非空白
  且跨组唯一。
- **`private` 是该分组的私聊转发开关**（默认关闭）：开启后，本分组的源群才可以把本群
  消息转发到**操作者账号的 QQ 好友**（`target_user_id`，二选一目标参数），并在准备阶段
  经好友名册核验对端为同账号好友；关闭时私聊目标在本地预检即拒绝。它不改变群目标的
  任何判定，也不给自动入口增加私聊举荐（自动判断仍只列举同组目标群）。
- 空目标分组允许保存，但该分组的源群显式调用与自动判断都会因「同组没有合法目标」被拒。
- **默认空分组等价于旧的空白名单**：没有源群也没有目标群，不触发自动判断，工具调用被拒。

> **Breaking（2026-10-06 起）**：平铺键 `source_groups` / `target_groups` 已移除，
> 无兼容期。升级时必须**手工**把旧配置改写成上面的分组形态：把原来的源群
> `source_groups` 与目标群 `target_groups` 归入同一个 `[[scope.groups]]` 块并补一个
> `name`；若原来只有一份源群 + 一份目标群，直接合成一个分组即可。`plugin.config_version`
> 已由 1.5.0 提升到 1.6.0。未改写的旧配置表现为「源群不在任何转发分组内」的可定位
> 拒绝，不会误发；要回滚代码，先把仓库示例与线上配置写回平铺键再降级。

> **Breaking（2026-10-09 起，双形态目标）**：转发分组新增 `private` 键（默认
> `false`，不写即关闭，旧分组无需改动即可加载）；`plugin.config_version` 提升到
> 1.7.0。本插件账本由四字段键扩为五字段键（新增目标形态），旧库在首次打开时一次性
> 迁移（既有行按 `group` 回填），迁移失败按账本不可用关闭发送、原文件不改动。

- 总开关默认关闭，自动入口默认开启、仅选合并转发，转发分组默认为空。关闭总开关时
  工具和观察 Hook 都不会发出任何平台请求、执行平台动作或自动判断；加载本身不联网。
- `snowluma.http_url` 是操作者确认的完整 HTTP API 端点，默认空（旧 WS 端点键不再解析，
  无兼容期）。明文 `http` 只允许回环、私有或链路本地目标（主机名在请求
  发出前解析确认，解析出公网或失败即拒绝），公网目标必须使用可验证证书的 `https`。
  不接受 `0.0.0.0` 等监听地址、URL 用户信息、查询串、片段或其他协议；请求显式禁止
  跟随重定向（含重发请求体与认证头的 307/308），凭证与请求体不得离开配置端点；
  不自动探测端口（HTTP 默认 3000 与 ws 3001 可能各自持 Token，按部署实际填写）。
- 客户端自设请求体上限 2MiB（代码常量）：序列化后超限在发出前拒绝，避免服务端静默
  断连（服务端实际上限实测约 2–3MB，超限不返回结构化错误）。
- `snowluma.token` 可直接填写令牌，非空且非全空白时优先使用。令牌明文保存于插件配置，
  请限制文件权限，避免把含真实令牌的配置提交到仓库或分享。
- `snowluma.token_env_var` 只填环境变量名；`token` 留空或全空白时才在请求前读取该变量。
  两种方式默认均为空；凭证只随 `Authorization: Bearer` 认证头发送，不进入 URL、日志、
  账本或工具结果，不自动读取适配器凭证。缺值、认证失败或实际登录账号不能对应可信宿主
  账号时停止发送；配置令牌认证失败不会改用环境变量重试。
- 容器中的 `localhost` 指该容器本身，不是宿主机。跨容器/跨主机须由操作者提供
  实际可达的受保护端点，不能直接照抄截图端口：明文目标必须解析为回环、私有或
  链路本地，公网地址必须走可验证证书的 `https`。
- 旧 `[service]` 不自动映射到直连地址，不要求填写旧服务身份或迁移确认；存在旧状态
  证据仍会阻断发送，见下文。
- `auto.message_types` 只接受 `text` / `image` / `forward`。空列表停止所有自动机会，
  不影响合法显式工具调用；未知类型明确拒绝。图文归 `image`，卡片优先归 `forward`。
- 分享标准最多 4000 字符，空/全空白回退上述默认。它只是源群模型的自然语言判断依据，
  不保证模型遵循，不改变权限，也不成为群友明确请求时的额外内容偏好门禁。
  开启普通文字或图片候选会增加模型调用。

先保持关闭，确认运行版本、U3–U8（U1 已在授权实测实例确认，本部署仍须复验；U2 的
长连接事件广播随 HTTP 直连不再是风险面）、端点与环境注入、本插件账本完整性及转发
分组，获得真实测试授权后再启用。评论延迟、超时和容量均为代码常量，不是配置或
模型参数。

## 群聊工具 `forward_message`

公开参数：`message_id`（必填，本群源消息 ID）、`comment`（可选，默认空，普通文本），
以及**二选一**的目标参数——`target_group_id`（与来源群同属一个转发分组且不同于源群的
目标群号）或 `target_user_id`（来源群所属分组开启 `private` 后的私聊好友 QQ 号）。
两个目标参数同缺或同在都在发送前拒绝，不默认任一目标。

```json
{"message_id": "1234567890", "target_group_id": "222222222", "comment": "这条挺有意思"}
{"message_id": "1234567890", "target_user_id": "3000100001", "comment": "这条挺有意思"}
```

源群、平台和账号来自宿主 Planner Hook 签发的一次性来源凭据；模型不能用额外字段
伪造。插件先按可信会话查询宿主消息，再经自己的 HTTP 端点核对账号、目标群名册（群目标）
或好友名册（私聊目标，确认对端为同账号好友）和同账号 OneBot 源记录。来源对应不足、
私聊、越权或目标不可确认都在发送前拒绝。模型不能提供正文、资源 ID、媒体地址或任意
平台动作。

私聊目标与群目标走同一套内容与防重规则，只有发送路由不同：卡片与文字经
`send_forward_msg` 的私聊路由参数提交、图片与评论经 `send_msg` 的私聊路由参数提交
（不引入具名私聊发送动作）；回执按形态核验——群目标核验群号，私聊目标核验回执属
私聊、对端为本次目标、账号为机器人自身与正整数平台序列。目标消息 ID 正负值都按
原值逐字比对。

## 群聊工具 `list_forward_friends`

只读群聊工具，**无公开参数**（模型无法声明会话、账号或字段），列出操作者账号的 QQ
好友名册，供模型在提交私聊目标前选取对端。门禁与转发工具同链：一次性来源凭据换可信
来源 → 来源群所属分组必须开启 `private`；未开启、来源群不在任何分组、无凭据或非群聊
来源都在发出任何平台请求前拒绝。返回只含 QQ 号、备注与昵称（条目数设代码常量上限，
超出即明示已截断，不做匹配排序）；名册数据不进日志、账本、任务表与投递结果，查询本
身零发送。总开关关闭时调用不产生任何平台请求。

自动入口只观察宿主 `chat.receive.after_process`，给源群一次判断机会：只对转发分组内的
源群触发，列给 Maisaka 的目标群仅限来源群所属分组的同组目标（**不举荐好友名册或私聊
目标**）；合并转发候选在唤起前经两步只读查询预识别嵌套卡片，命中不提供判断机会，查询
失败不影响本次机会（能否发送仍由发送前类型检查权威决定）；消息可读等待最多 10 秒，
去重为 10 分钟/4096 项的独立内存状态。直连收到的普通消息、自发事件或通知不触发自动判断，
不构成第二条宿主入站链；Planner 沉默时不转发、不评论。自动唤起之后模型自行提交私聊目标
时，按显式工具口径校验（分组开关 + 好友核验），不因唤起居次获得额外放行或拒绝。

## 支持与整条拒绝

实现支持可完整取得的普通文字、单图、多图、图文，以及唯一顶层合并转发卡片；按源消息
类型分派，保持内容和段序（群目标与私聊目标支持同一组类型，只有发送路由与回执核验按
形态不同）：

- **卡片消息转发**（合并转发卡片）：按源消息卡片标识展开查询后重组发送——先
  `get_forward_msg` 展开取得节点序列，经结构校验后以 `send_group_forward_msg` 单次
  提交，平台按目标群上下文重新上传卡片内媒体；插件不提取调用方资源 ID、不改写或清洗
  节点内容、不设置外层预览/摘要参数。内部回复、提及、媒体和未知段随节点内容原样保留；
  **展开结果含嵌套内层卡片（卡片套卡片）时发送前整条拒绝**，固定措辞「源卡片包含嵌套
  聊天记录，无法完整转发，不建议继续尝试」——实测该形态在目标群客户端只能显示为降级
  空壳，且与所引用资源的新旧无关（ADR 0011）。**显式工具调用同样在发送前被拒**；
  自动入口对这类候选不提供判断机会（只读预识别，查询失败不影响正常唤起）。其它实测
  有问题的节点类型（作节点内容时回执平台群序列为 0 的 `xml`/`share`/`contact`，端点
  拒收的 `poke`/`market_face`）本轮不阻断、留待以后处理，其目标群展示不另行保证。
  卡片内 at 是否在目标群客户端触发提醒不作保证（待真实联验，归 U6）；工具评论另发，
  不塞进卡片节点。
- **单节点卡片文字**（普通文字）：以单节点合并转发卡片发送，节点署名取自源消息
  发送者身份（标识与显示名只来自源消息），内容段按源消息原样提交，at 等提及随节点
  原样保留、不做文本化。
- **普通消息图片**（单图/多图/图文混排）：以普通消息段按原顺序直发。图片要求宿主
  材料可恢复，并从可信 OneBot 源记录获得可安全重放的 HTTPS 媒体引用；插件不下载
  调用者指定文件或地址；网关 DNS/重定向后的安全获取必须先确认 U5。
- 普通图片路径的提及是保真例外：转为 `［提及：显示名称（对象标识）］`、`［提及：对象标识］`
  或 `［提及：全体成员］`，不产生顶层 `at` 提醒；名称与标识压平控制字符、不截断、不虚构，
  原顺序和换行保持，转换不新增换行，不查询目标成员补全。普通文字路径的提及随节点
  原样提交，不走文本化。

普通消息夹带文件、视频、语音、回复等不支持段，图片缺媒体或含不安全地址，提及对象
不明、空内容、源不可定位，都整条拒绝。合并转发卡片源消息不存在或缓存缺失、多卡片或
与其他顶层内容混排同样拒绝；不丢段、拆段、生成摘要或把图片改成描述。此拒绝规则不递归
套用卡片内部。引用（reply）段的消息（例如群里回复聊天记录卡片的那条，气泡只显示被
引用卡片的预览）整条拒绝，并提示改用被引用卡片自身的消息 ID；卡片消息自身是唯一顶层
卡片时正常转发。

## 顺序、结果与防重

顺序：可信本地预检 → 查已有账本 → 直连只读准备（账号核对后，群目标查目标群名册、
私聊目标查好友名册确认对端为同账号好友）→ 复验并持久源占位 → 账号及实际写入前最后
复验（群目标复验同组判定，私聊目标复验分组 `private` 开关）→ 按类型一次发送（卡片
`get_forward_msg` 展开后群目标 `send_group_forward_msg` 节点重组／私聊
`send_forward_msg` 私聊路由；文字 `send_forward_msg` 单节点卡片，群目标提交群号、
私聊提交私聊路由参数；图片 `send_msg` 段直发，路由参数同上）→ 有限只读回执核实并立即
落账 → 非空评论等待固定 0.5 秒 → 复验、评论占位、提交前复验 → 一次普通文本评论 →
保存结果。空/全空白评论不等待、不占位、不发送；源失败、未知或落账失败不进入评论。

成功需要匹配动作响应及同一目标记录的 ID、目标群（群目标）或私聊对端（私聊目标，
另核验回执属私聊与账号为机器人自身）、发送账号、正整数平台序列四项证据；仅受理、
写帧成功或非空不透明 ID 不算成功。目标消息 ID 可为负值，按返回原值逐字比对，不假设
符号。其线上字段含义仍待 U7 确认。

八种工具 `status`：

- `sent`：源成功且已落账，评论未要求或也成功。
- `partial`：源已成功落账，评论未完成、明确未发或待核实。
- `already_forwarded`：已有源成功事实，本次零发送，也不补评论。
- `sending`：同键源在途，本次不重复发送。
- `rejected`：本次源未提交，来源、内容、权限、连接准备等拒绝。
- `failed`：源可证明未发送，只有后续显式新调用可以再尝试。
- `unknown`：证据不足或终态未落账，保持防重、人工核对，不自动重发。
- `ledger_unavailable`：源发送前账本不可用，关闭发送并人工核对。

`success=true` 对应 `sent` 或 `already_forwarded`，后者不表示本次新发送或曾要求的
评论一定完成。`sent/delivered=true` 仅说明源已有可靠投递证据；落账失败仍可能为真，
同时整体 `success=false`。`target_kind` 标明目标形态（`group`/`private`），
`target_group_id` 或 `target_user_id` 携带本次目标标识（群号或私聊对端 QQ 号）；
`target_message_id`、`comment_message_id` 是已知真实目标 ID，`stage/reason` 定位问题；
源、资源和目标 ID 不可混用。名册条目（备注/昵称）从不进入结果。

**评论持久性边界**：等待中撤权/卸载返回本次 `partial/comment_status=failed`，表示
确实没有提交评论；账本评论字段仍空，并没有持久记录本次未提交评论。以后重复调用
返回 `already_forwarded`，不补评论。已经提交评论但结果落盘失败时，本次是
`partial/comment_status=unknown/stage=comment_persist`，保留已知真实评论 ID，
不能声称评论结果可靠；账本在途评论重启恢复为 `unknown`。

## 本插件账本、历史与退出

唯一投递权威是宿主授予本插件目录内的 `delivery_ledger.sqlite3`，五字段键为
账号、源群、源消息 ID、目标（群号或私聊对端 QQ 号）与目标形态（`group`/`private`）；
评论、连接、请求或进程变化不改键，同源消息的群目标与私聊目标是两个独立键、互不阻断。
先取独占、检查历史与库完整性，再恢复；完整原库保留，确认新装才建库。四字段旧库在
首次打开时一次性迁移为五字段（既有行按 `group` 回填，记录数、状态与目标消息 ID 逐条
校验），迁移任一步失败按账本不可用关闭发送且原文件字节不改动；迁移后的既有键仍阻断
重发。成功/未知无时间或容量清理，源/评论遗留 `sending` 保守恢复为相应 `unknown`。

发现 `service_binding.json`（包括临时文件）、主库以外的数据库/归档副本、孤留伴随
文件、链接文件、损坏库或命中状态类证据名字规则（导出临时名、归档扩展名、中文
“快照/归档/备份”标记等）的条目时关闭发送，保留全部证据；插件自身源码、文档、
配置与缓存不构成证据。插件不读真实服务库、不自动回迁、不新建空库绕过历史，也不
读取其他插件账本。备份和回滚均先停写、保留最新事实，详见运维清单。

卸载先阻止新提交，取消并有界等待自己的任务、结束自己的在途请求和账本，所有工作共享
5 秒预算；残留工作逐条告警，有写入风险则保留账本独占，不假称已全部退出。已提交
动作按可靠回执或未知处理，本地取消不等于 QQ 撤回；不注销账号、不影响其他客户端。

目标 QQ 可见性需要真实联验；**目标群宿主消息记录与 Maisaka 历史同步不保证**。
冷目标不会被创建或唤起 Planner，不写宿主数据库、不伪造入站、不追加摘要；历史缺失
不是重发理由。
