# 真实 QQ 联验清单（需单独授权，未执行前不得宣称已验证）

> 本清单覆盖真实账号、真实源群/目标群与真实 QQ 客户端的端到端联验。**执行前必须
> 取得用户单独的部署与发群授权**；未授权时本清单保持未执行，任何“支持/拒绝”结论
> 都只代表自动化与合成测试，不代表线上投递已验证。执行中不自动部署、不修改远端、
> 不读取或落盘凭证；真实群号只写进本地执行记录，不写进本仓库文档。

## 0. 执行前置（全部满足才继续）

- [ ] 已取得用户明确的部署与发群授权，并确认本次只使用**测试源群/测试目标群**。
- [ ] **唯一发送路径**：旧转发路径已下线；本插件是唯一入口，转发服务是唯一发送方
      （插件不再调用宿主 `send.*`，`host_send.py` 已退役且无 fallback）；不存在并发
      运行的第三套转发代码。
- [ ] 服务端就绪：`ledger status` 显示已初始化的账本身份与导入摘要；`start` 打印
      「HTTP 服务端已就绪并监听 …」；客户端已填写相同的预期账本 ID 与迁移确认标识。
- [ ] 账号核对：服务端绑定账号与 OneBot 实际登录账号一致；源群/目标群在服务端许可
      上限与客户端白名单的交集内，且目标群不同于源群。
- [ ] 凭证只以环境变量提供（HTTP 凭证、OneBot 凭证），配置与日志中不出现凭证值。
- [ ] 记录执行环境：日期、Host/SDK 版本、插件版本、服务端提交或版本、状态目录、
      源群与目标群（仅本地记录）。

## 1. 输入材料（在源群逐条准备）

| 编号 | 输入材料 | 关注点 |
| --- | --- | --- |
| V1 | 纯文字（含多段与换行） | 段序与换行保持 |
| V2 | 单张图片 | 原图发送、不以描述代替 |
| V3 | 多张图片（3 张） | 原顺序 |
| V4 | 文字 + 图片混排 | 原顺序与段内容 |
| V5 | 普通文字 + 个人提及（有显示名）+ 全体成员提及 | 转成保留对象信息的普通文本、无 @ 提醒 |
| V6 | 图片 + 个人提及（无显示名或群名片形态） | 缺显示名时使用对象标识，不虚构 |
| V7 | 合并转发卡片，内部包含回复、个人提及、全体提及、图片与较深嵌套 | 整张原卡片转发；内部内容保留、不逐段改写 |
| V8 | 未展开的卡片（若现场能构造该形态） | 只发资源引用、不要求宿主展开内部节点；构造不出时在记录中注明“未覆盖” |
| V9 | 卡片与文字混排 | **应整条拒绝**，不悄悄丢弃外层内容 |
| V10 | 语音/文件/视频等不支持段 | **应整条拒绝**，无发送 |
| V11 | 缺媒体的图片（若现场能构造） | **应整条拒绝**；构造不出时注明“未覆盖” |
| C1 | 空评论（`comment` 缺省或全空白） | 不等待、不发送评论 |
| C2 | 非空评论（含命令式/协议形态文本） | 只作普通文本另发一条消息，不触发命令 |
| C3 | 超长评论（如数百字，未超模型参数限制） | 按文本发送；模型参数超限时应先被拒绝 |

## 2. 三个必须分开的判定层面

| 层面 | 观察方式 | 判定作用 |
| --- | --- | --- |
| **平台投递** | 工具结果的 `status` / `sent` / `target_message_id` / `comment_status`，以及服务端 `ledger status` 的权威记录 | **成功判定的唯一依据**（真实目标消息 ID 与账本事实） |
| **QQ 客户端展示** | 在目标群 QQ 客户端人工查看消息形态、卡片展开、提及是否提醒、评论间隔 | 展示层验收；外层预览差异与卡片内提及提醒属记录项，见第 5 节 |
| **宿主 Maisaka 历史** | 目标群宿主消息记录/上下文是否出现该消息 | **不参与成功判定**：本工具不保证目标群历史同步，历史缺失不构成失败 |

任何一层的观察都不能替代平台投递证据：服务端“受理请求”不是成功，仅本地不透明
消息 ID 不算成功；平台投递之后才发现的模糊失败按待核实处理，不重发。

## 3. 执行与判定表

| 场景 | 操作 | 平台投递判定 | 客户端/展示观察 | 宿主历史 |
| --- | --- | --- | --- | --- |
| 显式文字转发（V1，空评论 C1） | 群友明确请求调用 `forward_message` | `status=sent`、非空 `target_message_id`；账本新增 `sent` 行 | 目标群出现同内容消息；评论不出现 | 记录实际结果，不作判定 |
| 单图/多图/图文（V2–V4） | 同上，逐个执行 | 各自 `sent` 且顺序正确；账本各一行 | 图片可正常打开、顺序一致 | 记录 |
| 普通提及（V5/V6） | 同上 | `sent`；发送内容不含 `at` 段 | 目标群显示 `［提及：…］` 文本，被提及人不收到 @ 提醒 | 记录 |
| 原卡片（V7） | 同上，可选带评论 C2 | `sent`；发送恰一张原卡片资源引用 | 卡片可展开；内部回复/提及/图片保留**当时形态**；卡片内提及的提醒行为只记录、不作“绝不提醒”结论 | 记录 |
| 外层预览（V7 同一条） | 同上 | 同上 | 外层预览可能与原卡片不完全逐字相同；差异只记录 | 记录 |
| 评论间隔（C2） | 同一投递带非空评论 | `comment_status=sent` 且评论消息 ID 非空；源回执时间与评论时间差 ≥ 0.5 秒 | 目标群先源消息、后评论（独立一条） | 记录 |
| 不支持段（V10）与混排（V9） | 调用工具 | `status=rejected`，源与评论发送数 0，账本无新增行 | 目标群无任何新消息 | 无记录 |
| 重复调用防重 | 首次成功后，换评论再次调用同一「源消息 + 目标群」 | `status=already_forwarded`、`success=true`，源与评论发送数不增；账本计数不变 | 目标群不出现新消息、不出现第二条评论 | 记录 |
| 重启后防重 | 重启插件与/或服务后重复上一行 | 仍 `already_forwarded`，无新发送 | 同上 | 记录 |
| 待核实处置 | 若出现 `unknown`/`partial`（网络异常等） | 先人工核对目标群与账本，**不重发**；记录原因与处置 | 人工核对结果 | 记录 |

自动入口另测一次：源群出现 V7（或已选类型的候选）后，确认只产生一次源群
Planner 判断机会；Maisaka 沉默时目标群与账本零新增；Maisaka 决定分享时走同一个
工具与同一条发送路径。

## 4. 记录字段（每次执行一条）

- 日期与环境：Host/SDK 版本、插件版本、服务端提交/版本、状态目录。
- 源群/目标群（仅本地记录）、源消息 ID、目标消息 ID、评论消息 ID。
- 工具返回的完整结果字典（可脱敏：不含凭证；评论文本只记“已提供/未提供”）。
- `ledger status` 输出（身份、状态计数）与服务端日志中的可定位行。
- 三层观察：平台投递证据、客户端截图或文字记录、宿主历史实际结果。
- 结论：`通过 / 失败 / 待核实`，以及未覆盖项。

## 5. 明确未验证、不得宣称的事项

- **卡片内部提及的提醒行为尚未验证**：本工具保留原卡片资源与内部内容，但平台如何
  呈现内部提及（是否产生提醒）未经真实联验；**不得宣称“卡片内提及绝不提醒”**，
  只能记录实际观察结果。
- **目标群 Maisaka 历史不保证**：目标群没有活动运行时不会为它唤起 Planner；历史
  未同步不判失败，也不得写宿主数据库、伪造入站消息或追加摘要来“补齐”。
- **外层预览不保证逐字相同**：网关会重新编码外层预览；差异只记录。
- 未在现场构造出的输入形态（V8/V11 等）标注“未覆盖”，不得用合成结果代替。
