# AGENTS.md

麦麦搬运喵（`maimai-courier-plugin`）：麦麦在群聊间分享消息的**独立** MaiBot 插件。
源群出现**已选候选类型**的消息（默认仅**合并转发**，可配置加选普通文字与图片）后，
由源群 Maisaka 结合可编辑的自动分享标准自主决定是否分享，并可通过 `forward_message`
工具把本群指定**源消息**转发到白名单**目标群**，可选附带一条延迟 0.5 秒的评论。
**全部源发送与评论由同仓库的独立 SnowLuma 转发服务执行**（`service/`），插件侧是
客户端（`remote_client.py`），不再调用宿主发送能力。普通消息的个人与全体成员提及
是原形态保真的明确例外：转成保留对象信息的普通文本，不向目标群传播 @ 提醒；原卡片
内部内容（含提及、回复）随整张原卡片资源保留、不再逐段改写；不保证目标群宿主的
消息记录与 Maisaka 历史同步。

术语见 CONTEXT.md，行为契约见主规格 `openspec/specs/cross-group-forward/spec.md`
与本变更的服务规格 `openspec/changes/move-forwarding-to-snowluma-service/specs/`
（获准同步/归档前不覆盖主规格），设计取舍见该变更 `design.md` 与
`docs/adr/0004` / `docs/adr/0005`。

## 独立性

- 本插件不 import、不复制、不依赖同级**复读插件** `repeat-plugin`：没有旧项目的
  import、配置或任务集合依赖（由 `tests/test_plugin.py::test_生产代码不依赖复读插件`
  守住）。
- 不读旧插件的运行配置、凭证或投递记录；本插件状态只落在宿主授予的
  `ctx.paths.data_dir`（旧账本归档与本地迁移收据 `service_binding.json`），不与任何
  其他插件共享；转发服务的状态目录只归服务进程使用。
- `_manifest.json` 的 `capabilities` 随插件整体声明（`message.get_by_id` /
  `chat.get_all_streams` / `maisaka.proactive.trigger`），每一项都已在 Host
  `src/plugin_runtime/capabilities/registry.py` 核实；`send.*` 与 `chat.open_session`
  已移除，不得再声明。Hook 名称不是能力，不进该列表。
- **插件专属依赖只经 `_manifest.json` 的 `dependencies` 声明**（结构为
  `{type: "python_package", name, version_spec}`，当前 `aiohttp>=3.14.3`），由宿主
  依赖流水线装载；仓库根 `pyproject.toml` 只服务独立服务进程，不是插件依赖的声明
  入口，也不得把插件依赖写进别处。

## 结构

- `plugin.py` — 插件主类 + 组合根：三生命周期（`on_load` / `on_unload` /
  `on_config_update(scope, config_data, version)`）、一个群聊 Tool
  `forward_message`、两个 Hook：`maisaka.planner.after_response`（blocking，
  在模型输出工具调用后签发一次性来源凭据）与 `chat.receive.after_process`
  （observe，观察已处理入站消息：筛选自动入口候选并把等待/唤起登记为本插件自己的
  后台任务）；`get_components()` 覆写把 Tool 的 `chat_scope` 提到组件声明**顶层**
  （承载性修正，见下）。它同时是组合根：持有可注入时钟、服务客户端会话与可定位
  任务表，**不再打开账本、不持有发送接缝**。生命周期语义：`_tasks` 只装本插件创建
  的后台任务（自动等待 `_auto_tasks` 与在途投递），每项附带可定位描述（源消息／
  目标群／阶段）供超时告警逐条列出；`on_unload` 先置卸载标记（立即停止签发新阶段
  授权）→ 尽力请求远端撤销未消费授权并注销会话（不可达时如实报告「撤销未确认」）→
  取消并**有界等待**本插件任务退出（`TASK_EXIT_WAIT_SECONDS` = 5 秒，超出即按任务
  描述告警，不静默）→ 释放传输，不触碰其他插件的任务；`forward_message` 在预检
  返回后、创建投递任务前复检卸载标记（预检期间卸载时直接按 `rejected` 返回）；
  `on_config_update` 立即取消已失效的待执行自动判断，**发送许可**变化时推进远端
  权限代次并撤销不再允许的待执行尝试（只改标准或候选类型不推进代次）；投递在
  **源阶段与评论阶段授权前**共用 `_send_allowed` 复验（卸载标记 + 总开关 + 来源群/
  目标群白名单，读提交时最新配置）——复验失败时不提交授权、尽力撤销未消费尝试、
  对外按「明确未发送」的 `rejected` 报告（撤销不可达时记录「撤销未确认」，仍不发送）。
- `source_binding.py` — 工具参数面（公开参数声明、校验与统一拒绝措辞）与一次性
  来源凭据表：授权只由宿主 Hook 载荷签发、首次消费即作废；清洗与签发只作用于
  指向本插件 `forward_message` 的调用（同批其它工具调用原样保留，也不得获得
  凭据），工具调用里的会话/授权字段一概不读。
- `send_material.py` — 普通消息的内容完整性预检与提及材料构建：图片必须带可恢复
  二进制、不支持段整条拒绝；**个人与全体成员提及是普通消息原形态保真的唯一例外**，
  在递归预检里把已核实形态的 `at` 段转成不触发提醒的普通文本（有名称
  `［提及：显示名称（对象标识）］`、无名称 `［提及：对象标识］`、全体
  `［提及：全体成员］`，名称与标识压平控制字符、不截断，保留顺序与节点归属、输入
  不被原地修改；含提及的相邻文本片段按原换行归并，转换不新增换行；对象不可确认
  仍整条拒绝）。同时导出 `is_forward_card` 作为**唯一**的「是否合并转发卡片」形状
  判据（含宿主未展开的 `dict` 包装形态），自动入口、本地预检与服务端材料共用。
  本模块**只处理普通消息**：原卡片内部不做提及文本化、不做递归改写。
- `forward_precheck.py` — 工具入口的本地权限与内容预检编排（不联网、不发送）：凭据
  换可信会话、来源/目标白名单与「目标不同于源群」核对、按可信会话查询源消息归属，
  全部通过才产出 `PreparedForward`；**不再要求宿主目标发送会话**（目标平台与账号
  可用性由认证服务独立核对），**也不再本地递归校验卡片节点**——卡片只判顶层形状
  （唯一一张卡片；与其它顶层内容混排即拒绝），内部资源是否可用由服务端从可信源消息
  取得并决定；普通消息仍走 `send_material` 的完整内容预检。导出 `whitelist_entries` /
  `source_group_is_allowed` / `target_is_allowed`，让预检、阶段复验与自动入口共用
  同一份白名单口径。
- `delivery_ledger.py` — **旧账本只读兼容入口（保留不删除）**：定义旧 SQLite schema
  与旧公共接口（`open_ledger` / `reserve` / `mark_*` / `record_comment`），并把
  `DeliveryKey` / `LedgerStatus` / 错误类型从共享层兼容重导出；供旧库只读核对、
  迁移对照与测试使用。插件运行时不打开、不写入它；**禁止把它复活为客户端第二份
  投递状态**——服务端账本是新投递的唯一权威（design D7）。
- `forward_delivery.py` — 客户端投递编排：本地预检通过 → 远端准备（只校验、查源与
  登记，不发送）→ 读最新配置复验 → 源阶段单次授权 → 源确认后固定等待
  `COMMENT_DELAY_SECONDS`（0.5 秒）→ 复验 → 评论阶段单次授权 → 统一结果面
  `render_forward_result`（`shared/result.py`）。执行响应丢失时只查询**同一投递**，
  不再次提交发送探测；源确认但服务端回执未落盘时报告已知目标 ID 但不称完整成功；
  评论结果未落盘不得声称评论结果可靠；编排自身不调用任何宿主发送能力（`host_send.py`
  已退役，没有 fallback）。
- `host_send.py` — **已退役**的宿主旧发送实现墓碑：不再导出任何发送函数、不含任何
  `ctx.send` 调用点；保留文件与退役说明，防止遗留导入静默指向不存在的模块，并守住
  「不得复活旧发送通道」的检查面。真实发送只在服务端网关模块。
- `remote_client.py` — 插件侧唯一的转发服务访问面：有界请求（代码常量超时）、固定
  地址、不跟随重定向、默认校验证书；覆盖会话/心跳/策略/准备/源与评论执行/查询/
  撤销/注销的 v1 协议调用；持有账本绑定与本地迁移收据（`ctx.paths.data_dir` 下的
  `service_binding.json`，只含非敏感账本身份与迁移确认标识）。服务端上报的账本身份
  必须与配置预期值及本地收据一致，否则关闭发送，绝不回退旧发送通道。
- `shared/` — 插件侧与服务端共用的纯逻辑（投递类型与状态、协议模型、账本仓储协议、
  发送接缝协议、标识符规则、提及转换、结果渲染、配置规则）；插件用相对导入
  `.<插件包>.shared.*`，服务用顶层 `shared.*`，两侧解析到同一份源码，禁止复制成
  两套状态机或类型定义。
- `service/` — 独立 SnowLuma 转发服务：CLI（`start` 与 `ledger fresh|migrate|export|
  status`）、受控配置与认证、HTTP v1 路由、会话与投递协调器、服务端独占账本与
  迁移/导出、OneBot 网关与材料转换。服务进程不导入 `maibot_sdk`，也不依赖插件目录。
- `pyproject.toml` — 独立服务的项目级运行环境（`requires-python >= 3.11`、
  `aiohttp>=3.14.3`、`package = false`）；插件依赖声明仍只归 `_manifest.json`。
- `config.py` / `config.toml` — 最小配置：总开关、自动入口开关与两个判断输入
  （`auto.message_types` 默认 `["forward"]`、`auto.share_criteria` 默认设计原文且
  上限 4000 字符）、源／目标白名单，外加 `[service]` 连接与账本绑定（服务地址、
  客户端身份、凭证**环境变量名**、预期账本 ID、迁移确认标识），以及宿主强制的
  `plugin.config_version`（SDK `extract_plugin_config_version` 缺它即抛
  `PluginConfigVersionError`）；`MessageType`（`text` / `image` / `forward`）是
  配置枚举与自动分类共用的唯一词汇来源；两处默认值必须逐项一致，配置里不得出现
  凭证值。
- `auto_entry.py` — 源群自动判断入口（只唤起判断，不发送消息）：按宿主
  `chat.receive.after_process` 载荷做候选分类与筛选（白名单源群、非机器人自身、
  非通知的 QQ 消息；无法确认机器人账号或发送者时放弃候选）。分类复用
  `is_forward_card`：命中卡片一律归 `forward`（含未展开卡片）；无卡片时只允许已
  识别的文字、图片与提及附属段参与，图文混排归 `image`、非空文字归 `text`，夹带
  不支持段或非法结构即放弃；候选类型再按 `auto.message_types` 门控（默认仅
  `forward`，空列表不提供自动机会），分类成功不承诺可发送。用源消息 ID 经注入
  时钟**有限**确认消息可读取（`AUTO_READINESS_TIMEOUT_SECONDS` = 10 秒、轮询
  `AUTO_READINESS_POLL_INTERVAL_SECONDS` = 0.5 秒，皆是代码常量），再对源群调用
  一次 `maisaka.proactive.trigger`。候选的会话 ID 与源消息 ID 先过 `safe_identifier`
  （限长 128、无空白/控制字符/尖括号引号反引号）才允许进入意图与 metadata：形态
  异常直接放弃候选，绝不净化成对不上真实消息的另一个字符串。意图携带源消息 ID、
  **实际候选类型**、合法目标群号与可用名称、用户配置的分享标准原文与固定边界
  说明（「自行判断、可以沉默」）；群名按不可信显示文本处理（尖括号转全角、压平
  空白、限长），永不作为路由依据；标准空或全空白回退设计默认原文，只按文字处理。
  等待结束后按**最新**配置重验总开关/自动入口、来源群、目标白名单与候选类型，
  目标名称查询结束后重读最新配置并用最新标准提交（`auto_entry_invalid_reason`
  判定含候选类型，只改标准不取消仍合法的候选）；已提交给宿主的判断不追溯改写；
  去重是内存有界状态（`AUTO_DEDUP_WINDOW_SECONDS` = 10 分钟、
  `AUTO_DEDUP_MAX_ENTRIES` = 4096，逐出最早登记项），与持久投递账本完全分离，
  不掷骰、不签目标群决策票、不唤起目标群、不追加上下文。自动入口只唤起源群
  Planner，**不直接请求服务执行转发**。
- `clock.py` — 时钟边界（`Clock` 协议 + `SystemClock`）：评论延迟、阶段授权有效期与
  有界等待一律走注入时钟，测试注入可控替身即可确定性推进超时。
- `README.md` / `docs/` — 公开文档：README 面向插件使用者（独立安装、服务依赖与
  启动入口、默认关闭与空白名单、四节配置、三参数用法、支持与拒绝类型（含提及
  转换与卡片内部保留）、结果状态与人工核对、服务端账本与迁移、目标群历史不保证、
  两条验证命令），`docs/service-operations.md` 是启动/凭证/备份/迁移/回滚运维清单，
  `docs/real-qq-validation.md` 是真实 QQ 联验清单（未授权前不得宣称已联验），
  `docs/adr/` 记录设计取舍；`docs/handover-cross-group-forward-switch.md` 保留与旧
  项目的切换对照；私有操作手册在 `.local/runbooks/`（`.gitignore` 已排除，不入库）。
- `tests/` — pytest 与 `tests/fake_maibot_sdk.py`、`tests/service_support.py`、
  `tests/cross_process_support.py` 替身（本机不安装真实 SDK；传输、OneBot、账本与
  阶段闸门均可注入）；组件声明经插件公共入口 `get_components()` 断言；默认命令下
  需要 `aiohttp` 的传输与跨进程模块在导入期跳过，带 `--with aiohttp` 时才真正覆盖
  真实 HTTP/WebSocket 与跨进程场景。后续变更的提及转换用例落在
  `tests/test_forward_precheck.py`（普通消息材料层）与 `tests/test_forward_send.py`
  （真实发送链），候选分类与可编辑标准用例落在 `tests/test_auto_entry.py`，热更新
  竞态落在 `tests/test_lifecycle.py`，服务端账本/迁移/回滚/隔离与跨进程验收落在
  `tests/test_service_*.py`、`tests/test_acceptance_*.py`。

## 关键规则

- **默认安全**：默认总开关关闭、自动入口开启、自动候选仅合并转发、白名单为空；
  服务侧未完成绑定（地址、凭证环境变量、预期账本 ID、迁移确认）时一律拒绝发送；
  总开关关闭时工具与观察 Hook 都不得产生任何发送，也不得回退旧发送通道。
- **不把延迟、概率与超时做成配置**：0.5 秒评论延迟、阶段授权有效期、会话/心跳
  时限、客户端请求超时、自动去重与等待上限都是代码常量，不要改造成配置项、随机
  时长或模型参数。
- **服务端账本是新投递的唯一权威**：源与评论发送前由服务端在独占状态目录里持久
  占位，成功回执后立即落账并保存真实目标消息 ID；只有「明确未发送」的失败可登记
  `failed` 并允许后续显式新尝试；超时、取消、回执丢失、重启遗留的 `sending` 一律
  待核实（`unknown`），禁止自动重试或盲目重发。插件不得打开、写入或复制服务端账本
  文件，也不得维护第二份投递真相；成功记录不按 TTL 或容量静默清除，两端都不提供
  删除接口。服务端账本不可用时关闭发送并如实报告 `ledger_unavailable`；发送步骤
  返回契约外状态字面量时一律按待核实兜底，不得降级为可重试的 `failed`。
- **发送只能走服务端网关**：插件侧不得调用 `ctx.send.*`（`host_send.py` 已退役，
  禁止复活或新增 fallback）；真实 `send_msg` 只出现在 `service/onebot.py` /
  `service/gateway.py` 的受控 OneBot 连接里。成功证据只能是非空真实目标消息 ID：
  缺回执 ID、只拿到本地不透明 ID 或模糊失败时，一律按待核实保守登记，禁止改走另一
  通路重发。评论结果附属于源投递记录，评论结果未能落盘时不得声称评论结果已知。
- **普通消息提及文本化、卡片内部不改写**：普通文字/图片消息中的个人与全体成员提及
  按 `［提及：显示名称（对象标识）］` / `［提及：对象标识］` / `［提及：全体成员］`
  转成普通文本，不生成 `at` 段、不向目标群传播 @ 提醒；名称与标识只来自源材料并
  压平控制字符，不虚构、不查询目标群成员；对象不可确认的提及整条拒绝，绝不猜成
  全体成员。**原卡片内部是明确例外**：整张原卡片按顶层资源引用发送，内部回复、
  提及、媒体原样保留，不逐节点清洗、不做提及文本化、不因插件不支持某内部段而拒绝；
  顶层卡片与其它内容混排仍整条拒绝。显示名称中的协议语法、命令或提示指令只作为
  普通文字发送，不改变路由与权限。
- **评论段固定顺序**：远端准备（不发送）→ 源阶段授权 → 服务端持久占位并发送源消息
  → 源成功回执并立即落账 → 等待代码常量 0.5 秒 → 重验总开关与两级白名单 → 提交
  评论阶段授权 → 服务端按普通文本发送本次评论 → 保存评论结果。评论缺省/空/全空白
  不等待也不提交授权；源发送明确失败或结果未知都不进入评论段；评论只来自本次参数，
  不再次调用目标群 Maisaka 生成，不自动补发；重复调用不重发源消息、也不补发评论；
  源已成功而未提交评论时服务端不自主续发（按部分成功报告）。
- **自动入口只唤起、不发送**：唯一可信来源是宿主 `chat.receive.after_process` 载荷
  （不经模型）；只对白名单源群里非机器人自身、非通知的 QQ 消息中**已选中候选类型**
  的候选给源群**一次** `maisaka.proactive.trigger` 机会（卡片优先归 `forward`，无
  卡片时图文混排归 `image`、非空文字归 `text`，提及只作附属；分类成功不承诺可
  发送），意图不得伪造或摘抄聊天内容，群名只作不可信显示文本（不得成为路由依据，
  尖括号转全角），不掷骰、不签目标群决策票、不追加上下文、不对目标群唤起、不直接
  调用服务发送。消息可读取性用源消息 ID **有限**确认（10 秒上限），确认不了就放弃
  并记录可定位原因；同一候选的去重是有界内存状态（10 分钟／4096 项），与持久投递
  账本无关。普通文字与图片仅在对应类型被显式选中时才触发自动入口；目标名称查询
  结束后重读最新配置再提交（含候选类型与最新标准），已提交给宿主的判断不追溯改写，
  也不为新配置重复唤起同一候选。
- **候选类型与自动分享标准是配置，只影响自动评估**：`auto.message_types` 默认
  `["forward"]`，空列表表示不提供任何自动判断机会（不影响显式工具调用），未知
  枚举被明确拒绝、不解释为全选；`auto.share_criteria` 上限 4000 字符、空或全空白
  回退设计原文，只按文字处理、不做模板展开或命令执行。标准是交给源群 Maisaka 的
  自然语言判断依据，**不保证模型必然遵循**，也不得成为群友明确请求的额外内容偏好
  门禁：显式 `forward_message` 调用只受总开关、白名单、内容完整性、服务绑定与防重
  约束，不要求自动评估资格；标准不得改变路由、工具权限或支持的发送类型。
- **生命周期与 Hook 名称以核实契约为准**（Host `a995cc4` / SDK `4d8e577`）：
  `on_load` / `on_unload` / `on_config_update`，观察 Hook 为
  `chat.receive.after_process`。不要凭记忆改写成 `on_start` 之类的名字。
- **卸载与热更新只取消自己的工作，且不得假装远端已停止**：插件持有并等待**本插件
  创建的**后台任务（自动等待 + 在途投递，登记在 `_tasks`），`on_unload` 先停止签发
  新阶段授权、尽力请求远端撤销未消费授权（总预算有界，不可达时如实告警「撤销未
  确认」，不宣称远端已停止），再取消并**有界等待**退出（上限
  `TASK_EXIT_WAIT_SECONDS`，超出告警而非静默），不触碰其他插件的任务；
  `on_config_update` 只取消失效的待执行自动判断（如候选类型被移除、开关或白名单
  变化），只改标准不取消仍合法的候选、等待结束后用最新标准提交，投递不整体取消
  ——在途发送可能已产生副作用，正确做法是**源阶段与评论阶段授权前**按最新配置复验
  （`_send_allowed`），未发送的一律不发送、已成功的不回滚。热更新入口按宿主顺序
  （先注入配置再调用）读 `self.config`，不得缓存旧快照；复验失败的尝试按「明确未
  发送」处理（尽力撤销、按 `rejected` 报告），绝不降级为待核实，也不得跳过复验
  直接发送。
- **只导入 SDK 根 `__all__` 内的名字**：`HookMode` / `HookOrder` / `ErrorPolicy`
  只存在于 `maibot_sdk.types`，不在根导出面，hook 模式用字符串字面量
  `"observe"` / `"blocking"`（由 `tests/fake_maibot_sdk.py` 的
  `SDK_ROOT_EXPORTS` 与 `test_生产代码只导入SDK顶层导出的名字` 守住）。
- **`get_components()` 顶层 `chat_scope` 修正不得删除**：Runner 只读组件声明顶层，
  `@Tool(chat_scope=…)` 经 SDK 只落进 metadata，删掉会让群聊专用工具在私聊可见。
- **不把目标群历史写成保证**：本工具只保证 QQ 目标群收到消息与源群获得真实结果；
  目标群宿主消息记录与 Maisaka 历史同步是明确的不保证项，不得通过写宿主数据库、
  伪造入站消息、追加摘要或重发来“补齐”。
- 引用宿主源码前先在 `arcwsl:~/github/REFERENCE/` 只读核实；禁止部署、发群消息、
  修改远端仓库、读取凭证与运行配置。
- 代码、注释与文档一律中文；不使用全局依赖。
