# snowluma-forward-service Specification

## Purpose

定义独立 SnowLuma 转发服务器与 MaiBot 侧专用客户端的通信和执行契约，使源群 Maisaka 的合法工具调用能够转发原卡片、普通文字、图片及评论，并在认证、权限变化、网络中断、服务重启和账本迁移时保持可核实结果与防重安全，不依赖修改宿主或现有 QQ 适配器。

## Requirements

### Requirement: 独立服务与专用调用边界

系统 MUST 提供独立可部署服务器和客户端，服务器仅执行合法工具请求对应的源发送、评论发送、结果查询与撤销。MUST NOT 提供任意 OneBot 动作代理、任意外部地址访问或服务端自主分享。宿主侧工具的调用者仍为 Maisaka；候选观察与服务器执行 MUST 分离。客户端、服务器及网关各自地址和状态目录 MUST 由受控部署配置指定，MUST NOT 从模型参数或消息正文取得。

#### Scenario: 无工具调用
- **WHEN** 服务端在线且源群不断出现候选，但 Maisaka 未调用工具
- **THEN** 服务端不会仅因消息出现而发送任何转发或评论

#### Scenario: 请求任意动作
- **WHEN** 调用者试图指定任意平台动作、目标连接或自定义可执行消息类型
- **THEN** 拒绝请求，不将其转发到网关

### Requirement: 认证与最小账号权限

所有可读取投递状态或产生副作用的接口 MUST 认证。服务端 MUST 将调用身份绑定到明确账号及源/目标权限上限，确认网关实际登录账号一致；有效权限 MUST 同时满足客户端当前许可和服务端上限。凭证 MUST 来自环境变量，不写入配置样例、请求日志、持久账本或模型可见结果。跨主机连接 MUST 保护传输并验证对端；默认监听范围 MUST 不暴露到非受信网络。认证失败、账号改变或目标不可确认 MUST 关闭发送。

#### Scenario: 伪造授权或越界目标
- **WHEN** 缺少认证、认证身份对应另一账号或目标超出该身份许可范围
- **THEN** 不查询后泄露源正文，不登记可发送任务，不调用平台发送

#### Scenario: 网关账号变化
- **WHEN** 网关重连后实际账号与服务绑定账号不同
- **THEN** 旧授权失效，新发送拒绝，已有回执保留

### Requirement: 源材料来自可信源消息

服务器 MUST 通过绑定账号的网关查询指定源消息并核对群归属，MUST NOT 将客户端任意提交的正文、卡片资源 ID 或媒体路径当成源消息。客户端 MUST 先完成可信宿主来源绑定；服务器仍 MUST 独立核对源身份。仅有三参数中的 `comment` 可作为本次额外文本。原卡片 MUST 从可信源结构取得资源引用，仅校验顶层支持形态，不递归改写资源；普通文字/图片 MUST 校验完整内容，并对普通提及保留对象信息、转成文本。

#### Scenario: 源群不符
- **WHEN** 查询得到的源消息实际属于另一群
- **THEN** 发送前拒绝，不把查询到的正文返回模型

#### Scenario: 卡片内部不支持段
- **WHEN** 源结构为受支持的单张卡片且资源引用可用，内部包含回复、视频或提及
- **THEN** 复用原资源，不要求提取内部节点，也不删除其内部内容

#### Scenario: 普通内容不完整
- **WHEN** 普通源消息混入不支持段、图片不可恢复或提及对象不明
- **THEN** 整条拒绝，不静默舍弃某段后发送

### Requirement: 准备与执行分离

服务端接收发送准备请求 MUST 只进行校验、源材料准备和有界状态登记，不发送消息。实际源发送与评论发送 MUST 分别要求客户端依据最新配置签发的单次阶段授权，且绑定确定的投递身份、尝试及阶段；准备成功、状态查询、心跳、恢复和重复查询 MUST NOT 成为发送触发。过期、撤销、旧客户端运行实例或旧权限版本的未消费授权 MUST 拒绝。

#### Scenario: 准备后无授权
- **WHEN** 准备已成功但客户端退出、断线或不继续提交阶段授权
- **THEN** 不产生平台发送，准备状态在有限期限后失效

#### Scenario: 错用阶段授权
- **WHEN** 用源授权发送评论、换目标重用授权或提交旧版本授权
- **THEN** 拒绝，不产生相应发送；已消费授权的重复请求只返回同一阶段结果

### Requirement: 发送结果与只读核实

只有平台成功回执及可核实的真实目标消息身份才允许确认发送成功。源消息 ID、原资源 ID、服务器任务 ID 和仅本地生成的网关标识 MUST NOT 冒充真实目标回执。请求受理、超时、传输取消、回执缺失和模糊平台失败 MUST 区别处理；平台可能已产生副作用时 MUST 记录未知。查询接口 MUST 返回已持久化的已知结果，MUST NOT 通过再次发送来确认；不能核实的结果 MUST 保持未知。

#### Scenario: 平台已发但响应丢失
- **WHEN** 网关发送可能成功而客户端或服务端未取得可靠回执
- **THEN** 投递保持阻断重发状态，后续只读查询不会启动新的源发送

#### Scenario: 仅返回内部标识
- **WHEN** 服务或网关仅提供本地任务/不透明 ID，无法核实真实目标消息身份
- **THEN** 不返回完整成功，提供结果未知及具体阶段

### Requirement: 服务端持久投递事实

迁移后的服务端账本 MUST 是新投递的唯一权威。源发送前 MUST 持久占位，账本不可读或占位失败时 MUST 不发送；成功回执后 MUST 立即落账，失败时停止后续评论并如实保留已知回执。唯一投递身份 MUST 为账号、源群、源消息 ID、目标群，MUST 不包含评论、请求 ID 或进程 ID。并发与重放 MUST 原子地决定至多一个合法发送尝试；评论同样 MUST 有发送前占位。未知状态及重启遗留发送占位 MUST 阻止自动重试。只有确认未发的终态才允许新的显式尝试，旧尝试重放不得重启它。

#### Scenario: 并发与新请求 ID
- **WHEN** 两个调用使用不同请求 ID 但对应同一投递身份
- **THEN** 至多一个源发送被执行，另一调用得到现有状态；更换评论也不能绕过

#### Scenario: 重启恢复
- **WHEN** 服务启动时发现源或评论在途占位
- **THEN** 保守归并为待核实，不自动补发；纯准备状态失效而非自动执行

#### Scenario: 发送前后落盘失败
- **WHEN** 占位写入失败，或已收到平台成功回执但终态写入失败
- **THEN** 前者不发送；后者不继续评论、不允许重发，并报告已知投递事实及未落盘限制

#### Scenario: 旧失败尝试重放
- **WHEN** 已明确未发送的尝试再次收到相同执行请求
- **THEN** 返回该尝试原结果，不自动重启；重试需要新的合法工具调用和新尝试授权

### Requirement: 撤销与有限生命周期

客户端配置收缩、关闭或卸载 MUST 停止签发新阶段授权，并尽力通知服务端撤销未执行工作。服务端 MUST 对撤销与实际发送的开始建立确定顺序；撤销已确认的未执行授权不能再次启动。已发出或无法证明未发出的请求 MUST 保留真实结果或未知，MUST NOT 因本地任务取消登记成可重试失败。未提交阶段和失联客户端的准备状态 MUST 有限过期；服务器 MUST 不独立续发评论。退出 MUST 有界等待并报告残留任务。

#### Scenario: 撤销先完成
- **WHEN** 服务端先确认撤销，随后收到该授权的延迟执行请求
- **THEN** 拒绝发送并返回已撤销，不由旧请求重新激活

#### Scenario: 发送先开始
- **WHEN** 平台调用已开始后客户端请求撤销
- **THEN** 不承诺撤回；按实际回执登记，回执不可核实时保持未知

#### Scenario: 控制连接不可达
- **WHEN** 客户端停止时无法确认远端撤销
- **THEN** 本地拒绝新工作、记录未确认阶段；不宣称远端已停止，服务端到期禁止未消费授权继续执行

### Requirement: 旧账本迁移与回滚防重

启用新投递前 MUST 明确选择新装或本插件旧账本迁移，不得将缺失或损坏旧库默认为无历史。迁移 MUST 在旧发送停止后进行，验证快照完整性、导入数量和状态，不修改或删除原库；成功及未知记录 MUST 保留阻断作用，遗留发送中 MUST 归为待核实，评论结果一并保留。服务及客户端 MUST 绑定同一账本身份，误连空账本 MUST 关闭发送。回滚 MUST 停止新路径并保留新结果的防重作用，MUST NOT 直接启用只含旧快照的旧插件。只允许迁移本插件数据。

#### Scenario: 迁移成功记录
- **WHEN** 旧账本记录某源已向某目标发送成功或结果未知
- **THEN** 新服务拒绝重复发送，不能因当前进程、客户端或评论变化解锁

#### Scenario: 迁移失败或误连新库
- **WHEN** 迁移不完整、数据冲突、库损坏或账本身份不匹配
- **THEN** 发送保持关闭，报告可定位原因，不把它当成空库重新投递

#### Scenario: 回滚
- **WHEN** 新服务已产生投递后需要退回旧实现
- **THEN** 先停新路径，再验证包含新结果的兼容防重快照；无法安全回迁时保持关闭，不同时运行两条发送路径

### Requirement: 最小数据与部署隔离

服务端 MUST 使用自己受控的状态目录且单实例运行，客户端不得共享打开该 SQLite 文件。准备材料、未发送评论、临时媒体和授权 MUST 有界保存，完成或过期后清理；成功及未知防重记录 MUST 不按 TTL 或容量静默删除。日志 MUST 仅记录必要的投递身份、阶段和错误类别，不记录凭证、原卡片资源标识、聊天正文或评论正文。源媒体访问 MUST 受限制，不接受调用者指定本机路径或任意下载地址。部署、凭证配置和真实发群测试 MUST 另行授权。

#### Scenario: 不可信媒体地址
- **WHEN** 源材料或请求包含不能确认为网关合法媒体的本机路径或任意地址
- **THEN** 不读取本机文件或任意内网资源，按内容不可完整恢复拒绝

#### Scenario: 状态与临时材料保留
- **WHEN** 请求完成、失效或服务重启
- **THEN** 清理临时材料但保留源/评论投递事实，日志不泄露其正文或凭证
