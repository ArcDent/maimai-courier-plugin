# 将转发独立为麦麦搬运喵，由源群 Maisaka 决策

已确认将转发功能独立为 `maimai-courier-plugin`（麦麦搬运喵），同时保留自动和工具两种入口。自动入口仅关注合并转发，由源群 Maisaka 判断是否分享，再调用同一个接收消息 ID、目标群 ID 和评论内容的工具；不保留概率掷骰和目标群决策票。工具还支持普通文字、图片等消息，不支持的类型明确报错。

用户新增要求：评论内容由调用工具的 Maisaka 提供，随本次转发发往目标群。已确认顺序为先转发源消息，延迟一小段时间，再发送评论；不是一次原子发送，不重新交给目标群 Maisaka 生成另一条评论。`comment` 允许为空，为空时只转发，不等待评论延迟。延迟已确定为固定 0.5 秒，不随机、不提供配置覆盖。设计建议为转发失败不发评论；转发成功但评论失败时保留源消息已投递事实，明确返回部分成功，不以重发源消息补偿评论失败。

两入口共用源群、目标群白名单，工具只能转发调用所在源群的消息。成功投递记录持久化，跨重启防重：同一源消息不再发送到同一目标群；同一目标的并发调用也必须合并或拒绝，失败不得伪记成功。转发内容应由主程序正常发送记录进入 Maisaka 上下文，不另加插件上下文注入。允许破坏性重构，但旧插件的业务移除、部署切换和数据清理尚未实施。

用户已授权进入规格编写：新项目使用变更 `introduce-maimai-courier`，旧项目使用 `remove-cross-group-forward` 完整删除转发功能而非保留关闭壳。产品边界已确认；完整规划等待审阅，所以本 ADR 保持 proposed。当前没有业务实现，没有执行 Git 初始化或其他 Git 写操作。

## 取舍与证据

旧方案的概率门禁、目标群票据和额外注入与新目标冲突，不为兼容旧行为继续保留；现有请求实现中的发送参数与消息归属校验可按需复用，不整包移植其查看资格和多轮恢复机制。

源码事实与研究边界见原项目 [ADR 0014](../../../repeat-plugin/docs/adr/0014-standalone-forward-plugin.md)（此链接按同级项目布局解析）。主程序 `send.forward` 支持节点发送、消息存储和内建 Maisaka 历史同步，不是协议端按 ID 转发的直接包装；协议端按 ID 转发本身不能证明已进入主程序上下文。完整验收须涵盖目标会话路由、活跃/冷会话、失败时无伪造成功记录及媒体保真。

## 规格与验证边界

- 新项目 `introduce-maimai-courier` 已创建 proposal、specs、design、tasks，主程序发送支持矩阵和冷会话上下文验证是实施前置条件。
- 自动入口在合并转发可读后唤起源群判断；目标群不另行触发评论生成，评论只来自工具可选参数并固定延迟 0.5 秒。
- 旧项目 `remove-cross-group-forward` 规划完整删除转发代码、配置、工具与专属测试，不保留兼容壳；保留历史文档和线上状态数据。切换先停旧转发再启用新插件。

本地 runbook 首次同步清单已获用户确认：`.local/runbooks/maibot-plugin.md` 与仅包含有效链接的 `.local/runbooks/INDEX.md`；不复制无关运维记录、运行配置或凭证。阶段二只编写规划工件，runbook 已纳入新项目实施任务 5.2，尚未同步；业务实现等待后续授权。
