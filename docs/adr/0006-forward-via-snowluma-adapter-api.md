# 复用适配器公开 API，独立服务实现保留为历史

> 2026-10-02：用户结合 OneBot WebSocket 服务端截图，明确改选“插件自己作为客户端直连 SnowLuma 已有服务端”，见 [ADR 0007](0007-direct-snowluma-websocket-client.md)。下文保留曾确认的适配器 API 方向及其背景，不再作为当前发送架构依据；旧实现保留与非连接类产品边界由新决策承接。

根据[返工方向报告](../rework-direct-snowluma-via-adapter-api.md)，本轮选择“插件 → 现有适配器公开 API → SnowLuma”作为唯一发送方向，取代 [ADR 0005](0005-separate-snowluma-forward-service.md) 的独立服务方案。SnowLuma 已是现有运行件，插件复用适配器连接与凭证，不再要求用户部署第三个常驻进程、配置新的连接端点或凭证。代价是依赖适配器公开 API 的可用性与兼容性，不能将它视为宿主正常发送服务，也不能承诺目标群宿主消息记录或 Maisaka 历史同步。

本记录描述已确认的返工方向与保留边界，**不表示运行代码已返工、API 契约已重新核实或真实 QQ 联验已通过**。阶段一只调整术语与设计决策；新规划和实现仍需按后续阶段推进。

## 旧实现保留边界

用户明确选择：旧独立服务代码及其专属测试继续留在仓库中作为历史，返工完成后彻底退出插件运行、部署及默认验证路径。本轮不按方向报告的删除清单直接删除 `service/`、`remote_client.py` 或专属测试，尤其不能假定尚未跟踪的文件已经存在于 Git 历史中。

历史实现不是备用发送通道；新插件不能因适配器不可用而重新连接独立服务或调用宿主旧发送通道。历史代码的隔离位置、关联依赖与测试收集边界在新变更中明确，不能仅靠文档写“已退役”而仍被入口导入、打包为运行依赖或纳入默认测试收集。历史保留不要求继续维护第二套可部署产品。

## 沿用的产品边界

- 源群 Maisaka 仍决定是否分享、选择源消息及目标群，使用原有三参数 `forward_message`；自动入口只提供源群判断机会，不直接发送。来源凭据、两级白名单、账号归属及目标不同于源群的约束继续有效，模型不能提交任意动作、端点或授权信息。
- 普通文字、图片、原卡片及可选评论统一经适配器公开 API 执行，不修改宿主或适配器。[ADR 0004](0004-preserve-original-forward-card.md) 的原卡片内部保留继续有效；普通消息提及仍转成保留对象信息的普通文本。媒体或原资源不可恢复时整条拒绝，不以摘要、丢段或节点重建替代。
- 本插件自己的持久投递账本恢复为唯一防重权威，复用本插件既有数据，保留成功和待核实记录的跨重启阻断作用；不读取复读插件或其他插件的账本，不维护并行服务账本。报告的“零账本迁移”仅适用于仍以本插件原账本为权威、尚未切换到服务账本的使用路径，不能据此忽略已有服务投递事实或自动创建空库绕过防重。
- 真实目标消息证据与结果持久登记继续作为成功判据。可能已提交的发送遇到超时、取消、回执不足或落盘失败时保守报告，不自动重试、不换动作或通路探测重发。
- 评论只来自本次参数；源成功并落账后等待固定 0.5 秒，按最新开关与白名单复验再发送。源失败或未知不进入评论，重复调用不补评论；关闭或卸载阻止未提交的工作，但不能把本地取消当作已撤回适配器请求。

## 规划基线与待核实事实

本次检查期间，旧变更已出现在 `openspec/changes/archive/2026-10-02-move-forwarding-to-snowluma-service/`，主规格已包含独立服务要求及 `snowluma-forward-service` 能力。后续应基于当前主规格新增返工变更，建议名 `forward-via-snowluma-adapter-api`，明确修改跨群转发契约并移除活跃的独立服务能力；保留既有归档，不倒退或伪造它的任务状态。归档任务 8.4 仍未完成，归档本身不是已部署或真实联验通过的证据。

现有报告记录了适配器 `1.0.3` 的源码基线，但不能据此承诺任意版本兼容。后续需只读核实提供方限定调用方式、`api.call` 的真实签名及错误面、源消息与账号核对、卡片资源及图片可重放材料、真实目标回执证据和查询上界，再确定支持范围；未经核实不编造接口、版本区间或把动作异常认定为明确未发送。若核实推翻方向报告的可行性或需要缩减产品支持范围，应返回需求对齐，不在实现中静默改约定。

本决定不授权部署、读取凭证或真实运行配置、发群联验、账本迁移、Git 写操作或删除文件。
