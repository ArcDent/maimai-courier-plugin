# 插件作为客户端直连 SnowLuma 已有 WebSocket 服务端

用户结合 OneBot 协议端点截图明确选择：本插件在 MaiBot 插件进程内创建自己的正向 WebSocket 客户端，直接连接 SnowLuma 已有的 WebSocket 服务端，既不新增独立转发服务进程，也不借用 MaiBot 适配器的公开 API。此决定取代 [ADR 0006](0006-forward-via-snowluma-adapter-api.md) 的适配器 API 路径；[ADR 0005](0005-separate-snowluma-forward-service.md) 的独立服务路径同样不恢复。代价是插件负责自己的连接、认证引用、回执关联和生命周期，而不是复用适配器内部连接与凭证。

本记录确认架构方向，**不表示业务代码已返工、连接契约已重新核实或真实 QQ 联验已通过**。本轮仍处于阶段一，主规格与运行代码保留当前状态，待新变更驱动后续返工。

## 截图证据与报告纠偏

- 截图处于“WS 服务端”页面，说明是 SnowLuma 本地监听、客户端主动连接；不是让插件监听端口等待 SnowLuma 反向连接。
- 截图列出两个启用的 `Universal` 端点：端口 `3001` 显示一个客户端，端口 `3002` 显示两个客户端，均显示已设 Token。这证明截图时第二个端点存在多个客户端连接，不证明客户端身份、任意新客户端权限、响应隔离或并发行为。
- 两个端点的“上报自身”设置不同。不能由此认定插件直连后的发送一定进入宿主历史，也不能把事件回流当成投递成功证据。
- `0.0.0.0` 是截图中的监听地址，不是插件应直接使用的连接目标。实际可达主机地址、路径、部署版本与网络边界须在部署时由操作者提供并核实；不把截图中的端口或账号写成代码默认值。
- [方向报告](../rework-direct-snowluma-via-adapter-api.md) 的“无需新增服务进程”仍符合目标；“必须借适配器 API”“零新增连接配置”“因此删除 aiohttp 并新增 api.call 能力”不再作为规划前提。直连需要受控地址与凭证环境变量名，凭证值不得写入配置、文档、日志或仓库，也不自动读取适配器配置或凭证。
- 报告中的 API 名、图片可重放字段、回执核实字段及版本兼容范围仅作为调查线索，不能因架构方向已确认就视为已重新核实。

## 沿用的产品与历史边界

此决定改变发送连接方式，不自动扩大功能范围，也不推翻既有非连接类约定：

- 保留三参数 `forward_message`、宿主签发的一次性来源凭据、源群与目标群白名单、目标不同于源群及账号一致性核对。所有源发送与本次可选评论统一使用插件自己的受控连接，模型不获得任意 OneBot 动作、端点或凭证参数。
- 自动候选仍仅从宿主已处理入站 Hook 进入，只唤起源群 Maisaka 判断；直连收到的普通消息、自发消息及通知不成为第二套自动入口，不伪造宿主入站、不向目标群追加历史。连接管理事件与动作响应的处理在设计中明确。
- 普通消息提及继续文本化；原卡片按原资源引用发送，内部不展开改写、不上传重建节点。原卡片外层展示不承诺字节级一致，真实可打开性与提醒行为仍需获准联验。
- 插件自己的持久投递账本恢复为唯一防重权威，保留成功及待核实记录的跨重启阻断；发送前持久占位，成功证据及时落账。断线、超时、取消或回执不足不得触发自动重发，也不改用适配器 API、宿主旧发送能力或历史服务探测重发。
- 源成功并落账后才等待固定 0.5 秒，再读最新开关与白名单决定是否发送本次评论；源失败或未知不进评论，重复调用不补评论。卸载只管理本插件任务与连接，不关闭其它客户端；本地取消不等于 SnowLuma 已撤回请求。
- 沿用 ADR 0006 已记录的历史保留决定：旧独立服务代码及专属测试保留、退出活跃运行与默认验证路径，不据报告直接删除尚未跟踪的文件。实现阶段优先复用经核实的现有传输、材料、回执与账本逻辑，不能把整个旧服务继续作为运行依赖，也不维护第二套发送通道。
- “无需账本迁移”只适用于从未切换权威账本的安装。不能凭报告断言所有安装均满足此前提；发现已有服务绑定或无法确认的投递事实时，应停止发送并要求核对，不创建空库绕过防重，不读取其他插件的账本。

## 后续规格的核实边界

新变更建议命名为 `direct-snowluma-websocket-forwarding`，从当前主规格出发修改跨群转发契约、移除活跃的独立服务要求；不改写既有归档任务的完成状态。进入实现前至少核实以下契约，不能把截图替代源码或真实联验证据：

1. 正向 WebSocket 的认证、端点路径、`Universal` 上的事件与动作响应、`echo` 配对，以及多客户端是否按请求连接返回动作响应；插件必须避免事件回流造成重复判断或发送。
2. 可信宿主源消息标识到同账号 OneBot 源消息的对应、源群归属、卡片资源及图片可重放材料；无法确认时整条拒绝，不接受模型补填资源或身份信息。
3. 发送动作的参数与错误语义、真实目标回执的核实方式和有界查询；区分明确未提交与可能已提交，重连不能重放未确认动作。
4. 固定地址与账号核对、连接关闭及热更新期间的在途请求处理、有界资源占用；不能因修改连接配置使同一投递的源与评论跨账号执行。
5. 本插件原账本兼容、历史服务状态识别、专属测试隔离，以及最小网络依赖的清单声明。现有 `service/onebot.py` 等仅为可复用实现候选，测试存在不代表新直连架构已验证。

事实核实若推翻可行性或要求缩减产品支持范围，应返回需求对齐，而不是在实现中静默改约定。本决定不授权部署、读取凭证或真实运行配置、修改远端、发群消息、账本迁移、Git 写操作或删除文件。
