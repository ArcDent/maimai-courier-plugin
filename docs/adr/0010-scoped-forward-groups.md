# 源／目标平铺白名单收敛为具名转发分组（转发分组）

## 背景与动机

`[scope]` 节此前是两份平铺白名单（`source_groups` / `target_groups`）：平铺结构下
任意源群可发往任意目标群，唯一约束是「目标 ≠ 来源群自身」。实际投递诉求是分区
的：一个吃瓜群常需同时接收多个源群的料，而某个源群的料可能只给固定对象；平铺
白名单无法表达「同组才能互投」，多源多目标场景下越权面随目标数量线性放大。

## 决策

1. `[scope]` 节改为 `groups` 具名分组结构数组，每项含必填 `name`、`source_groups`
   与 `target_groups`；两份平铺白名单直接移除，不设兼容期（与 ADR 0008 同风格），
   配置版本随之提升；默认空数组等价于旧的空白名单（没有源也没有目标）。
2. 判定口径统一为**目标必须与来源同组**。三处消费方（工具预检与提交前复验、评论
   阶段复验、自动入口的候选筛选与目标列举）共用同一个分组判定函数，不复制第二套。
3. 结构校验在配置期完成：源群跨组重复、同一分组内源群重复、`name` 跨组重复或为
   空白，一律拒绝写入。空目标分组与组内「源 = 目标」允许保存，由运行期既有的
   「目标 ≠ 来源群自身」规则拒绝。
4. `name` 不参与任何路由、权限或判断，只作用户自己的标识与日志前缀；不限长、
   不限字符集，但不可空白、不可跨组重复。
5. 目标群可跨组重复（多个源群喂同一个吃瓜群）；源群也可兼作别组的目标群，实际
   投递仍受「目标 ≠ 来源群自身」兜底。

## 代价与不变量

- 代价：存量用户需手工把平铺白名单改写成分组；代码三处消费方与测试夹具全部
  迁移。
- 不变量：四字段账本键（账号/源群/源消息 ID/目标群）不变；自动入口的「没有合法
  目标群即不唤起」行为保留，只是目标范围收紧为同组；热更新复验改按同组口径，
  未发送的不发送、已成功的不回滚。

## 未确认项

无外部契约变化；真实 QQ 联验另见 `docs/real-qq-validation.md`，离线通过不等于
联验完成。
