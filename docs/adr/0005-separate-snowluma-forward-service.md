# 新增独立转发服务器与客户端，Maisaka 保留工具调用职责

> 2026-10-02：本方案已由 [ADR 0006](0006-forward-via-snowluma-adapter-api.md) 的适配器公开 API 方案取代。下文保留原决策背景与实现记录；旧服务代码保留为历史，退出运行、部署与默认验证路径属于后续返工任务，尚未完成。旧变更已归档，但真实 QQ 联验任务仍未完成，不能将归档理解为上线验证通过。

用户明确选择新增独立服务器／客户端，而不是仅复用现有宿主—适配器通信与公开 API。Maisaka 保留源消息选择、目标群选择及工具调用职责；MaiBot 侧客户端接收该工具调用，请求 SnowLuma 侧服务执行实际转发。服务端不接管是否值得分享的模型判断。

自动入口沿用现有职责：源群出现符合条件的候选消息后，只唤起源群 Planner，由 Maisaka 决定是否调用转发工具，也可以保持沉默。**自动入口不直接调用转发服务；服务端收到实际工具调用对应的合法请求后才执行发送。** 调用关系固定为“候选消息 → 源群 Planner → Maisaka 选择调用工具 → 客户端 → SnowLuma 侧服务器 → 实际转发 → 工具结果返回 Maisaka”。群友明确请求也由 Maisaka 调用同一个工具完成，不另设绕过判断的自动发送路径。

已有适配器公开 API 虽可执行单消息转发，但不直接提供宿主正常发送服务的落库、历史同步与目标会话路由保证。用户已明确接受本次独立服务转发只保证 QQ 目标群收到消息、源群 Maisaka 获得真实工具结果，**不保证目标群 Maisaka 的历史同步**。因此不为了补齐历史而修改宿主/适配器、直接写宿主数据库或追加上下文；既有来源绑定、白名单、防重与不确定结果保护仍需保留。

用户另已确认改动范围：仅修改搬运插件并新增独立服务／客户端，现有 QQ 适配器和 MaiBot 宿主保持不变。实现应使用已公开能力，不以猴子补丁、运行时替换宿主逻辑或直接写宿主数据库规避这一边界。

用户已确认迁移范围：**`forward_message` 的全部发送统一迁移到新服务，包括普通文字、图片、合并转发卡片与可选评论**；旧宿主发送通道不作为本工具的备用发送路径。自动入口仍只提供 Planner 判断机会，该范围选择不授权自动入口直接调用服务。

本次按专用跨群转发服务规划，不把任意 OneBot 动作直接开放给模型。原卡片内部内容保留的产品决定见 [ADR 0004](0004-preserve-original-forward-card.md)。普通文字、图片迁移的是执行位置，未另行改变其支持范围与提及转普通文本的规则；只有原卡片内部免于逐段改写。客户端接入位置、通信协议、身份认证和账本归属在规格设计阶段确定；不新增“发送后补记宿主历史”的能力。

## 沿用的安全与行为边界

- 账号、源群、源消息及目标群必须与可信工具调用上下文和白名单匹配；服务端只执行合法请求，不接受任意 OneBot 动作或模型自填的授权信息。
- 客户端重传、断线和服务重启不得造成相同投递重复发送；既有已投递记录不能因迁移而失去防重作用。超时、取消、回执丢失或发送后落盘失败继续按结果未知保守处理，不换通路重发。
- 原卡片资源或网关缓存不可用时明确报告，不用摘要、残缺内容或节点重建冒充原卡片转发。
- 评论仍来自本次工具参数；源消息确认成功并落账后等待固定 0.5 秒，再经权限复验发送。空白评论不等待；评论失败保留源投递事实，不重发源消息或自动补评论。
- 关闭插件或撤销权限后阻止尚未发送的工作；已发出的消息不回滚。远端取消、授权时效及阶段复验如何实现必须在设计和验收中明确，不能把本地任务取消视为远端已停止。
- 本工具所有迁移后的发送均不承诺目标群 Maisaka 历史同步；成功依据仍为真实平台投递结果，不等同于“请求已被服务器接受”。

上述核查说明新增服务与正常目标历史之间不能直接画等号，不是平台绝对不可能支持的证明。用户据此选择将目标群 Maisaka 历史同步排除出本次独立服务转发的保证范围；即使对端自发事件偶然回流，也不将其当成稳定的成功条件。这调整了 [ADR 0001](0001-standalone-source-decided-forward.md) 对本工具发送的正常历史要求，适用于已确认迁移的普通文字、图片、合并转发卡片与评论。

本记录只确认独立服务边界与调用职责。实现设计见变更 `move-forwarding-to-snowluma-service` 的 design；业务代码已完成迁移（插件侧客户端、独立服务与服务端账本，插件不再调用宿主发送能力），主规格正式同步、真实部署与发群联验仍属待获准阶段，本记录不构成部署授权，也不代表线上投递已验证。
