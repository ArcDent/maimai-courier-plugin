# 插件直连 SnowLuma 运维清单

当前唯一运行路径为 MaiBot 插件进程内客户端 → 操作者已有的 SnowLuma 正向 WebSocket
服务端。本文是获准后的操作核对清单，**本轮未部署、未读取真实配置/凭证/账本、未发群**。
旧独立服务的启动、迁移和导出命令已退出活跃路径，不需要新增服务、监听端口或后台进程。

## 1. 放行前提

1. 保持 `plugin.enabled=false`，确认唯一发送入口；不同时启用旧服务或旧发送实现。
2. 核实实际加载的 Host/SDK 与插件清单范围相符：Host 1.2.5–1.99.99，SDK 2.8.0–2.99.99。
   公开 SDK 2.8.0 源码核实只是接口证据，不是运行版本证明。此前宿主锁文件为 2.5.2，
   不能据此推断运行版本；若实际为 2.5.2，则不满足加载条件。
3. 逐项另行确认归档的 [U1–U8](../openspec/changes/archive/2026-10-04-direct-snowluma-websocket-forwarding/verification/unverified-server-contracts.md)。
   特别是仅 Bearer 头认证、图片 DNS/重定向后的安全获取、原卡片资源与真实平台回执含义。
   这些当前全部未确认；失败则停止并返回规划，不临时改动作或放宽判据。
4. 确认插件依赖由 `_manifest.json` 装载 `aiohttp>=3.14.3`。旧服务的项目依赖快照只在历史区，
   不运行 `uv sync` 安装旧服务，不从历史目录 import。
5. 确认实际受保护端点、同账号来源条件、测试源群/目标群白名单及本插件账本完整性。
   真实部署、环境注入和发群须另行授权；满足离线检查不等于授权。

## 2. 地址与凭证

`[snowluma]` 有三项，默认均为空：

```toml
[snowluma]
websocket_url = ""
token = ""
token_env_var = ""
```

- 地址只来自受控配置，精确指向已有服务端；明文 `ws` 只允许回环、私有或链路本地
  目标，主机名在建连前解析确认（解析出公网地址或失败即拒绝），公网目标必须使用
  `wss` 并验证证书和主机名。URL 不含用户信息、查询串、片段或凭证；`0.0.0.0`/`::`
  是监听地址而非连接目标。不自动选端口、探测账号或跟随重定向。
- 容器内 `localhost` 只指容器自己。跨容器或宿主网络需要操作者提供真实可达端点：
  明文只允许解析为回环/私有/链路本地的目标，公网必须 `wss`；截图端口及客户端数量
  不能证明可达性、身份、权限或响应隔离。
- `token` 可直接填写令牌，非空且非全空白时优先使用；明文保存在插件配置，须限制
  文件权限，不把含真实令牌的配置提交到仓库或分享。
- `token_env_var` 填环境变量名，例如 `MAIMAI_COURIER_ONEBOT_TOKEN`，不是值。
  `token` 留空或全空白时，才在建连时读取操作者注入宿主插件进程的该变量。
  不读取别的插件/适配器配置补齐，凭证不写命令历史、日志、账本或 URL。
- 凭证只通过认证头发送。缺值、空值、认证失败或重定向停止连接；配置令牌认证失败
  不改用环境变量重试，也不退回 URL token。配置令牌、变量引用或地址变更使旧投递
  未提交阶段失效；同一变量的值轮换应先停止并完全退出本插件旧连接，再注入新环境、
  重新加载，不假设既有连接会重新认证。
- 总开关关闭、配置不完整时仍能加载和注册三个组件；加载不建连。只有合法工具请求
  按需建立连接，断线没有后台自动重连或重放循环。

## 3. 唯一账本与升级停止条件

状态只在宿主授予本插件的 `ctx.paths.data_dir`：`delivery_ledger.sqlite3` 是唯一投递
权威，`delivery_ledger.lock` 用于独占。四字段键仍为账号、源群、源消息 ID、目标群。
只读查询和重启恢复不发送；成功/未知不因时间、容量、更换评论或重建连接失效。

打开顺序为独占 → 本目录历史识别 → 已有库结构/记录核实 → 兼容扩展与恢复。完整原库
可以继续使用；源 `sending` 恢复 `unknown`，评论 `sending` 只把评论恢复 `unknown`，
源 `sent` 保留。不同实例不能同时打开同一目录；仅确认新装的空目录才能初始化。

以下任一情况都保持 `ledger_unavailable`，不建立发送连接：

- `service_binding.json` 或 `service_binding.json.tmp`，无论是否可解析；
- 命中状态类证据名字规则的条目：主库以外的数据库/归档副本、`.tmp-<8位十六进制>`
  导出临时名、归档类扩展名（`.tar/.tgz/.gz/.zip/.7z/.rar/.bak`）、中文「快照/归档/
  备份」标记、其他锁文件等无法确认来源的状态痕迹；
- 主库缺失却有旧锁或 `-wal/-shm/-journal` 伴随文件；
- 损坏、不兼容、来源不明或无法安全核实的数据库/路径；
- 同目录被另一实例持有，或上次卸载残留任务仍可能写入。

插件自身的源码、文档、配置与缓存不构成证据，不阻断打开；纯任意命名（无扩展名、
无状态标记、非 `.tmp-8hex`）的文件无法靠名字识别，属名字判定的固有边界，只能靠
人工核对发现。

保留原库、收据、伴随文件和归档原样；不要移动、清空、删除证据来制造新装，不用
另一空目录绕过防重。插件不自动回迁服务账本、不访问真实服务库或其他插件目录。
曾切换服务权威的安装须另行规划完整事实核对，本轮没有“忽略迁移”开关。

## 4. 开关、顺序和故障处置

业务默认值、候选标准、支持/拒绝材料和工具三参数见 [README](../README.md)。
开启普通文字/图片候选只增加源群自动评估机会，标准不是工具授权，不保证模型遵循。

每条源/评论各只有一次固定群发送动作。源先可靠回执并落账，评论非空才等待 0.5 秒；
实际写入前再次核对账号、连接与最新开关/白名单。空白评论不等待、不占位、不发送。

- `rejected/failed`：根据安全原因核对配置或材料；只有确认源未发的结果允许以后显式
  新调用，不自动重试。不存在切换动作、适配器 API、旧 HTTP 或宿主发送的备用路线。
- `unknown`：可能已发或源终态未落账，保留占位、人工核对；不能按通用错误码猜未发。
  源已取得真实 ID 但落账失败时，结果保留该 ID，`stage=source_persist`，不发评论。
- `partial`：源事实保留；评论未完成、未发或待核实，不重发源、不自动补评论。
- 评论等待中撤权或卸载，本次返回 `partial/comment_status=failed`，而账本评论字段
  仍为空；这是未提交评论，不表示其失败结果已持久记录。以后重复调用是
  `already_forwarded`，无新平台查询/发送，也不补评论。
- 已提交评论的终态落账失败，本次返回 `partial/comment_status=unknown`、
  `stage=comment_persist`，可保留已知真实评论 ID；账本评论仍在途，重开转未知。
  不能把已知回执说成评论结果可靠落账。
- `ledger_unavailable`：源发送前账本未就绪，停止并保留证据；评论占位失败则已存在源
  成功事实，整体为 `partial`，评论未知且阶段为 `comment_persist`，不会提交评论。

日志只含安全定位（源 ID、目标群、阶段、状态、原因），不包含正文、评论、凭证、
原资源或签名媒体地址。实际目标记录 ID、目标群、账号和正平台群序列齐全才认定成功；
自发事件、写入成功、动作受理或本地不透明 ID 不能代替回执。

## 5. 停止、备份与回滚

1. 关闭总开关，阻止新源/评论提交；卸载只管理本插件自己的任务、连接与账本。
   已提交动作仍可能有副作用，本地取消不表示远端撤回，不注销 QQ 账号。
2. 退出处理共用 5 秒预算。核对是否出现逐任务的“未退出/清理未完成/账本独占”告警。
   有残留写入风险时保持关闭，等确认真实退出再处置，不强行另起实例接管。
3. 在完全停写、独占已安全释放后，由获准操作者制作本插件状态的一致性备份，保留
   主库及必要伴随文件；复制进行中的 SQLite 文件不是一致性保证。备份放在本插件
   数据目录之外的受控位置，避免备份本身被识别为未知历史；不把凭证或正文混入备份。
4. 恢复先核对完整性及最新成功/未知事实，不能用较旧快照覆盖新投递后继续发送。
   目标版本必须能完整保留这些事实及评论未知阻断，否则继续关闭。
5. 回滚代码不等于授权恢复旧发送，不直接运行历史服务或迁移 CLI。真实账本核对、
   导出/回迁及回滚执行都须单独授权和方案；本轮没有提供自动工具。

目标群 QQ 客户端展示、原卡片可展开性和提醒行为由 [真实联验](real-qq-validation.md)
确认；目标群宿主消息记录与 Maisaka 历史始终不保证。冷目标不唤起，不补摘要或伪造入站，
历史缺失不能触发重发。
