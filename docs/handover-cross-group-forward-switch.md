## 0. 参与者与前置结论

| 项目 | 结论 |
| --- | --- |
| 旧复读插件 | 转发域必须已移除（无转发 Tool/Hook/配置），且其运行代码为删除转发后的版本 |
| 其他转发插件 | 部署环境里任何仍承担转发的旧插件（含历史遗留的独立转发插件）必须停用且无代码参与加载 |
| 新旧并存 | **禁止**新旧转发路径同时运行（用户已明确此口径） |
| 旧状态数据 | 不自动迁移、不自动删除、不由本插件读取 |
| 本插件 | 首次启用默认总开关关闭；白名单为空；启用前先配好源群与目标群两组白名单 |

## 1. 切换前置检查（全部满足才继续）

- [ ] **确认 MaiBot 与 SDK 版本**：Host ≥ 1.2.5、SDK ≥ 2.8.0（即 `_manifest.json`
      里 `host_application` / `sdk` 的 `min_version`）；版本不满足时插件会被拒绝加载。
      Host 下限取线上部署机容器自报 1.2.5（其宿主代码与参照 Host `a995cc4` 的能力名/
      Hook 行号逐一对齐，已据此核实，故不能声明更高下限）；SDK 下限 2.8.0，线上
      2.8.2 满足。
- [ ] **备份旧配置**：复制旧复读插件的 `config.toml` 及其历史备份，保留在当前部署机
      的独立备份目录（不动其原有 `config.toml.bak*`）。
- [ ] **备份旧状态**：枚举并备份旧插件 `data_dir` 下的**全部持久文件**（旧账本、
      去重/触发状态等，文件名以现场目录实际内容为准）到备份目录；只备份，不导入、
      不删除，也不假定存在某个固定文件名。
- [ ] **确认旧转发已下线**：旧复读插件不再注册任何转发 Tool/Hook，`[forward]` 配置段
      已不存在（旧字段不会重新启用功能）；重启后日志无转发域加载信息。
- [ ] **确认旧独立转发插件停用**：历史转发插件目录无可加载代码或被停用，插件列表
      加载日志中没有它；若仍有代码，先移除或禁用。
- [ ] **确认没有第三条转发路径**：判定方法——重启后在插件加载日志里逐项核对已加载
      插件，除本插件外不应有插件承担同类转发；随后一段时间内目标群每出现一条新转发
      消息，都应在**服务端账本**（`ledger status`）里找到对应记录（每次转发至多一条
      源记录 + 一条评论结果），有转发却无账本记录即说明存在本插件之外的转发路径。
- [ ] **准备白名单**：确定本插件要用的**源群**与**目标群**群号（与旧配置对照，去掉
      已失效的群），确认机器人在这些群可见、转发服务的 OneBot 连接与绑定账号可用，
      且这些群在服务端许可上限与客户端白名单的交集内。

## 2. 启用本插件

1. 把本目录放进 MaiBot 的 `plugins/`，插件 ID 为 `arcdent.maimai-courier-plugin`。
2. 重启 MaiBot（或热加载），确认日志出现「麦麦搬运喵已加载」且无转发服务绑定告警。
3. 先只填**测试群**白名单、**保持总开关关闭**，确认插件可正常加载：
   - `scope.source_groups` = 只含测试源群；
   - `scope.target_groups` = 只含测试目标群（且不同于源群）；
   - `plugin.enabled` 仍为 `false`。
4. 打开 `plugin.enabled = true`；按需保留或关闭 `auto.enabled`（自动入口只决定是否给
   源群一次自主判断机会，不影响工具调用）。**此时不要填入生产源群**：自动入口开关
   默认开启，源群一旦在名单内，该群新到的合并转发（默认唯一的候选类型）会立即获得
   一次源群 Maisaka 的自主判断机会（**这只是判断机会，不等于发送**）；若在配置中
   加选普通文字或图片，这两类消息同样会立即纳入自动判断范围并增加模型调用量。
5. 按第 4 节的联验清单在测试群验证通过后，再补齐其余源群与目标群白名单（新增源群
   同样会立即纳入自动判断范围）。

## 3. 数据边界（必须向使用者说明）

- **旧状态不自动导入**：旧的转发账本不会被本插件读取或自动转换（不改、不删）。
  本版本的**全部发送由独立转发服务执行**，防重事实以**服务端账本**为准；从旧版本
  升级时必须先用 `ledger migrate` 显式迁移旧账本（不迁移则旧的成功/待核实记录失去
  防重作用，可能重复转发一次）。迁移、备份与回滚步骤见
  [服务运维清单](service-operations.md)。
- **迁移前旧历史不保证被识别**：旧插件历史成功转发过的「源消息 → 目标群」，在迁移
  完成前新服务没有记录，仍可能再次转发一次；切换前用旧记录核对一遍近期已转发内容，
  必要时先与群管理确认。
- **旧数据不删除**：旧账本留在部署机上由部署者按需处理（删除属不可逆操作，需单独
  确认后再做）；本插件与服务都不触碰任何其他插件的文件。
- **服务端账本备份**：停止服务后整目录复制服务状态目录（`service_ledger.sqlite3`
  与伴随的锁文件）；不要在服务运行中复制。口径见 README 的
  《防重、迁移与备份》一节与[服务运维清单](service-operations.md)；不要手工删改
  记录（删除成功记录会失去防重保护）。
- **单实例**：一个数据目录只给一个 MaiBot 实例使用；服务端状态目录也只给一个服务
  进程使用。
- **升级不扩大自动范围**：升级到含候选类型与自动分享标准的版本时，旧配置缺少的
  新字段由默认补齐（自动候选仍仅合并转发），既有开关、白名单与投递账本**不被
  覆盖、不迁移、不删除**；只有在配置页显式加选普通文字或图片才会扩大自动判断
  范围，标准留空或全空白时回退默认标准。
- **回滚本插件旧版**：恢复到不支持提及转换的旧版本后，含个人／全体成员提及的源
  消息会**再次被整条拒绝**（旧版没有该例外），切换到旧版前需向使用者说明；账本
  同样保留，不迁移也不删除。

## 5. 回滚清单

1. **先停本插件与转发服务**：关闭 `plugin.enabled`（或卸载/移除插件目录），并停止
   转发服务进程。判定「不再有新的转发」的观察点：卸载日志出现本插件退出记录
   （在途任务超时的告警见下一条）；此后服务端账本不再新增记录；如需更直接的确认，
   可在源群再发一条合并转发，目标群与账本都不得出现任何新增。
2. **保留账本**：不要删除插件 `data_dir` 里的旧账本归档，也不要删除或改写服务端
   状态目录里的服务账本（保留已投递事实与待核实记录，供后续核对）；停机备份口径见
   [服务运维清单](service-operations.md)。
3. **确认无在途**：等待在途投递结束（插件卸载会取消并等待本插件自己的后台任务，
   上限 5 秒；超出会有告警，说明在途远端调用可能仍完成；服务端退出也会把遗留占位
   保守归并为待核实）。
4. **恢复旧实现（如需）**：先按[服务运维清单](service-operations.md)第 5 节做兼容
   导出并验证全部成功/待核实键仍阻断；无法安全导出时**保持关闭**，不得直接启用只含
   迁移前历史的旧库。随后只读对照旧项目该变更的归档材料
   （`repeat-plugin/openspec/changes/archive/2026-09-29-remove-cross-group-forward/`；
   tasks 6.3 即旧项目自己的「切换与回滚交接」任务，其回滚步骤以旧项目自身材料为准），
   据此确认要恢复的旧版本应包含哪些内容，再从旧项目仓库的版本历史取回**删除转发
   之前**的代码与配置。**同一时间只能有一套转发路径**——本插件与服务都已停用并确认
   无发送后，才可以恢复旧转发。回滚到本插件不支持提及转换的旧版本后，含个人／全体
   成员提及的普通消息会再次被整条拒绝，需提前向使用者说明。
5. **核对未知记录**：若服务端账本里留有 `unknown`（待核实）记录，先核对目标群实际
   消息，再决定是否保留现状或按运维流程处理；两端都不提供删除或改写账本记录的接口。
