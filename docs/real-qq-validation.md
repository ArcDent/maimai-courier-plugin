# 真实 QQ 联验清单（未授权、未执行）

本清单适用于插件进程内客户端经单一 HTTP API 端点直连已有 SnowLuma 服务端（无长连接）。
**截至 2026-10-05，下列人工项及服务端契约未确认项全部未执行/未确认**。离线模拟、公开
SDK 源码、部署目录、旧变更归档或授权实测快照（ADR 0008）都不能代替真实运行证据。执行
须另行取得部署、账号、读取范围和发群授权；不自动部署、不读取真实凭证、不在仓库记录真实
群号、正文、媒体地址或凭证值。

原独立服务阶段的 [完整清单原件](../history/snowluma-forward-service/docs/real-qq-validation.md)
保留为历史；其中 HTTP、服务身份、`ledger status` 等不属于当前运行路径。

## 0. 授权与实际运行前置

- [ ] P1：取得明确授权，约定测试源群/目标群、材料、可产生的消息数量与故障演练范围。
- [ ] P2：保持总开关关闭，确认只有本插件的直连路径可发送；旧服务/适配器 API/宿主
  fallback 均未启用，不同时运行两种版本来比较效果。
- [ ] P3：确认实际加载的 Host/SDK/插件/适配器及 SnowLuma 版本与证据来源。
  本插件声明 SDK 2.8.0–2.99.99；公开 2.8.0 接口核对不证明线上已加载，宿主锁文件
  2.5.2 也不证明线上实际版本。若实际低于下限则停止，不能以静态包或部署目录放行。
- [ ] P4：核对受控 `snowluma.http_url`、仅存变量名的 `token_env_var` 与插件进程
  环境注入；凭证值不落盘、不回显、不来自其他插件文件。明文 `http` 只允许回环、私有或
  链路本地目标（主机名在请求发出前解析确认，解析出公网或失败即拒绝），公网必须可验证
  证书的 `https`，不以容器 `localhost` 误指宿主，不复制截图端口作默认。HTTP 端点
  （默认 3000）与 ws 端点（3001）可能各自持 Token，按部署对应填写；请求禁跟随重定向，
  超 2MiB 的请求体由客户端在发出前拒绝（服务端精确阈值见 F10）。
- [ ] P5：核对本插件账本为完整唯一权威且独占，成功/未知历史未丢失；出现服务收据、
  归档、孤留伴随文件或历史不明时停止，保留原件并另行规划核对，不能新建空库绕过。
- [ ] P6：核对可信宿主账号与端点实际账号一致、源消息确实经过已核实入站链、来源群与
  目标属于同一转发分组且不同群；未知映射拒绝，模型补填不作为证据。

## 1. 服务端门槛 U1–U8（U1 已在授权实测实例确认，其余未确认）

部署形态。以下每项记录授权来源、实际版本、操作、观察及结论；失败涉及范围/安全/
可行性时回到规划，不在联验现场换字段、动作或成功口径。

- [ ] U1：~~实际路径、仅 Bearer 头认证、Token 校验、动作权限和 TLS~~ **实测实例已
  确认**（2026-10-04，SnowLuma 1.14.17-node：Bearer 头被接受、失败 401、未见
  URL 凭证通道被本插件使用）。**本项剩余工作=本部署复验**：当前部署的实际路径、
  Token 校验与 TLS（若公网 https）、以及 3000/3001 是否各自持 Token。失败不加 URL

- [ ] U2：Universal 事件广播、自发上报、echo 原样回显、多客户端响应归属及限帧/空闲
  行为。即使响应广播也须互不串回执；截图客户端计数不是此项证明。（HTTP 直连不建立
  长连接，事件广播/echo/响应归属不再是本路径的风险面；服务端限帧对应请求体上限，
  见 F10。）
- [ ] U3：`get_login_info`、`get_group_list`、同账号 `get_msg` 的身份和缓存范围；返回
  源记录 ID/类型/群归属完整，未知/错群/错账号在无发送副作用的准备阶段拒绝。
- [ ] U4：三类固定发送动作分派——卡片 `get_forward_msg` 按源消息卡片标识展开查询后
  `send_group_forward_msg` 节点重组一步投递（平台按目标群上下文重建并重新上传卡片内
  媒体）、文字 `send_forward_msg` 单节点卡片（节点署源发送者身份、内容段原样）、图片
  `send_msg` 群分支段直发；结构化 `text` 不执行 CQ 语法。失败不换动作、不退回
  `send_msg` 直引旧 res_id、摘要或备用通道。
  **已实测事实（2026-10-05，arclinux，catalog 6.5/6.6）**：同一跨群含图卡片上卡片
  投递路径结果分化——按源消息标识重建的旧通道业务失败 400；`send_msg` 直引旧 res_id
  是**假成功**（信封 ok、四项回执全过、群内展示降级空壳）；`send_group_forward_msg`
  投递 `get_forward_msg` 展开节点（sender 拍平、平台按目标群上下文重传图片）内容
  完整。**展开重组路径已实测可用（2026-10-05，arclinux）；嵌套内层卡片已改为发送前
  整条拒绝（2026-10-06 实测三种形态均不可用，见 U6）。** 回执四项核验不能发现
  「内容降级」，路径选择不得以信封
  ok 为准。**补充（2026-10-06，catalog 6.8）**：上表「sender 拍平」通道经对照实测
  证明节点发送者字段 `sender` 被平台静默丢弃、uin 回退 bot 自身（目标群显示 bot
  署名）；已改为 `uin`（`user_id` 亦可用）并经回查逐节点证实保留原发送者。原发送者
  头像由客户端按 uin 渲染，目标群目视确认未执行。
- [ ] U5：HTTPS `image.data.url` 的单图/多图/图文重放；网关在 DNS 解析和重定向之后
  仍拒绝内网、文件及非法资源。这是允许真实图片流量的安全前提，不能先发后用 unknown
  补救，也不能把全部拒图说成已支持图片。前提不能确认则停止。
  **已实测事实（2026-10-05，catalog 6.5）**：`send_msg` 图片段传公链 https 可被
  平台下载转为 QQ 资源（回执为多媒体 CDN 地址）；但旧「按源消息标识重建」的卡片
  通道转发跨群转来的含图卡片会因平台下载卡片内图片签名 URL 失败而返回
  `retcode=100 "HTTP download failed: 400"`，距卡片创建约 25 分钟即可发生；现行
  展开重组路径由平台按目标群上下文重新上传卡片内图片，不经该签名 URL 下载
  （catalog 6.6）。卡片内图片的精确时效窗口与可重发条件未测定。
- [ ] U6：原资源跨群可用性/有效期、卡片展开、内部回复/提及/媒体、嵌套内层展示、
  外层预览差异及提醒行为。不能承诺卡片内提及绝不提醒或外层逐字相同。
  **已实测事实（2026-10-05，arclinux，catalog 6.5/6.6）**：①旧「按标识重建」通道下
  跨群含图卡片的内部图片签名 URL 在平台侧下载 400 失败（纯文本卡片不受影响）；
  ②`send_msg` 直引旧 res_id 会发出空壳卡片（假成功，回执核验无法识别）；
  ③`send_group_forward_msg` 投递 `get_forward_msg` 展开节点的节点重传路径可完整重建
  该卡片，**展开重组路径已实测可用（2026-10-05，arclinux）**。
  **已实测事实（2026-10-06，arclinux，catalog 6.9）**：嵌套内层三种投递形态均不能
  保留内层信息——旧 res_id 原样提交与 `upload_forward_msg` 重传取新 res_id 在目标群
  客户端均显示为降级空壳，递归拍平结构丢失、内层 reply 显示「[原消息已过期]」；新旧
  两种引用都能被 `get_forward_msg` 正常展开，降级发生在客户端渲染层、**与所引用资源
  的新旧无关**。契约已据此改为**发送前整条拒绝**（固定措辞「源卡片包含嵌套聊天记录，
  无法完整转发，不建议继续尝试」，`type_check` 单点判定），本部署剩余复验为该拒绝在
  真实链路上生效且传输层零请求。自动入口的只读预识别行为：仅合并转发候选，在可读性
  确认与配置初检之后、目标名称查询之前做 `get_msg`+`get_forward_msg` 两步只读查询，
  命中不提供判断机会并记录可定位原因；查询失败、取不到平台卡片标识或结果不可判定时
  放行（fail-open，不阻断自动判断，能否发送仍由工具路径在发送前权威决定）。
  **仍未联验**：外层预览差异与卡片内 at 提醒行为归本项，须本部署授权后实测再定承诺；
  上述均为单实例快照，不等于全量联验完成。
- [ ] U7：动作候选 ID 与 `get_msg` 返回的同 ID、目标群、发送账号、正整数 `message_seq`
  的含义，确认群序列是真实 QQ 平台证据而不是本地受理记录。
- [ ] U8：平台发送与缓存登记的实际顺序、发送后登记异常/失败返回可能已有副作用。
  无充分证据时保持未知，不按通用错误码、文本或本地取消推断未发。

资源获取安全等前置项须在相应真实流量前确认。需真实消息才能确认的项，只在明确授权

## 3. 故障、隔离与恢复（全部未执行，需专门授权）

- [ ] F1：发送前不可达/认证失败/错账号/源群错误（含来源群不在任何转发分组或目标不与
  来源群同组），零源与评论；安全拒绝，不泄露正文。
- [ ] F2：发送帧可能已写出后断线、无回执或错目标记录，保持 unknown，源未知不发评论；
  重连后不重放、不换动作，同键再调用仍阻断。
- [ ] F3：同键成功后重载/重连、更换评论再调用，`already_forwarded` 且无新源/评论；
  对另一允许目标的调用独立判断。
- [ ] F4：源/评论发送前后存储故障，只能在获准的可控环境演练，不人为损坏生产账本。
  占位失败不提交对应阶段；真实 ID 已取得但结果未落盘时如实保留 ID 和持久性限制。
- [ ] F5：评论等待中关闭、撤权或卸载，源成功保留，本次 `partial/comment_status=failed`；
  未提交评论的账本字段仍空，并未记录本次失败，后续重复调用不补评论。
- [ ] F6：评论已提交但终态落盘失败，`partial/comment_status=unknown/stage=comment_persist`，
  保留已知真实评论 ID，不称可靠落账；重开仅评论归未知、源仍 sent。
- [ ] F7：实际写入前的排队/账号查询等待中撤权或切换地址/凭证引用，旧阶段不提交；
  已开始写入的结果按真实证据/未知，不假称撤回。
- [ ] F8：插件连接与现有客户端并存，事件/响应不串投递；卸载只关闭本插件连接，其他
  客户端仍能工作，不注销 QQ 账号。超出共享 5 秒预算时逐项告警，不释放有风险的账本。
- [ ] F9：本插件服务历史痕迹闭锁、同目录双实例拒绝、完整旧库成功/未知阻断，均先用
  合成数据；真实状态处置须另行核对授权，不能将合成通过写成真实迁移完成。
- [ ] F10：服务端请求体精确上限阈值：以受控递增体积确认服务端真实断连点（实测 100KB
  与 1MB/2MB 抵达业务层、3MB 起直接关闭连接且无结构化错误码，实际上限约 2–3MB），
  核对客户端 2MiB 前置拒绝是否留有余量、超限是否按可定位的明确未发送报告
  （未验证，归 U7：发送动作回执前提）。
