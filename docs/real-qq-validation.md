- [ ] P3：确认实际加载的 Host/SDK/插件/适配器及 SnowLuma 版本与证据来源。

  2.5.2 也不证明线上实际版本。若实际低于下限则停止，不能以静态包或部署目录放行。
- [ ] P4：核对受控 `snowluma.websocket_url`、仅存变量名的 `token_env_var` 与插件进程
  环境注入；凭证值不落盘、不回显、不来自其他插件文件。明文 `ws` 只允许回环、私有或

  证书的 `wss`，不以容器 `localhost` 误指宿主，不复制截图端口作默认。
- [ ] P5：核对本插件账本为完整唯一权威且独占，成功/未知历史未丢失；出现服务收据、
  归档、孤留伴随文件或历史不明时停止，保留原件并另行规划核对，不能新建空库绕过。
- [ ] P6：核对可信宿主账号与端点实际账号一致、源消息确实经过已核实入站链、来源群

## 1. 服务端门槛 U1–U8（均未确认）

详细证据强度与替代来源见归档的 [待确认清单](../openspec/changes/archive/2026-10-04-direct-snowluma-websocket-forwarding/verification/unverified-server-contracts.md)。
以下每项记录授权来源、实际版本、操作、观察及结论；失败涉及范围/安全/可行性时回到
规划，不在联验现场换字段、动作或成功口径。

- [ ] U1：实际路径、仅 Bearer 头认证、Token 校验、动作权限和 TLS。失败不加 URL token、
  不跟随重定向、不换端点探测；当前仅头是否可用尚未确认。
- [ ] U2：Universal 事件广播、自发上报、echo 原样回显、多客户端响应归属及限帧/空闲
  行为。即使响应广播也须互不串回执；截图客户端计数不是此项证明。
- [ ] U3：`get_login_info`、`get_group_list`、同账号 `get_msg` 的身份和缓存范围；返回
  源记录 ID/类型/群归属完整，未知/错群/错账号在无发送副作用的准备阶段拒绝。
- [ ] U4：唯一 `send_msg` 群分支、结构化 `text` 不执行 CQ 语法、`forward.data.id`
  复用原资源。失败不换为其他动作、节点上传、摘要或备用通道。
- [ ] U5：HTTPS `image.data.url` 的单图/多图/图文重放；网关在 DNS 解析和重定向之后
  仍拒绝内网、文件及非法资源。这是允许真实图片流量的安全前提，不能先发后用 unknown
  补救，也不能把全部拒图说成已支持图片。前提不能确认则停止。
- [ ] U6：原资源跨群可用性/有效期、卡片展开、内部回复/提及/媒体、外层预览差异及
  提醒行为。不能承诺卡片内提及绝不提醒或外层逐字相同。
- [ ] U7：动作候选 ID 与 `get_msg` 返回的同 ID、目标群、发送账号、正整数 `message_seq`
  的含义，确认群序列是真实 QQ 平台证据而不是本地受理记录。
- [ ] U8：平台发送与缓存登记的实际顺序、发送后登记异常/失败返回可能已有副作用。
  无充分证据时保持未知，不按通用错误码、文本或本地取消推断未发。

资源获取安全等前置项须在相应真实流量前确认。需真实消息才能确认的项，只在明确授权
的最小测试范围内进行；全部确认前不宣称可正式启用。

## 2. 材料与正常链（全部未执行）

每项分开记录：工具结果、独占账本事实、QQ 客户端展示。宿主目标历史只作观察，
不作为成功或失败判定，不补写历史。非空 ID 或 `success` 单一字段不能替代平台证据。

- [ ] V1：多段纯文字与原换行，一次源发送，目标正确，真实 ID 落账。
- [ ] V2：单图可打开且不是描述，安全媒体前提已确认。
- [ ] V3：多图（例如三张）保持顺序和内容，没有丢图或拆消息。
- [ ] V4：图文混排保持完整段序。
- [ ] V5：普通文字中的有名个人提及与全体提及转为 `［提及：…］` 文本，目标无顶层 @ 提醒。
- [ ] V6：图片与无名/名片形态个人提及，保留对象标识、不虚构名称、不查询目标成员补齐。
- [ ] V7：原卡片包含回复、个人/全体提及、图片、嵌套及未知段，整张引用可展开，不重建节点。
  内部提醒和外层预览差异单独记录，不作未经验证的绝对保证。
- [ ] V8：宿主未展开的卡片按可信原资源发送；现场无法构造则记“未覆盖”。
- [ ] V9：顶层卡片混文字/图片/提及及多卡片整条拒绝，无发送。
- [ ] V10：普通语音/文件/视频/回复等不支持段整条拒绝，原卡片内部不套用此规则。
- [ ] V11：缺媒体图片、缺资源/缓存卡片拒绝；无法构造则记“未覆盖”，不用合成结果代替。
- [ ] C1：评论缺省、空、全空白分别只发源，不等待、不占位评论。
- [ ] C2：非空评论（含 CQ/命令式文本）只在源成功且落账后至少 0.5 秒另发，一条普通文本，
  评论提交前账本占位，真实评论 ID 落账。
- [ ] C3：合理较长评论完整作为普通文本发送，不被当指令或塞进卡片节点。
- [ ] A1：源群候选重复上报仅一次 Planner 机会；沉默零发送；明确调用才走同一工具与账本。
  普通文字/图片仅显式选中类型才自动判断，关闭自动入口不阻止合法工具。
- [ ] A2：目标群无活动 Maisaka 时仍按合法平台目标执行，不创建/唤起目标 Planner。

## 3. 故障、隔离与恢复（全部未执行，需专门授权）

- [ ] F1：发送前不可达/认证失败/错账号/源群错误，零源与评论；安全拒绝，不泄露正文。
- [ ] F2：发送帧可能已写出后断线、无回执或错目标记录，保持 unknown，源未知不发评论；
  重连后不重放、不换动作，同键再调用仍阻断。
- [ ] F3：同键成功后重载/重连、更换评论再调用，`already_forwarded` 且无新源/评论；
  对另一允许目标的调用独立判断。
- [ ] F4：源/评论发送前后存储故障，只能在获准的可控环境演练，不人为损坏生产账本。
  占位失败不提交对应阶段；真实 ID 已取得但结果未落盘时如实保留 ID 和持久性限制。
- [ ] F5：评论等待中关闭、撤权或卸载，源成功保留，本次 `partial/comment_status=failed`；
  未提交评论的账本字段仍空，并未记录本次失败，后续重复调用不补评论。
- [ ] F6：评论已提交但终态落盘失败，`partial/comment_status=unknown/stage=comment_persist`，
  保留已知真实评论 ID，不称可靠落账；重开仅评论归未知、源仍 sent。
- [ ] F7：实际写入前的排队/账号查询等待中撤权或切换地址/凭证引用，旧阶段不提交；
  已开始写入的结果按真实证据/未知，不假称撤回。
- [ ] F8：插件连接与现有客户端并存，事件/响应不串投递；卸载只关闭本插件连接，其他
  客户端仍能工作，不注销 QQ 账号。超出共享 5 秒预算时逐项告警，不释放有风险的账本。
- [ ] F9：本插件服务历史痕迹闭锁、同目录双实例拒绝、完整旧库成功/未知阻断，均先用
  合成数据；真实状态处置须另行核对授权，不能将合成通过写成真实迁移完成。
