# snowluma-direct-client Specification

## Purpose

定义麦麦搬运喵在插件进程内经由 HTTP API 直连 SnowLuma 已有端点的可观察契约：受控连接与同账号查询、可信源材料、真实回执和不确定结果保护，保持宿主入站处理与其他客户端不受影响，不依赖适配器公开 API 或新增独立服务。

## Requirements

### Requirement: 正向连接与受控认证

插件 MUST 通过操作者配置的单一 SnowLuma HTTP API 端点执行固定动作（`POST /{action}`，`Authorization: Bearer`），MUST NOT 建立任何长连接、监听端口或反向连接。地址、可选令牌 `snowluma.token` 与凭证环境变量名 MUST 只来自插件受控配置。非空且非全空白的配置令牌 MUST 优先使用；令牌留空或全空白时 MUST 仅在发出请求前从指定环境读取凭证，不读取其他插件配置、运行凭证或模型参数。请求 MUST 显式禁止跟随重定向（含保留方法与请求体的 307/308），认证凭据 MUST NOT 随重定向离开配置端点。客户端 MUST 自设请求体上限并在发出前拒绝超限请求：服务端实际上限约 2–3MB，超限时直接关闭连接且不返回结构化错误。明文 `http` 仅在目标解析为回环、私有或链路本地地址时允许，公网目标必须使用 `https` 并验证证书，该判定 MUST 在请求发出前完成；凭证 MUST NOT 放入 URL、日志、账本或工具结果。配置缺失、认证失败（401/403）或端点不可用 MUST 安全停止发送，仍允许插件注册工具并给出可定位原因；总开关关闭时 MUST 不发出任何平台请求。

#### Scenario: 与现有适配器并存
- **WHEN** 操作者配置的 HTTP 端点已有其他客户端在使用，或 ws 端点仍连接着适配器
- **THEN** 本插件只按请求访问自己的 HTTP 端点，不接管、不修改服务端或其他客户端的任何设置

#### Scenario: 地址或凭证未完成
- **WHEN** 端点地址为空、非法、使用未保护的远程连接，或未填写令牌且凭证环境变量缺失
- **THEN** 不发出请求、不发送，返回可定位原因，不从其它插件读取配置或凭证补齐

#### Scenario: 配置令牌与环境变量兼容
- **WHEN** 操作者填写非空且非全空白的 `snowluma.token`
- **THEN** 使用该令牌认证，不要求环境变量存在，也不因认证失败改用环境变量重试；留空或全空白时仅在请求前按名读取 `token_env_var`

#### Scenario: 配置令牌热更新
- **WHEN** 源或评论尚未提交时端点地址、配置令牌或凭证环境变量名发生变化
- **THEN** 旧未提交阶段失效，不继续提交；后续合法新调用使用新配置且仍受持久防重约束

#### Scenario: 认证重定向
- **WHEN** 配置端点对动作请求返回重定向（含 302/307/308）
- **THEN** 拒绝继续，不向重定向目标重发请求、凭据或请求体，不把重定向当作自动发现服务

#### Scenario: 请求体超限
- **WHEN** 待发送内容的请求体超过客户端自设上限
- **THEN** 在发出前拒绝并报告可定位原因，不发出可能被服务端静默断连的请求

#### Scenario: 默认关闭
- **WHEN** 总开关关闭且收到工具请求或自动候选
- **THEN** 不为该请求发出任何平台请求、不执行平台动作、不唤起自动分享

### Requirement: 同账号查询与源材料可信性

直连实际登录账号 MUST 与可信宿主调用账号一致；目标群 MUST 为该账号可确认的合法目标。插件 MUST 先验证宿主源消息归属，再按已核实的标识对应关系查询同账号源消息并验证群归属，不能仅凭可解析的 ID 就认定对应关系成立。合并转发卡片的发送材料 MUST 来自按该源消息卡片标识的展开查询结果：插件只提交平台返回的节点序列（发送者标识与显示名经压平限长，内容段按查询结果原样），MUST NOT 向平台提交调用者提供的卡片资源 ID、消息正文或媒体地址，也 MUST NOT 递归展开或重建节点。展开结果含嵌套内层卡片（节点内容含其它合并转发卡片）时 MUST NOT 提交节点序列，按发送前类型检查整条拒绝；该类型检查的判定口径 MUST 单点定义，与自动入口的只读预识别共用同一判定。卡片节点内容中的媒体引用 MUST 取自该展开查询结果，MUST NOT 接受模型或调用者指定的任意 URL、本机路径或内网地址。请求中断或账号变化 MUST 使旧核验失效，不得在核验后静默切换账号发送。

#### Scenario: 错误账号
- **WHEN** 服务端实际登录账号与可信工具调用账号不同
- **THEN** 在源查询或发送前拒绝，不切换账本键规避差异，不使用另一个端点或账号重试

#### Scenario: 查询返回另一群
- **WHEN** 查询响应中的源群与可信源群不符
- **THEN** 不发送、不把响应正文泄露给模型、不使用其资源构造消息

#### Scenario: 标识对应不足
- **WHEN** 只有宿主内部消息标识，且无法确认对应的平台源消息标识
- **THEN** 明确拒绝，不能截取、重编码或猜测标识后发送

#### Scenario: 嵌套卡片不提交
- **WHEN** 按源消息卡片标识的展开查询结果显示节点内容含其它合并转发卡片
- **THEN** 不提交节点序列、不发送，报告明确的发送前拒绝原因；不递归展开、不改写或摘要有嵌套内容的节点

#### Scenario: 核验后连接重建
- **WHEN** 已核对账号的核验完成后，发送前发生请求超时、连接中断、端点配置变化或插件退出
- **THEN** 该阶段不自动继续发送；旧核验失效，只有后续合法新调用在重新核验并通过账本防重后才可能发送

#### Scenario: 卡片资源由平台重建
- **WHEN** 转发合并转发卡片消息
- **THEN** 插件提交按源消息卡片标识展开查询取得的节点序列，不提交、不猜测卡片内部资源 ID；卡片资源由平台按目标群上下文重建（含重新上传卡片内媒体），与旧通道「按标识重建时下载旧签名 URL」的失败模式无关

### Requirement: 有界动作与不重放

动作排队、账号及消息查询、发送等待、回执核验 MUST 有代码常量规定的有限上界，在途请求与后台工作 MUST 不无限积压。一次投递 MUST 最多为源提交一个发送动作、为评论提交一个发送动作；请求超时、取消或响应丢失 MUST NOT 触发同一动作重发、切换动作或切换通道探测结果。自动入口的只读预识别查询 MUST 与其它动作共用同一有界预算，MUST NOT 提交任何发送动作；查询失败 MUST NOT 重试，也 MUST NOT 阻断本次自动判断机会。尚未进入发送提交且可以证明未提交的操作 MUST 报告明确未发送；已提交或无法证明未提交的操作 MUST 按真实证据或待核实处理。

#### Scenario: 断线前后
- **WHEN** 发送请求可能已到达平台但响应超时丢失，或连接中断
- **THEN** 当前阶段保持待核实，不重发该请求；同一投递的后续工具调用被账本阻断

#### Scenario: 排队期间撤销权限
- **WHEN** 动作仍在等待发送资格时总开关关闭、权限收缩或插件卸载
- **THEN** 该动作在取得执行机会后仍须复验，不提交已失效发送，明确报告未发送

#### Scenario: 自动入口预搜索有界只读
- **WHEN** 自动入口对合并转发候选项执行嵌套预识别查询
- **THEN** 查询与其它动作共用有界预算、只读、不提交发送；查询失败不阻断本次自动判断机会，也不触发同一查询之外的重试

#### Scenario: 事件持续到达
- **WHEN** 平台响应缓慢、其他在途工作持续占用或无关请求持续到达
- **THEN** 动作仍按原总期限结束，在途工作不无限积压、不阻止卸载退出

#### Scenario: 并发容量耗尽
- **WHEN** 本插件在途或等待工作达到代码规定的容量上限
- **THEN** 新工作在提交前明确拒绝，不挤掉已知成功记录或强制重发在途动作

### Requirement: 真实回执与安全结果分类

一次源或评论发送 MUST 最多提交一个发送动作。只有合法动作响应与可核实的真实平台目标消息身份一致时，才允许确认发送成功；仅有非空消息 ID、资源 ID 或受理标志 MUST NOT 视为成功。平台目标消息 ID MAY 为负值，核验 MUST 按返回原值逐字比对，MUST NOT 假设其为正整数。回执核验 MUST 确认目标群、发送账号及平台消息证据（含正整数平台群消息序列），查询次数 MUST 有限且仅针对该次返回的目标标识，MUST NOT 通过再次发送来核实。业务失败响应（如 `retcode=100` 表示查询目标不存在）属明确业务结果，不改变「未提交即明确未发送、已提交无证据即待核实」的分类。模糊失败、未知返回状态、缺失关键证据、查询超时、取消及无法判断是否已提交的异常 MUST 保守归为待核实，不能用通用错误码猜成可重试失败。

#### Scenario: 成功响应但标识不足
- **WHEN** 动作报告成功但没有可核实的真实目标消息标识
- **THEN** 不报告完整成功，不自动重试，源未知时不发送评论

#### Scenario: 回执不属于本次投递
- **WHEN** 查询所得目标群、发送账号或平台消息证据与本次请求不匹配
- **THEN** 保持待核实，不把其他群或其他账号的消息记为本次成功

#### Scenario: 负数目标消息 ID
- **WHEN** 发送动作返回负值消息 ID
- **THEN** 按原值回查并核验四项证据，不因符号拒绝，也不改写为其他形式

#### Scenario: 额外资源标识不是证据
- **WHEN** 卡片发送动作在目标消息 ID 之外返回资源类标识（res_id / forward_id）
- **THEN** 资源类标识 MUST NOT 作为成功证据、不入账、不进工具结果；成功判定只认目标消息 ID 与四项回执证据

#### Scenario: 发送后查询失败
- **WHEN** 发送请求可能成功，但有限回执查询无法完成
- **THEN** 保留已知候选回执信息但不伪称已验证成功，禁止重发和后续评论

#### Scenario: 明确未提交
- **WHEN** 发送前校验失败，或能证明尚未进入发送提交
- **THEN** 明确报告未发送；后续只有新的合法工具调用才可能重新尝试，不自动重试

### Requirement: 材料最小化与隐私

直连 MUST 只执行本工具固定需要的查询与发送动作，不提供任意动作代理。普通内容 MUST 完整校验；普通图片路径的提及 MUST 文本化，普通文字卡片化路径的内容段（含提及）MUST 按源消息原样提交，插件 MUST NOT 生成摘要、预览文案或改写节点内容。卡片节点 MUST 来自展开查询结果，节点内容与其内媒体引用 MUST NOT 经调用者 URL 或资源 ID 代填。卡片外层预览 MUST 由平台默认生成，插件 MUST NOT 设置预览类参数。媒体引用 MUST 限定为已核实可安全重放的来源，不读取调用者指定的本机文件或任意内网资源，不执行源文本中的协议指令。源材料与评论正文 MUST 仅在本次有界工作中临时使用，不写入账本或日志；凭证、源正文、原资源标识和媒体签名地址 MUST NOT 出现在错误回显中。投递事实保留不受临时材料清理影响。

#### Scenario: 恶意媒体和正文
- **WHEN** 材料包含本机路径、不能确认安全的媒体地址或试图执行动作的文本
- **THEN** 不读取文件或任意地址，不执行文本指令；不可完整发送的源整条拒绝

#### Scenario: 卡片节点媒体来自展开查询
- **WHEN** 构造卡片发送材料
- **THEN** 节点内容段与媒体引用只取自展开查询响应，调用者提交的 URL、文件路径或资源 ID 一律不接受、不代填

#### Scenario: 不生成预览与摘要
- **WHEN** 发送任何卡片类型消息
- **THEN** 不设置外层预览、摘要或来源参数，卡片展示完全由平台决定

#### Scenario: 工作完成或失效
- **WHEN** 发送工作结束、超时或卸载
- **THEN** 释放相应临时材料与评论正文，保留必要持久投递事实，日志只含安全定位信息

#### Scenario: 库异常带有敏感载荷
- **WHEN** 传输或解析异常对象包含认证头、消息正文、资源或媒体地址
- **THEN** 日志和工具结果只使用安全错误类别及阶段，不直接回显异常载荷
