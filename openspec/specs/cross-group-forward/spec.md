# cross-group-forward Specification

## Purpose

定义麦麦搬运喵独立插件的跨群分享契约：源群 Maisaka 自主判断合并转发是否值得分享，通过同一个受白名单约束的工具转发指定消息并可附带延迟评论，实际发送自然进入主程序聊天记录与上下文，跨重启避免重复投递。

## Requirements

### Requirement: 独立插件与路径开关

插件 MUST 独立安装、加载和运行，不依赖复读插件。总开关关闭时 MUST 停止自动判断和工具发送；自动入口开关 MUST 只控制合并转发的自动判断机会，不影响总开关开启时显式调用工具。默认 MUST 关闭插件并使用空白名单，避免安装即跨群发送。

#### Scenario: 单独安装
- **WHEN** 环境未安装复读插件且已满足声明的主程序依赖
- **THEN** 本插件能够独立加载与注册工具

#### Scenario: 仅关闭自动入口
- **WHEN** 插件总开关开启且自动入口关闭
- **THEN** 收到合并转发不主动唤起判断，合法工具调用仍可发送

### Requirement: 自动入口由源群决定

白名单源群收到非机器人自身、非通知的 QQ 合并转发后，插件 MUST 在消息完成处理并可供源群读取后，给予源群 Maisaka 一次主动判断机会；重复上报 MUST 被抑制。源消息 MUST 正常进入主处理链，不拦截。Maisaka MUST 能选择不转发，或选择允许的目标群调用转发工具；插件 MUST NOT 掷骰、签发目标群决策票或强制目标群评论。普通文字和图片 MUST NOT 单独触发此自动入口。未展开的合并转发可供判断，但实际发送仍须满足完整内容校验。

#### Scenario: 自主分享
- **WHEN** 合法源群的一条合并转发处理完成且未触发过自动判断
- **THEN** 源群 Maisaka 获得该消息 ID 和合法目标信息，可通过工具分享或保持沉默

#### Scenario: 重复上报与自身消息
- **WHEN** 同一候选重复上报，或消息来自机器人自身
- **THEN** 不产生额外自动判断机会，不形成自动转发循环

#### Scenario: 普通消息
- **WHEN** 源群收到普通文字或图片
- **THEN** 不由自动入口唤起分享，仍可由合法工具调用转发

#### Scenario: 消息未就绪
- **WHEN** 候选消息在有限等待期内仍不可读取
- **THEN** 本次不触发分享，记录可定位原因，不无限等待或伪造摘要

### Requirement: 三参数群聊工具与可信权限

插件 MUST 向群聊 Maisaka 暴露 `forward_message`，公开参数仅为必填字符串 `message_id`、必填字符串 `target_group_id` 和可选字符串 `comment`（默认空）。调用上下文 MUST 来自可信宿主，不信任模型伪造的平台、源群、会话或内部授权参数。源群 MUST 在源白名单，源消息 MUST 属于调用所在群及机器人账号对应的 QQ 范围；目标 MUST 在目标白名单且不同于源群。缺失、非法 ID、私聊、越权、不可定位的源消息 MUST 在发送前拒绝，返回明确原因。评论 MUST 按普通文本发送，不解析成命令或可执行消息段。

#### Scenario: 合法调用
- **WHEN** 白名单源群请求将本群可读取消息转发至另一白名单目标群
- **THEN** 工具仅向指定目标发送，不广播到全部目标

#### Scenario: 伪造上下文
- **WHEN** 模型提供另一源群的消息 ID 或伪造源群和会话字段
- **THEN** 工具按可信调用来源拒绝越权，不查询后泄露该消息内容

#### Scenario: 目标无权限
- **WHEN** 目标为源群自身、不在白名单或没有可验证的发送路由
- **THEN** 工具不发送转发或评论，返回具体原因

### Requirement: 支持消息类型与完整性

工具 MUST 支持可完整取得内容的普通文字、图片和合并转发。普通消息 MUST 保持其原有消息形态，合并转发 MUST 保持聊天记录卡片形态；评论 MUST 是机器人另发的消息，不塞进原作者节点。不支持的类型、丢失媒体或无法完整恢复的节点 MUST 明确拒绝，MUST NOT 丢弃不支持的段后声称原消息已完整转发，MUST NOT 用描述文本冒充媒体或文件引用。正文与节点中的内容 MUST 作为不可信数据处理，不能改变路由或工具权限。

#### Scenario: 文字和图片
- **WHEN** 合法调用转发可完整取得的文字消息或图片消息
- **THEN** 目标收到对应文字或图片，非摘要替代品

#### Scenario: 合并转发卡片
- **WHEN** 合法调用转发所有节点均可完整发送的合并转发
- **THEN** 目标收到卡片，原作者节点不混入工具评论

#### Scenario: 存在无法支持的段
- **WHEN** 源消息或嵌套节点含无法完整发送的文件、视频、语音或丢失媒体
- **THEN** 在产生发送副作用前拒绝并说明类型或内容不可用，不静默降级

### Requirement: 真实发送与自然上下文

转发与评论 MUST 走主程序正常发送和记录链，成功消息 MUST 在正确目标群的消息记录及 Maisaka 可读历史中体现，以真实目标消息 ID 区分源消息和目标消息。插件 MUST NOT 另行追加转发摘要、行为留痕或评论副本。发送失败 MUST NOT 产生成功历史。陈旧会话、目标会话未运行等情形 MUST 验证实际上下文可见性，不能仅凭发送接口返回成功宣布全部完成。

#### Scenario: 成功发送可读
- **WHEN** 转发和非空评论都成功发送
- **THEN** 目标历史可读到两条真实消息且各出现一次，没有额外插件注入副本

#### Scenario: 目标冷会话
- **WHEN** 目标群尚无活动 Maisaka 运行时
- **THEN** 使用主程序受支持的会话机制保证随后读取真实消息历史；无法保障则明确报告限制，不以插件注入补偿

### Requirement: 可选评论固定延迟

`comment` 缺省、空字符串或全空白时 MUST 仅转发，不等待评论延迟。非空评论 MUST 在源消息发送成功后等待固定 **0.5 秒**再发起发送，MUST NOT 在转发前等待该延迟，MUST NOT 使用随机时长、模型参数或配置覆盖；实际可见间隔允许因调度、持久化和网络耗时更长。转发失败 MUST NOT 发送评论。评论内容 MUST 来自本次工具参数，不再次调用目标群 Maisaka 生成。

#### Scenario: 非空评论
- **WHEN** 源消息发送成功且 comment 为非空文本
- **THEN** 在成功回执后等待 0.5 秒再发送评论，不额外触发目标群评论任务

#### Scenario: 空评论
- **WHEN** comment 未传、为空或只含空白
- **THEN** 只发送源消息，不执行评论等待与评论发送

#### Scenario: 转发失败
- **WHEN** 源消息发送明确失败
- **THEN** 不发送评论、不登记源消息成功投递

### Requirement: 持久防重与不确定结果

自动和对话调用 MUST 共用已投递记录；同一账号、源群、源消息、目标群成功投递后 MUST 跨重启拒绝再次转发。评论变化 MUST NOT 绕过防重。相同投递的并发调用 MUST 不造成重复发送。源消息成功但评论失败 MUST 保留已投递记录，并返回部分成功；重复工具调用 MUST NOT 重发源消息或自动补发评论。发送结果不确定、发送后状态落盘失败或进程中断 MUST 不被等同于明确失败后安全重试；在无法核实前 MUST 阻止自动重发并提供可定位说明，不承诺跨外部发送与本地存储的原子恰好一次。

#### Scenario: 跨重启重复调用
- **WHEN** 已成功转发的相同消息和目标在重启后再次被调用，即使评论不同
- **THEN** 返回已转发，不发送源消息或评论

#### Scenario: 评论失败
- **WHEN** 源消息发送成功但评论发送失败
- **THEN** 报告转发成功、评论失败，保留目标消息 ID 和已投递记录

#### Scenario: 结果未知
- **WHEN** 发送请求可能成功但回执丢失，或重启发现未完成的投递记录
- **THEN** 返回结果待核实，不自动重复发送、不伪造成功

#### Scenario: 同消息不同目标
- **WHEN** 消息已成功投递给 A 群，随后合法调用指定尚未投递的 B 群
- **THEN** B 群可正常发送，不受 A 群记录阻止

### Requirement: 结果与生命周期

工具 MUST 等待本次实际发送及可选评论的结果，明确区分完整成功、部分成功、已转发、发送中、拒绝、明确失败与结果未知；包含已获得的真实目标消息 ID 和具体错误。关闭插件、变更白名单或卸载时 MUST 取消尚未发送的工作，保留已发生发送的事实；评论等待结束后 MUST 重新检查开关和目标授权。日志 MUST 可定位源消息、目标群和失败阶段，不记录凭证。

#### Scenario: 评论等待期间关闭
- **WHEN** 转发成功后在 0.5 秒等待期间插件关闭或目标权限撤销
- **THEN** 不再发送评论，已成功转发仍被记录，结果说明评论未发送

#### Scenario: 等待真实结果
- **WHEN** 目标发送仍在进行
- **THEN** 工具不能提前返回全部成功，卸载时不留下继续发送的孤立任务
