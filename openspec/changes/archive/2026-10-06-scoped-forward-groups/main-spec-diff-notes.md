## delta 未覆盖、需用户决定的残留

### (a) Purpose 段的白名单措辞

主 spec 第 5 行 Purpose 段含「通过同一个受白名单约束的工具转发指定消息」。delta 没有
`## Purpose` 操作，sync/archive 不会自动改它，同步后 Purpose 段仍以白名单口径与被整块
替换后的分组口径需求并存。建议用户在 sync 时手工改为分组口径，建议措辞：「通过同一个
受转发分组约束的工具转发指定消息」。

### (b) WebSocket 系措辞漂移

以下为上一轮 HTTP 直连变更归档同步时漏改的既存漂移，非本变更引入，仅报告：

- 主 spec 第 5 行 Purpose 段「源发送与评论由插件自身经受控的 SnowLuma 正向 WebSocket
  连接执行」：delta 无 Purpose 操作，sync/archive 后仍残留；同 spec 的「真实发送与自然
  上下文」需求（第 191 行）已写「经受控 HTTP 端点直连 SnowLuma 执行」。建议用户另开
  变更修正，或顺手在 sync 时按 HTTP 口径改写该句（如「正向 HTTP 连接执行」）。
- 主 spec 第 11 行「独立插件与路径开关」正文「直连 SnowLuma 已有正向 WebSocket
  服务端」：同为漏改漂移，但本变更 delta 的 MODIFIED 版本该处已写「正向 HTTP
  服务端」，sync/archive 整块替换后自动修复，不构成残留，用户无需额外处理。
- 主 spec 第 193 行「真实发送与自然上下文」正文「或 WebSocket 通道作替代」是禁止性
  措辞（禁止以 WebSocket 通道充当替代发送路径），与 HTTP 直连口径不矛盾，保留即可；
  列出以免误判为漂移。
