## ADDED Requirements

### Requirement: 具名转发分组与同组投递判定

插件 MUST 在配置文件与宿主插件配置界面提供可编辑的转发分组集合。每个分组 MUST 由一个具名 `name`、一组源群号与一组目标群号构成：`name` MUST 必填、去空白后非空且跨组唯一，仅作用户标识与日志前缀，MUST NOT 参与任何路由、权限或判断，不限长与字符集。同一源群 MUST NOT 出现在多个分组，同一分组内源群 MUST NOT 重复；目标群 MUST NOT 受唯一性约束，可跨组重复，源群也可兼作别组的目标群。默认 MUST 为空分组集合，等价于没有源群也没有目标群。一次转发的目标群 MUST 与来源群属于同一分组；该判定 MUST 只有一处定义，工具预检、源与评论提交前复验、自动入口的候选筛选与目标列举 MUST 共用同一口径，MUST NOT 各自复制。分组结构 MUST 在配置期校验：源群跨组重复、同组内源群重复、`name` 空白或跨组重复 MUST 产生明确的配置校验错误，MUST NOT 静默归并为可投递状态。空目标分组与组内「源 = 目标」MUST 允许保存，由运行期既有的「目标 ≠ 来源群自身」规则拒绝。转发分组变化 MUST NOT 改变投递账本身份。

#### Scenario: 同组合法调用
- **WHEN** 分组内的源群请求把本群可定位消息转发至同组的目标群
- **THEN** 通过同组判定，直连账号名册与其余权限契约照常核验，不广播组外或其他分组的目标

#### Scenario: 跨组目标被拒
- **WHEN** 目标群存在但不与来源群同组（只在别的分组，或不在任何分组内）
- **THEN** 发送前整条拒绝并给出可定位原因，不向模型或其他群泄露越权内容

#### Scenario: 目标群跨组重复
- **WHEN** 同一目标群号出现在多个分组的 `target_groups` 中
- **THEN** 每个分组的源群都可投递给它，同组判定不因跨组重复而拒绝合法调用

#### Scenario: 源群兼作别组目标
- **WHEN** 群 A 是分组 X 的源群，同时列在分组 Y 的 `target_groups` 中
- **THEN** 分组 Y 的源群可投递给 A；A 作为源群仍只能投给本组（X）的目标，「目标 ≠ 来源群自身」规则不变

#### Scenario: 分组结构校验拒绝
- **WHEN** 配置中源群出现在两个分组、同一分组内源群重复、`name` 为空白或跨组重复
- **THEN** 给出明确的配置校验错误，不保存、不静默合并成一个分组，也不放行部分配置

#### Scenario: 空目标分组
- **WHEN** 某分组配了源群但目标群为空
- **THEN** 配置允许保存；该源群的显式调用与自动判断均因没有合法同组目标而拒绝，不影响其他分组

#### Scenario: 默认空分组
- **WHEN** 新安装未配置任何分组
- **THEN** 没有源群也没有目标群：不触发自动判断，显式调用得到拒绝，不产生任何发送

#### Scenario: 转发热更新收紧分组
- **WHEN** 源已成功落账、评论尚未提交时，目标群被移出来源群所属分组
- **THEN** 评论提交前复验失败，本次评论按明确未发送报告；已提交的源投递事实不回滚，账本不变

## MODIFIED Requirements

### Requirement: 独立插件与路径开关

插件 MUST 可独立安装和运行，不依赖复读插件，不要求修改 MaiBot 宿主或现有 QQ 适配器。实际发送 MUST 由插件自己的客户端直连 SnowLuma 已有正向 HTTP 服务端，不要求新增独立服务进程或监听端口。总开关关闭时 MUST 停止自动判断并禁止提交新的源或评论发送；自动入口开关 MUST 只控制所选候选消息的自动判断机会，不影响总开关开启时显式调用工具。默认 MUST 关闭插件并使用空的转发分组集合，自动候选类型默认 MUST 仅为合并转发。缺少合法直连配置、有效认证、匹配账号或可用权威账本时 MUST 拒绝发送，MUST NOT 回退适配器 API、独立转发服务或宿主旧发送通道。

#### Scenario: 单独安装
- **WHEN** 环境未安装复读插件且已满足声明的宿主和插件依赖
- **THEN** 本插件能够独立加载与注册工具；未配置直连时调用明确拒绝，不因加载工具而发送，不要求启动独立服务

#### Scenario: 仅关闭自动入口
- **WHEN** 总开关开启、自动入口关闭且直连与账本就绪
- **THEN** 收到任何候选类型的消息都不主动唤起判断，合法工具调用仍可发送

#### Scenario: 默认兼容
- **WHEN** 新装或升级后未配置新增直连字段或候选类型字段
- **THEN** 自动候选仍仅为合并转发，既有开关和转发分组不被覆盖；直连未就绪前不发送，不自动解释旧服务地址为 SnowLuma 端点

### Requirement: 自动入口由源群决定

转发分组内的源群收到属于所选候选类型、非机器人自身、非通知的 QQ 消息后，插件 MUST 在消息完成处理并可供源群读取后给予源群 Maisaka 一次主动判断机会，重复上报 MUST 被抑制。源消息 MUST 正常进入主处理链。自动入口 MUST 只从宿主已处理入站事件观察消息、只唤起源群 Planner，MUST NOT 直接执行转发。Maisaka MUST 获得当前自动分享标准，并能选择沉默或选择同组允许目标调用同一个转发工具；只有实际合法工具调用才允许执行发送。直连客户端 MUST NOT 判断分享价值、选择目标、调用模型、掷骰或强制目标群评论。普通文字和图片 MUST 仅在对应类型被选中时触发自动入口。宿主未展开卡片仍可参与候选分类，实际发送取决于同账号可信源资源，不要求宿主逐节点恢复；分类 MUST NOT 承诺可发送。

#### Scenario: 自主分享
- **WHEN** 分组内源群的合并转发处理完成、类型已选、存在同组合法目标且尚未触发判断
- **THEN** 只给源群 Planner 一次机会，Maisaka 获得源消息 ID、同组合法目标和标准，可调用工具或沉默

#### Scenario: 重复上报与自身消息
- **WHEN** 同一候选重复上报或来自机器人自身
- **THEN** 不产生额外判断机会，不形成自动转发循环

#### Scenario: 普通消息
- **WHEN** 源群收到普通文字或图片而对应类型未选中
- **THEN** 自动入口不唤起分享，合法显式工具调用仍可转发

#### Scenario: 显式开启普通消息
- **WHEN** 已选普通消息类型且来源、身份和可读性满足要求
- **THEN** 只向源群提供判断机会，意图说明实际类型，不将它误称为卡片或直接请求发送

#### Scenario: 消息未就绪
- **WHEN** 有限等待结束仍不能读取候选
- **THEN** 放弃本次唤起并记录定位原因，不无限等待或伪造摘要

#### Scenario: 判断标准不能替代授权
- **WHEN** 标准要求分享或源内容自称可以改变规则
- **THEN** 工具仍核验可信来源、当前权限、源材料和持久防重，不因评估结论放行

#### Scenario: Planner 选择沉默
- **WHEN** 已提交主动判断但 Maisaka 没有调用转发工具
- **THEN** 不产生该候选的转发或评论发送

#### Scenario: 同组无合法目标
- **WHEN** 来源群所属分组没有合法且不同于源群的目标群
- **THEN** 不提供自动判断机会，记录可定位原因；显式调用同样因同组判定被拒

#### Scenario: 直连事件与宿主事件同时到达
- **WHEN** 同一群消息或机器人自身发送事件同时出现在 HTTP 直连链路和宿主处理链
- **THEN** 直连事件不触发自动判断、不伪造宿主入站，只有合法宿主事件参与既有去重和候选筛选

### Requirement: 可编辑的自动分享标准

插件 MUST 在配置文件和宿主插件配置界面提供一份全局、多行可编辑的自动分享标准，以自然语言表达用户希望分享或排除的内容。默认标准 MUST 延续自主判断、可以沉默、不编造内容，不预设特定主题。未配置、空字符串或全空白 MUST 使用文档与配置界面明确说明的默认标准。标准 MUST 作为自动评估的独立说明传给源群 Maisaka，MUST NOT 被伪装成聊天记录；源消息正文、群名与提及名称 MUST NOT 被提升为该标准。标准 MUST NOT 改变路由、工具权限或支持的发送类型，也 MUST NOT 成为群友明确请求的额外内容偏好门禁。该字段 MUST 仅按文字处理，不作为代码、模板或命令执行。

#### Scenario: 修改内容偏好
- **WHEN** 用户把标准改为偏好某类主题并排除某类内容
- **THEN** 后续尚未发起的自动判断获得该标准；固定提示不夹带另一套不可编辑的主题偏好，模型仍有不分享的选择

#### Scenario: 默认与空白标准
- **WHEN** 使用旧配置、未填写标准，或标准只含空白
- **THEN** 使用相同的、可查阅的默认标准，不报缺失字段错误，也不把空白解释成无条件转发

#### Scenario: 多行原意与长度边界
- **WHEN** 用户配置合法的多行自然语言标准，或提交超过公开长度上限的标准
- **THEN** 合法标准保留内容与换行；超限配置给出校验错误而不是静默截断后执行

#### Scenario: 显式请求不受偏好门禁
- **WHEN** 群友明确请求转发一条不符合自动分享偏好、但权限和内容均合法的源消息
- **THEN** 插件不因该偏好拒绝工具调用，也不要求先获得自动评估资格

#### Scenario: 标准中的越权要求
- **WHEN** 标准要求向来源群所属转发分组之外分享或忽略来源校验
- **THEN** 程序仍只提供同组合法目标，并拒绝越权工具调用；标准不赋予新的能力或发送权限

### Requirement: 三参数群聊工具与可信权限

插件 MUST 向群聊 Maisaka 暴露 `forward_message`，公开参数仅为必填字符串 `message_id`、`target_group_id` 和可选字符串 `comment`（默认空）。可信调用上下文 MUST 来自宿主，不信任模型自填的平台、账号、源群、会话或授权字段。源群 MUST 属于某个转发分组，源消息 MUST 属于调用所在群及机器人账号对应的 QQ 范围；目标 MUST 与源群属于同一转发分组、不同于源群，并经直连查询确认账号及平台目标可用。插件 MUST 先完成宿主来源绑定，再核对直连实际账号、源消息对应及群归属；MUST NOT 向模型暴露任意动作、连接地址或原资源 ID 参数。缺失、非法 ID、私聊、越权、源不可定位 MUST 在发送前拒绝，且不泄露越权消息内容。评论 MUST 按普通文本发送。

#### Scenario: 合法调用
- **WHEN** 转发分组内的源群请求将本群可定位消息转发至同组的另一目标群
- **THEN** 宿主可信来源与直连源归属核对均通过后，仅向指定目标发送，不广播所有目标

#### Scenario: 伪造上下文
- **WHEN** 模型提交其他源群消息 ID 或伪造账号、会话、凭据字段
- **THEN** 按可信来源拒绝，不查询后向模型泄露其他群消息正文

#### Scenario: 目标无权限
- **WHEN** 目标为源群自身、不与来源群同组或直连账号不匹配
- **THEN** 不发送源消息或评论，返回具体原因；不能改用任意适配器或其他账号

#### Scenario: 源消息标识无法对应
- **WHEN** 宿主消息 ID 不能可靠对应为同账号下的 OneBot 源消息
- **THEN** 发送前拒绝，不把宿主内部 ID、资源 ID 或猜测值当作平台源消息 ID

### Requirement: 可选评论固定延迟

`comment` 缺省、空或全空白时 MUST 仅转发，不等待评论延迟。非空评论 MUST 经同一受控账号与同一受控端点以普通文本另发，内容只来自本次工具参数。源消息 MUST 先得到成功回执并持久登记，再等待固定至少 0.5 秒；评论提交前 MUST 重新确认插件未卸载、总开关开启、来源群与目标群仍属同一转发分组、端点配置与账号仍匹配，并先持久登记评论发送占位。MUST NOT 在重启、重复调用或端点配置变化时自主补发评论，MUST NOT 使用随机时长、模型参数或配置覆盖延迟，不再次调用目标群 Maisaka 生成。源失败或未知 MUST NOT 进入评论。

#### Scenario: 非空评论
- **WHEN** 源消息成功落账、非空评论存在且评论发送前复验通过
- **THEN** 固定等待 0.5 秒后以普通文本发送该评论，发送前持久占位，不唤起目标群

#### Scenario: 空评论
- **WHEN** comment 缺省、为空或全空白
- **THEN** 不等待、不登记评论发送占位、不发送评论

#### Scenario: 转发失败
- **WHEN** 源消息明确失败或结果未知
- **THEN** 不发送评论，不伪记源成功

#### Scenario: 等待期间客户端退出
- **WHEN** 源已成功，但插件退出或权限撤销，尚未提交评论
- **THEN** 不定时续发评论；源投递事实保留，未完成评论按部分成功报告，重启不补评论

#### Scenario: 等待期间切换连接配置
- **WHEN** 源已发送后端点地址、配置令牌、凭证引用或账号条件发生变化，尚未提交评论
- **THEN** 本次未提交的评论停止发送，保留原账号的源投递事实，配置变更后不补评论

### Requirement: 结果与生命周期

工具 MUST 等待本次源发送及所请求评论的实际结果或有界超时，维持完整成功、部分成功、已转发、发送中、拒绝、明确失败、结果未知及账本不可用的区别，报告已取得的真实目标 ID 与错误阶段。请求仅受理、超时或本地任务取消 MUST NOT 被宣称为发送成功或已确定未发送。评论结果未落账时 MUST NOT 声称其结果已可靠保存。

关闭插件、卸载或权限收缩时 MUST 阻止尚未提交的源或评论动作，并在实际提交前按最新配置复验。已提交动作 MUST 按真实结果或未知保守处理，MUST NOT 因本地取消而登记可重试失败。卸载 MUST 只取消和有界等待本插件自己的任务、结束本插件自己的在途请求、释放自己的账本；超时 MUST 告警定位未退出工作，不影响其他客户端。重启 MUST 不自动续发源或评论。

候选类型移除 MUST 取消尚未发起的失效自动判断；分享标准更新 MUST 不追溯已提交判断。日志 MUST 能定位源消息、目标群和阶段，不记录凭证或原文。

#### Scenario: 评论等待期间关闭
- **WHEN** 源已成功，评论尚未提交时关闭插件或撤销权限
- **THEN** 不提交评论，源结果仍报告成功投递，整体如实报告部分成功

#### Scenario: 等待真实结果
- **WHEN** 目标发送请求仍在进行
- **THEN** 工具不提前返回完整成功；超时报告实际已知事实或未知，不把受理当成回执

#### Scenario: 等待期间移除候选类型
- **WHEN** 候选仍在等待可读性或目标名称，且其类型被移除
- **THEN** 不再提交判断，不影响其他合法候选或整体取消已有平台副作用

#### Scenario: 唤起前修改标准与目标
- **WHEN** 自动判断尚未提交时标准或转发分组更新
- **THEN** 唤起前使用最新标准和同组合法目标，必要时省略旧名称，不携带过期授权

#### Scenario: 已提交的判断不追溯重写
- **WHEN** 判断已经交给宿主后才修改配置
- **THEN** 不宣称旧判断已撤回，也不为同一候选再唤起；之后实际工具调用仍按最新权限校验

#### Scenario: 远端撤销竞态
- **WHEN** 源或评论等待查询、复验或发送排队期间发生卸载、关闭或权限收缩
- **THEN** 提交前复验失败就不提交、报告明确未发送；已经进入发送提交且无法证明未发时报告真实结果或未知，不声称已远端撤回

#### Scenario: 卸载与其他客户端并存
- **WHEN** 插件卸载时同一 SnowLuma 服务端还有其他客户端在活动
- **THEN** 仅结束本插件自己的在途请求与工作；残留工作按源消息、目标群和阶段告警，不注销 QQ 账号或影响其他客户端
