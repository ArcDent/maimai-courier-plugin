## Context

动机和产品范围见 `proposal.md`；行为契约见本变更的 `specs/cross-group-forward/spec.md`。用户已确认提及改为普通文本、自动候选类型可选、自动分享标准可编辑，分别记录在 ADR 0002、0003。

当前 `send_material._build_segments` 递归处理文字、图片与合并转发，其余段统一拒绝。本次用不含真实账号的合成消息调用生产预检：文字通过；文字前附加 `at`、转发节点内附加 `at` 均稳定得到对应段类型拒绝。这只验证了本地拒绝路径，不证明宿主 `at` 的完整载荷形态。

当前 `auto_entry.screen_forward_candidate` 只接受合并转发，`build_share_intent` 使用固定提示。`ForwardCandidate` 已由 `_auto_tasks` 持有，可以附加候选类型供热更新复验，无需另建任务系统。`run_auto_entry` 在等待消息可读后读一次配置，但随后还等待目标名称查询，因此必须在最后提交主动判断前再次读取配置。

### 实现前置阻塞

2026-09-30 对 `arcwsl` 的只读 SSH 连接超时，未读取到宿主或 SDK 新证据。实现阶段第一组必须在 `~/github/REFERENCE/` 核实并记录参考提交：

- 宿主入站、存储回读、合并转发节点中的个人与全体提及字段；显示名称是否真实可用，以及异常载荷形态。
- 正常文字、混排和转发节点中的普通文本是否均不再解析成提及／协议消息段；若某条通路会再次解析，必须找到已支持的安全文本方式，否则阻塞该支持，不猜测转义规则。
- SDK 配置模型的枚举数组、多行字符串、长度限制和默认值声明，宿主 UI 对这些声明的承载方式，以及旧配置合并、配置版本和热更新顺序。

上述是实现准入检查，不是已验证结论，不放在可随意延后的问题中。无法取得证据时保持任务未完成，不以替身测试替代宿主契约证据；若现有宿主不能支持已确认行为，应报告阻塞并重新对齐方案，不能暗改规格。

## Goals / Non-Goals

**Goals:** 复用现有预检递归、配置模型、自动任务与两条发送接缝；让提及转换只影响内容材料，让类型与偏好只影响自动判断；用最终提交前的配置复验覆盖异步等待窗口。

**Non-Goals:** 新建策略引擎、消息总线或模板执行器；扩展权限或账本结构；为不支持的媒体绕过宿主直发；让模型偏好变成可靠的确定性内容过滤承诺；在当前规划阶段修改业务代码。

## Decisions

### D1 提及在材料构建中统一转换

在 `send_material.py` 的既有递归预检中识别已核实形态的 `at`，生成新的普通 `text` 段；普通消息、合并转发与嵌套节点使用同一转换逻辑。保留原输入不变、原节点作者和层级不变，结构指纹描述转换后的可发送材料；其余类型仍走既有完整性校验。

文本显示采用明确的引用格式：个人有名称时为 `［提及：显示名称（对象标识）］`，无名称时为 `［提及：对象标识］`，全体为 `［提及：全体成员］`。名称只从源材料中已核实的显示字段取得，压平控制字符和多余空白，不查询目标成员；标识必须可确认，不能把缺失标识猜成全体成员。不对用户可控显示文本进行模板或命令求值。

转换后的内容必须在三条实际相关通路中验证为普通文本，不能只断言没有 `at` 字段。与提及相邻的文字不得因转换而新插入换行：优先在含提及的材料路径归并相邻文本，保持原文字中的换行；只有确实需要时才修改 `host_send.py` 的拼接辅助，不顺带重写其他发送逻辑。

替代方案：原样透传会将通知意图带到另一群，已被用户否决；直接丢弃会丢失语义；转为独立消息会改变消息数量、防重和评论顺序。统一转换后复用已有发送接缝，不引入第三条发送链。

### D2 最小配置增量与默认兼容

在既有 `[auto]` 节增加两个插件自有字段，名称是本变更的设计选择，不是声称宿主存在同名 API：

- `message_types`：文字 `text`、图片 `image`、合并转发 `forward` 的枚举列表，默认 `["forward"]`；空列表合法，未知枚举拒绝。复用 `Literal` 与 SDK 已核实的配置字段机制，不自行实现宽松别名解析。
- `share_criteria`：多行字符串，默认“结合消息内容与目标群，自行判断是否值得分享；不值得或无法判断时保持沉默，不必回复，不要编造消息内容。”；代码默认和 TOML 默认逐字一致。空白仅在读取有效标准时回退默认，不把非空配置压成单行。长度上限采用 4000 个字符，超过则配置校验失败，UI 提示和文档公开该上限；不静默截断。

配置界面位于现有自动入口区域，分别标注“自动候选类型”和“自动分享标准”，展示候选默认、空列表含义、标准空白回退及调用量提示。多选与多行控件只能使用前置检查核实的元数据，不能凭经验发明 `widget` 等字段。

旧配置缺少新字段时由配置默认补齐，保留既有开关、白名单和投递账本。`plugin.config_version` 的升级与合并步骤在前置检查确认宿主契约后落实，不把示例默认配置覆盖到用户运行配置。

替代方案：把整段内部提示暴露为模板会扩大路由和内容混杂的风险；每群／每目标单独标准增加当前不需要的配置复杂度。此次仅一份全局偏好，硬性权限仍由程序控制。

### D3 候选分类与发送预检分工

在 `auto_entry.py` 中替换当前仅卡片的候选判断为一个小型纯分类函数，候选类型的词汇来源与配置枚举共用：

1. 只要既有 `is_forward_card` 判据命中，就归为 `forward`，包括未展开包装；不复制卡片判据。卡片混排仍可能被工具侧拒绝，分类不承诺完整可发送。
2. 无卡片时，仅允许已识别的文字、图片、提及附属段参与普通分类；出现其他段或非法段结构直接放弃普通候选。
3. 含图片归为 `image`，覆盖单图、多图、图文与附带提及的图片；不含图片但存在非空文字归为 `text`。只有空白或仅提及不单独触发。

分类阶段不下载或恢复媒体，也不因预检所需二进制暂时缺失阻塞入站 Hook；发送时才执行完整材料校验。QQ 平台、来源白名单、可靠账号／发送者、非自身、非通知、安全标识校验全部保留。

在既有 `ForwardCandidate` 中保存分类结果，既有内存去重键仍使用账号、源群和源消息；不加入配置版本或类别，避免一条消息在多选或热更新后获得重复判断。去重窗口、容量与消息可读等待上限不变；修改配置不扫描和重放历史消息。

替代方案：逐段按每个已选类型触发会使图文混排重复评估；只检查“含文字”会让图片／视频夹带文字绕过类型选择；把完整发送材料构建搬进 Hook 会扩大延迟和耦合。

### D4 固定安全说明与可编辑偏好分开

扩展 `build_share_intent` 以接收实际候选类型与已经解析好的有效标准。固定部分仅说明源消息 ID、实际消息类型、合法目标、工具用法、不可信显示文本与允许沉默等边界；单独标注“用户配置的自动分享标准”并放入标准原文。既有群名清洗与安全标识检查继续复用，源消息正文和节点内容不拼进意图。

固定部分不暗藏技术资料、广告等主题偏好，不把文字或图片称为合并转发。标准仅做文字拼接，不使用格式模板展开或可执行表达式。模型可能不完全遵循偏好，文档应区分自然语言判断依据与程序保证的权限限制。

工具预检与 `_send_allowed` 不增加标准或候选资格检查，不给自动判断签发新票据；群友明确请求保持当前工具授权方式。自动结果最终仍走同一投递链。

替代方案：在工具内硬判内容偏好需要额外模型调用并会误伤明确请求；把正文或群名放进标准区域会混淆不可信内容与用户配置。

### D5 在实际唤起边界读取最新配置

复用 `auto_entry_invalid_reason` 统一开关、源群、目标及候选类型判定；`plugin._auto_entry_invalid` 与后台等待结束后的检查均使用它。更新候选类型后取消失效的本插件自动任务；只更新标准时不取消仍合法的候选，等待结束读取最新值。

`run_auto_entry` 在消息可读后执行初检和可选群名查询，查询结束后再次取得最新配置、重新验证候选、重建合法目标集合、解析最新标准，然后直接进入 `maisaka.proactive.trigger` 调用，中间不再插入其他异步查询。若新增目标没有名称，按现有约定只提供群号；移除目标不得从名称查询快照重新混入。

“尚未发起”的边界定义为插件尚未调用宿主主动判断能力；请求已交给宿主后不承诺撤回或重写。插件在取消等待任务时可能结束本地等待，但不得把已提交的宿主判断描述为已撤销。热更新不整体取消在途投递，源发送前和评论发送前继续复用 `_send_allowed` 检查最新权限。

替代方案：入站时缓存标准会使长等待任务使用旧偏好；仅在消息可读时复验仍遗漏名称查询期间的变更；为追赶配置重启相同候选会破坏一次判断约束。

### D6 沿用已有测试边界

提及转换既需要纯材料测试，也需要经插件入口到真实 `host_send` 实现、替身 `ctx.send` 的端到端断言，检查普通文本段、节点归属、消息数量、真实目标 ID、评论顺序与防重。异常对象、恶意显示名称、其他不支持段、丢失媒体和空节点继续整条拒绝。

自动入口用既有 `received_message`、`drive_observe_hook`、注入时钟和 `apply_config_update`；增加类型组合、旧配置默认、多行标准、空白回退、长度校验、等待期间及目标名称查询期间的更新测试。通过可控悬停替身定位竞态，不加真实睡眠或轮询概率。

本机全量验证仍使用项目规定的 pytest 与 pyright 命令，不安装真实 SDK或全局依赖。替身和静态 schema 测试不代替宿主 UI 承载与文本发送契约核实；实际群消息验证需另获授权。

## Risks / Trade-offs

- [参考机不可达] → 前置检查保持阻塞；不伪造宿主字段、配置控件或验证结论。
- [普通消息导致模型调用增多] → 默认仅合并转发，用户显式开启；配置界面说明成本，保留原有去重但不引入暗藏概率或冷却。
- [来源显示信息中夹带协议语法] → 明确生成普通文本，核实所有相关宿主通路不会重新解析；异常对象仍拒绝。
- [材料转换意外改变排版或节点归属] → 对段顺序、原换行、作者、嵌套与实际发送载荷做断言，不以摘要替代原材料。
- [配置更新发生在异步间隙] → 最终唤起前重读配置；已提交判断不追溯撤销，发送权限继续独立复验。
- [用户误以为候选类型等于可发送保证] → UI 与 README 区分候选机会和完整预检，明确其他段仍会拒绝。
- [自然语言标准未被模型遵循] → 如实说明它是判断依据而非确定性过滤；程序安全限制独立执行。

## Migration Plan

1. 完成参考源码与 SDK 前置核实，按用户确认的规格实施并通过本地回归；当前阶段仅规划。
2. 用户自行部署；旧配置通过新字段默认保持仅合并转发，保留现有账本，不迁移或删除投递记录，不读取其他插件数据。
3. 配置页确认两个新增字段可见可编辑，按需开启普通类型并填写标准；未经另行授权不发送群消息做验证。
4. 回滚时先关闭自动入口或插件，由用户恢复旧版本及兼容配置；保留账本，明确旧版会再次拒绝提及，避免同时运行两条跨群发送路径。
5. 实现完成并另获流程授权后同步增量规格，更新主规格目的描述、README 与项目规则；保留 `CLAUDE.md` 的规则软链接。当前不改主规格、不自动提交或推送。
