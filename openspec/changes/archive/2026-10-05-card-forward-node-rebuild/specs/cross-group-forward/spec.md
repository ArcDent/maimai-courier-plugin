## MODIFIED Requirements

### Requirement: 支持消息类型与完整性

工具 MUST 支持可完整发送的合并转发卡片、普通文字与普通图片（含图文混排），全部通过插件自己的 SnowLuma HTTP 端点按源消息类型分派执行。合并转发卡片 MUST 以「卡片消息转发」发送：按源消息的卡片标识展开查询取得节点序列，经结构校验后以单次卡片发送动作提交，平台按目标群上下文重建卡片并重新上传卡片内媒体；插件 MUST NOT 递归展开、重建内层、改写或清洗节点内容，MUST NOT 提交调用者提供的资源 ID、正文或媒体地址。卡片节点署名 MUST 取自源消息发送者身份（标识与显示名只来自源消息）。卡片内部的回复、提及、媒体与未知段 MUST 作为节点内容保留，MUST NOT 逐节点清洗，MUST NOT 因插件不支持某种内部段而拒绝。普通文字 MUST 以单节点合并转发卡片发送：节点署名 MUST 取自源消息发送者身份，节点内容段 MUST 按源消息原样提交（含个人与全体成员提及原样保留、不做文本化）。普通图片 MUST 以普通消息段直发、保留文字与图片顺序；普通图片路径的个人及全体成员提及 MUST 保留对象信息并转成不触发提醒的普通文本。卡片内提及是否在目标群客户端触发提醒 MUST NOT 作保证。评论 MUST 为独立的普通文本消息，不塞入卡片节点。卡片消息 MUST NOT 设置外层预览、摘要或来源参数。

插件 MUST NOT 以 `send_msg` 之类普通发送动作直接引用源卡片资源标识发送卡片（实测该通道信封成功而群内展示降级空壳，回执核验无法识别）。普通消息（图片路径）的不支持段、丢失媒体和对象不可确认的提及 MUST 在发送前整条拒绝；引用（回复）段 MUST 随消息整条拒绝并指引改用被引用消息自身的 ID。源消息顶层卡片与其他内容混排 MUST 明确拒绝。源正文、卡片内部、群名和提及名称 MUST 仅作为数据，不能改变权限或路由。

#### Scenario: 文字和图片
- **WHEN** 合法调用转发可完整取得的普通文字、单图、多图或图文混排
- **THEN** 普通文字以单节点卡片发送（节点署源发送者身份、内容段原样），普通图片以普通消息按原顺序段直发；不以描述代替媒体，不调用宿主旧发送通道

#### Scenario: 合并转发卡片
- **WHEN** 合法调用转发可定位的合并转发卡片消息
- **THEN** 按源消息的卡片标识展开查询取得节点，经结构校验后以单次卡片发送动作一次提交；平台按目标群上下文重建卡片，插件不递归展开、不改写内容，不混入工具评论

#### Scenario: 嵌套卡片原样提交
- **WHEN** 展开取得的节点内容含对另一张卡片的 forward 段（嵌套卡片）
- **THEN** 内层 forward 段作为节点内容原样提交，插件不递归展开、不重建内层；内层在目标群的展示不作保证

#### Scenario: 假成功通道禁止
- **WHEN** 实现或运维试图用普通发送动作直接引用源卡片资源标识发送卡片
- **THEN** 契约禁止该通道；发送路径只允许展开查询后的卡片发送动作，不以信封成功当作内容可用

#### Scenario: 普通消息中的个人提及
- **WHEN** 普通图片或图文混排消息附有可识别的个人提及
- **THEN** 保留对象信息并转为普通文本，与其余内容顺序一致，不产生实际顶层提及（普通文字路径的提及随节点原样提交）

#### Scenario: 全体成员提及
- **WHEN** 普通图片或图文混排消息附有可确认的全体成员提及
- **THEN** 仅发送表示全体成员含义的普通文本，不生成提醒全群的段（普通文字路径的提及随节点原样提交）

#### Scenario: 提及缺少显示名称
- **WHEN** 普通图片路径的提及对象明确但没有源显示名称
- **THEN** 使用源对象标识，不虚构昵称或查询目标群成员补全

#### Scenario: 嵌套节点中的提及
- **WHEN** 原卡片内部或嵌套卡片含个人、全体成员提及或回复
- **THEN** 作为节点内容的一部分随重组保留，不逐段改写，不将内部提及提取为目标群顶层提醒

#### Scenario: 提及对象不可确认
- **WHEN** 普通图片路径的提及既不能确认为全体也没有可用个人标识
- **THEN** 发送前整条拒绝，不把缺失标识猜成全体；不扫描原卡片内部套用此规则

#### Scenario: 存在无法支持的段
- **WHEN** 普通源消息（图片路径）包含不支持的文件、视频、语音、回复段或丢失图片媒体
- **THEN** 发送前整条拒绝；此规则不用于剥除或拒绝原卡片内部已存在的内容

#### Scenario: 显示信息不能变成消息指令
- **WHEN** 普通消息的提及显示名称、卡片内容或本次评论包含协议语法、命令或提示指令
- **THEN** 按普通数据发送，不转成消息段或改变路由

#### Scenario: 原资源不可用
- **WHEN** 源消息缓存缺失、卡片源消息已不存在（平台返回不存在）、展开查询失败无可派发节点，或卡片结构校验不通过
- **THEN** 发送前整条拒绝并给出可定位原因，不用源消息 ID 猜造资源 ID，不退回复制节点或摘要重建

#### Scenario: 顶层卡片混排
- **WHEN** 源消息含合并转发卡片以及额外顶层文字、图片或提及
- **THEN** 明确拒绝不支持的混排，不只发送卡片并声称整条已完整转发
