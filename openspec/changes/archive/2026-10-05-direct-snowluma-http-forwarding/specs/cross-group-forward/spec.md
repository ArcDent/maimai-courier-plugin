## MODIFIED Requirements

### Requirement: 支持消息类型与完整性

工具 MUST 支持可完整发送的合并转发卡片、普通文字与普通图片（含图文混排），全部通过插件自己的 SnowLuma HTTP 端点按源消息类型分派执行。合并转发卡片 MUST 以「卡片消息转发」发送：只提交源消息标识与目标群，由平台按标识重建卡片，插件 MUST NOT 提取内部节点、重建卡片、提交或猜测资源 ID；卡片内部的回复、提及、媒体与未知段 MUST 作为卡片内容保留，MUST NOT 逐节点清洗，MUST NOT 因插件不支持某种内部段而拒绝。普通文字 MUST 以单节点合并转发卡片发送：节点署名 MUST 取自源消息发送者身份（标识与显示名只来自源消息，不用其他身份），节点内容段 MUST 按源消息原样提交（含个人与全体成员提及原样保留、不做文本化）。普通图片 MUST 以普通消息段直发、保留文字与图片顺序；普通图片路径的个人及全体成员提及 MUST 保留对象信息并转成不触发提醒的普通文本。卡片内提及是否在目标群客户端触发提醒 MUST NOT 作保证。评论 MUST 为独立的普通文本消息，不塞入卡片节点。卡片消息 MUST NOT 设置外层预览、摘要或来源参数。

普通消息（图片路径）的不支持段、丢失媒体和对象不可确认的提及 MUST 在发送前整条拒绝；引用（回复）段 MUST 随消息整条拒绝并指引改用被引用消息自身的 ID。源消息顶层卡片与其他内容混排 MUST 明确拒绝。源正文、卡片内部、群名和提及名称 MUST 仅作为数据，不能改变权限或路由。

#### Scenario: 文字和图片
- **WHEN** 合法调用转发可完整取得的普通文字、单图、多图或图文混排
- **THEN** 普通文字以单节点卡片发送（节点署源发送者身份、内容段原样），普通图片以普通消息按原顺序段直发；不以描述代替媒体，不调用宿主旧发送通道

#### Scenario: 合并转发卡片
- **WHEN** 合法调用转发可定位的合并转发卡片消息
- **THEN** 只提交源消息标识与目标群，平台重建卡片并发送；插件不提取、不改写、不重建内部节点，不混入工具评论

#### Scenario: 普通消息中的个人提及
- **WHEN** 普通图片或图文混排消息附有可识别的个人提及
- **THEN** 保留对象信息并转为普通文本，与其余内容顺序一致，不产生实际顶层提及（普通文字路径的提及随节点原样提交）

#### Scenario: 全体成员提及
- **WHEN** 普通图片或图文混排消息附有可确认的全体成员提及
- **THEN** 仅发送表示全体成员含义的普通文本，不生成提醒全群的段（普通文字路径的提及随节点原样提交）

#### Scenario: 提及缺少显示名称
- **WHEN** 普通图片路径的提及对象明确但没有源显示名称
- **THEN** 使用源对象标识，不虚构昵称或查询目标群成员补全

#### Scenario: 嵌套节点中的提及
- **WHEN** 原卡片内部或嵌套卡片含个人、全体成员提及或回复
- **THEN** 作为卡片内容的一部分随平台重建保留，不逐段改写，不将内部提及提取为目标群顶层提醒

#### Scenario: 提及对象不可确认
- **WHEN** 普通图片路径的提及既不能确认为全体也没有可用个人标识
- **THEN** 发送前整条拒绝，不把缺失标识猜成全体；不扫描原卡片内部套用此规则

#### Scenario: 存在无法支持的段
- **WHEN** 普通源消息（图片路径）包含不支持的文件、视频、语音、回复段或丢失图片媒体
- **THEN** 发送前整条拒绝；此规则不用于剥除或拒绝原卡片内部已存在的内容

#### Scenario: 显示信息不能变成消息指令
- **WHEN** 普通消息的提及显示名称、卡片内容或本次评论包含协议语法、命令或提示指令
- **THEN** 按普通数据发送，不转成消息段或改变路由

#### Scenario: 原资源不可用
- **WHEN** 源消息缓存缺失、卡片源消息已不存在（平台返回不存在），或可确认资源不可读取
- **THEN** 明确说明不可用，不用源消息 ID 猜造资源 ID，也不退回节点重建

#### Scenario: 顶层卡片混排
- **WHEN** 源消息含合并转发卡片以及额外顶层文字、图片或提及
- **THEN** 明确拒绝不支持的混排，不只发送卡片并声称整条已完整转发


### Requirement: 真实发送与自然上下文

转发与评论 MUST 由插件经受控 HTTP 端点直连 SnowLuma 执行，并以真实平台投递结果和目标消息 ID 报告给源群 Maisaka；HTTP 受理、资源 ID、本地不透明 ID 或写入成功 MUST NOT 被视为发送成功。插件 MUST NOT 调用适配器公开 API、独立转发服务、宿主旧发送通道或 WebSocket 通道作替代，也不注册第二个同路由发送网关。直连 MUST NOT 成为宿主入站以外的第二事件源：平台侧推送的事件 MUST NOT 唤起 Planner、执行转发、伪造宿主入站或补写目标群历史。目标群宿主消息记录及 Maisaka 历史同步不属于本工具保证，MUST 明确公开该限制；MUST NOT 追加摘要、直接写宿主数据库、假造入站消息或重复发送来补偿。平台投递失败 MUST NOT 报告成功。真实目标消息 ID MUST 与源消息及资源 ID 区分。

#### Scenario: 成功发送可读
- **WHEN** 源消息和非空评论获得平台成功回执并完成结果落账
- **THEN** 源群工具结果包含两条真实目标消息的状态与 ID；QQ 目标可见性可独立验收，不将目标群 Maisaka 历史可读性当作已保证事实

#### Scenario: 目标冷会话
- **WHEN** 目标群没有活动 Maisaka 运行时
- **THEN** 不为转发创建或唤起目标 Planner；按合法平台目标发送，明确不保证宿主历史同步

#### Scenario: 服务不可用
- **WHEN** SnowLuma HTTP 端点不可用、认证失败，或发送请求结果不确定
- **THEN** 如实区分发送前拒绝与结果未知，不改用其它通道或另一个平台动作补发

#### Scenario: 自发事件回流
- **WHEN** 所用服务端端点开启上报自身，或平台存在事件推送能力
- **THEN** 插件不经长连接接收事件，不把任何推送当作可靠回执或第二事件源，不据此触发再次转发或承诺历史同步


### Requirement: 可选评论固定延迟

`comment` 缺省、空或全空白时 MUST 仅转发，不等待评论延迟。非空评论 MUST 经同一受控账号与同一受控端点以普通文本另发，内容只来自本次工具参数。源消息 MUST 先得到成功回执并持久登记，再等待固定至少 0.5 秒；评论提交前 MUST 重新确认插件未卸载、总开关开启、两级白名单允许、端点配置与账号仍匹配，并先持久登记评论发送占位。MUST NOT 在重启、重复调用或端点配置变化时自主补发评论，MUST NOT 使用随机时长、模型参数或配置覆盖延迟，不再次调用目标群 Maisaka 生成。源失败或未知 MUST NOT 进入评论。

#### Scenario: 非空评论
- **WHEN** 源消息成功落账、非空评论存在且评论发送前复验通过
- **THEN** 固定等待 0.5 秒后以普通文本发送该评论，发送前持久占位，不唤起目标群

#### Scenario: 空评论
- **WHEN** comment 缺省、为空或全空白
- **THEN** 不等待、不登记评论发送占位、不发送评论

#### Scenario: 转发失败
- **WHEN** 源消息明确失败或结果未知
- **THEN** 不发送评论，不伪记源成功

#### Scenario: 等待期间客户端退出
- **WHEN** 源已成功，但插件退出或权限撤销，尚未提交评论
- **THEN** 不定时续发评论；源投递事实保留，未完成评论按部分成功报告，重启不补评论

#### Scenario: 等待期间切换连接配置
- **WHEN** 源已发送后端点地址、配置令牌、凭证引用或账号条件发生变化，尚未提交评论
- **THEN** 本次未提交的评论停止发送，保留原账号的源投递事实，配置变更后不补评论


### Requirement: 结果与生命周期

工具 MUST 等待本次源发送及所请求评论的实际结果或有界超时，维持完整成功、部分成功、已转发、发送中、拒绝、明确失败、结果未知及账本不可用的区别，报告已取得的真实目标 ID 与错误阶段。请求仅受理、超时或本地任务取消 MUST NOT 被宣称为发送成功或已确定未发送。评论结果未落账时 MUST NOT 声称其结果已可靠保存。

关闭插件、卸载或权限收缩时 MUST 阻止尚未提交的源或评论动作，并在实际提交前按最新配置复验。已提交动作 MUST 按真实结果或未知保守处理，MUST NOT 因本地取消而登记可重试失败。卸载 MUST 只取消和有界等待本插件自己的任务、结束本插件自己的在途请求、释放自己的账本；超时 MUST 告警定位未退出工作，不影响其他客户端。重启 MUST 不自动续发源或评论。

候选类型移除 MUST 取消尚未发起的失效自动判断；分享标准更新 MUST 不追溯已提交判断。日志 MUST 能定位源消息、目标群和阶段，不记录凭证或原文。

#### Scenario: 评论等待期间关闭
- **WHEN** 源已成功，评论尚未提交时关闭插件或撤销权限
- **THEN** 不提交评论，源结果仍报告成功投递，整体如实报告部分成功

#### Scenario: 等待真实结果
- **WHEN** 目标发送请求仍在进行
- **THEN** 工具不提前返回完整成功；超时报告实际已知事实或未知，不把受理当成回执

#### Scenario: 等待期间移除候选类型
- **WHEN** 候选仍在等待可读性或目标名称，且其类型被移除
- **THEN** 不再提交判断，不影响其他合法候选或整体取消已有平台副作用

#### Scenario: 唤起前修改标准与目标
- **WHEN** 自动判断尚未提交时标准或白名单更新
- **THEN** 唤起前使用最新标准和合法目标，必要时省略旧名称，不携带过期授权

#### Scenario: 已提交的判断不追溯重写
- **WHEN** 判断已经交给宿主后才修改配置
- **THEN** 不宣称旧判断已撤回，也不为同一候选再唤起；之后实际工具调用仍按最新权限校验

#### Scenario: 远端撤销竞态
- **WHEN** 源或评论等待查询、复验或发送排队期间发生卸载、关闭或权限收缩
- **THEN** 提交前复验失败就不提交、报告明确未发送；已经进入发送提交且无法证明未发时报告真实结果或未知，不声称已远端撤回

#### Scenario: 卸载与其他客户端并存
- **WHEN** 插件卸载时同一 SnowLuma 服务端还有其他客户端在活动
- **THEN** 仅结束本插件自己的在途请求与工作；残留工作按源消息、目标群和阶段告警，不注销 QQ 账号或影响其他客户端
