# 1.4 回执证据与失败分类

日期：2026-10-02。**服务端字段及含义未复核**；冻结依据为旧网关研究报告“五、目标消息
回执与失败边界”、旧方向报告第3节、现有 `service/gateway.py` 480–578 行。
本轮部署客户端只能证明其使用 `status/data`，不能证明 QQ 投递结果；没有连接真实端点。

## 允许确认成功的证据集合（U7）

同连接、当前 `echo` 的合法动作响应，`status="ok"`，`retcode` 若提供必须为非布尔的 0，
`data` 是映射，`data.message_id` 是可引用标识；这些只形成**候选回执**。
事件标记（如 `post_type`）存在时不能冒充动作响应，`status=async/failed/未知` 均非成功。
随后只对这一个候选 ID 执行有限 `get_msg`，要求：

1. `data.message_id` 与被查询 ID 相同：证明返回的是本次候选记录，不是别的缓存行。
2. `data.group_id` 等于可信目标群；类型必须为群消息（若字段缺失不能证明群消息则未知）。
3. `data.user_id` 等于可信宿主账号及该发送阶段同连接核验的登录账号。
4. `data.message_seq` 是真正的正整数，布尔、零、负数、字符串与缺失均不合格。

`message_seq` 被解释为 QQ 真实群序列这一点**只有服务端才可确认**；字段齐全也只是
离线约定，不能冒充线上证据已验证。U7 未确认前不宣称已实测支持此判据。

旧网关报告记录：`finalizeSend` 有正群序列时由序列/目标群/事件类型派生 OneBot ID；
无群序列时可能返回本地不透明 ID。因此非空甚至数字 ID 不是成功证明，不能仅凭格式
区分真实与不透明 ID。资源 ID、源消息 ID 也都不能充当新目标 ID。

## 合成样本与反例

成功样本：固定 `send_msg` 返回 `{"status":"ok","retcode":0,"data":{"message_id":-23456},"echo":"instance-1-1"}`；
仅查 `-23456`，返回同 ID、`message_type=group`、`group_id=222`、`user_id=10001`、
`message_seq=42`，均与请求及同连接账号一致。满足冻结契约后得到
`SourceSendResult(status="sent", target_message_id="-23456")`；落账成功才是完整成功。

- 无 ID：`status=ok,data={}` → unknown；不评论、不重发。
- 本地不透明 ID：ID 非空但 `message_seq=0`/缺失/True/"42" → unknown。
- 错记录：查询 `-23456` 返回 `-23457`，即便其它三项相符 → unknown。
- 错群/错发送账号：任一不符 → unknown，不以别群消息冒充成功。
- 查询失败/缓存暂不可见：最多8次、总预算3秒、间隔0.5秒且受剩余预算约束；
  不使用旧实现的最小查询时间额外延长期限，不模糊搜索事件。
- 发送后网关登记异常：QQ 发送可能已完成而 `finalizeSend`/缓存登记抛错；
  即便得到通用 `failed/retcode/wording` 也必须 unknown。不能按错误文字猜未发。
- 已有可靠四项证据，但本插件 `mark_sent` 失败：保留真实目标 ID 与已有占位，
  `stage=source_persist`，不称完整成功，不进入评论；评论终态失败同理不称可靠保存。

## 未提交与可能提交分界（U8）

- 本地权限/材料/账号/目标拒绝、握手失败、排队取消，且能证明发送帧**未开始写入**：
  明确未发送。准备函数返回 `PrepareRejected`；编排区分 rejected 与 ledger_unavailable，
  需要结束占位时可标 failed，后续仅显式新调用可能再试。
- 进入 `send_json/send_str` 前置写入标记之后，包括写入协程抛错、断线、超时、取消、
  无回执、未知状态：没有充分成功证据就 unknown，不能用库异常类别断定未发。
- 写入成功只证明字节交给传输，动作受理只证明受理；都不是 QQ 到达证据。
- 当前阶段固定连接断开后不重连继续发；后续合法只读操作可以建立新连接，不能重放旧帧。
- 评论仅在源确认并可靠落账后执行；源 unknown 或落账失败不进入评论。重复调用不补评论。

失败口径复用 `SourceSendResult`、`normalize_send_status` 和 `render_forward_result`；
传输内部的“未开始/可能开始”证据不扩展模型参数或通用动作能力。原始异常、正文、
资源 ID、媒体签名和凭证不进入日志/结果。服务端待确认 U7/U8 不属于已完成联验。
