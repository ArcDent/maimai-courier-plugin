## MODIFIED Requirements

### Requirement: 独立插件与路径开关

插件 MUST 可独立安装和运行，不依赖复读插件，不要求修改 MaiBot 宿主或现有 QQ 适配器。实际发送 MUST 由插件自己的客户端直连 SnowLuma 已有正向 WebSocket 服务端，不要求新增独立服务进程或监听端口。总开关关闭时 MUST 停止自动判断并禁止提交新的源或评论发送；自动入口开关 MUST 只控制所选候选消息的自动判断机会，不影响总开关开启时显式调用工具。默认 MUST 关闭插件并使用空白名单，自动候选类型默认 MUST 仅为合并转发。缺少合法直连配置、有效认证、匹配账号或可用权威账本时 MUST 拒绝发送，MUST NOT 回退适配器 API、独立转发服务或宿主旧发送通道。

#### Scenario: 单独安装
- **WHEN** 环境未安装复读插件且已满足声明的宿主和插件依赖
- **THEN** 本插件能够独立加载与注册工具；未配置直连时调用明确拒绝，不因加载工具而发送，不要求启动独立服务

#### Scenario: 仅关闭自动入口
- **WHEN** 总开关开启、自动入口关闭且直连与账本就绪
- **THEN** 收到任何候选类型的消息都不主动唤起判断，合法工具调用仍可发送

#### Scenario: 默认兼容
- **WHEN** 新装或升级后未配置新增直连字段或候选类型字段
- **THEN** 自动候选仍仅为合并转发，既有开关和白名单不被覆盖；直连未就绪前不发送，不自动解释旧服务地址为 SnowLuma 端点

### Requirement: 自动入口由源群决定

白名单源群收到属于所选候选类型、非机器人自身、非通知的 QQ 消息后，插件 MUST 在消息完成处理并可供源群读取后给予源群 Maisaka 一次主动判断机会，重复上报 MUST 被抑制。源消息 MUST 正常进入主处理链。自动入口 MUST 只从宿主已处理入站事件观察消息、只唤起源群 Planner，MUST NOT 直接执行转发。Maisaka MUST 获得当前自动分享标准，并能选择沉默或选择允许目标调用同一个转发工具；只有实际合法工具调用才允许执行发送。直连客户端 MUST NOT 判断分享价值、选择目标、调用模型、掷骰或强制目标群评论。普通文字和图片 MUST 仅在对应类型被选中时触发自动入口。宿主未展开卡片仍可参与候选分类，实际发送取决于同账号可信源资源，不要求宿主逐节点恢复；分类 MUST NOT 承诺可发送。

#### Scenario: 自主分享
- **WHEN** 合法源群合并转发处理完成、类型已选且尚未触发判断
- **THEN** 只给源群 Planner 一次机会，Maisaka 获得源消息 ID、合法目标和标准，可调用工具或沉默

#### Scenario: 重复上报与自身消息
- **WHEN** 同一候选重复上报或来自机器人自身
- **THEN** 不产生额外判断机会，不形成自动转发循环

#### Scenario: 普通消息
- **WHEN** 源群收到普通文字或图片而对应类型未选中
- **THEN** 自动入口不唤起分享，合法显式工具调用仍可转发

#### Scenario: 显式开启普通消息
- **WHEN** 已选普通消息类型且来源、身份和可读性满足要求
- **THEN** 只向源群提供判断机会，意图说明实际类型，不将它误称为卡片或直接请求发送

#### Scenario: 消息未就绪
- **WHEN** 有限等待结束仍不能读取候选
- **THEN** 放弃本次唤起并记录定位原因，不无限等待或伪造摘要

#### Scenario: 判断标准不能替代授权
- **WHEN** 标准要求分享或源内容自称可以改变规则
- **THEN** 工具仍核验可信来源、当前权限、源材料和持久防重，不因评估结论放行

#### Scenario: Planner 选择沉默
- **WHEN** 已提交主动判断但 Maisaka 没有调用转发工具
- **THEN** 不产生该候选的转发或评论发送

#### Scenario: 直连事件与宿主事件同时到达
- **WHEN** 同一群消息或机器人自身发送事件同时出现在 WebSocket 连接和宿主处理链
- **THEN** 直连事件不触发自动判断、不伪造宿主入站，只有合法宿主事件参与既有去重和候选筛选

### Requirement: 三参数群聊工具与可信权限

插件 MUST 向群聊 Maisaka 暴露 `forward_message`，公开参数仅为必填字符串 `message_id`、`target_group_id` 和可选字符串 `comment`（默认空）。可信调用上下文 MUST 来自宿主，不信任模型自填的平台、账号、源群、会话或授权字段。源群 MUST 在源白名单，源消息 MUST 属于调用所在群及机器人账号对应的 QQ 范围；目标 MUST 在目标白名单、不同于源群，并经直连查询确认账号及平台目标可用。插件 MUST 先完成宿主来源绑定，再核对直连实际账号、源消息对应及群归属；MUST NOT 向模型暴露任意动作、连接地址或原资源 ID 参数。缺失、非法 ID、私聊、越权、源不可定位 MUST 在发送前拒绝，且不泄露越权消息内容。评论 MUST 按普通文本发送。

#### Scenario: 合法调用
- **WHEN** 白名单源群请求将本群可定位消息转发至另一白名单目标群
- **THEN** 宿主可信来源与直连源归属核对均通过后，仅向指定目标发送，不广播所有目标

#### Scenario: 伪造上下文
- **WHEN** 模型提交其他源群消息 ID 或伪造账号、会话、凭据字段
- **THEN** 按可信来源拒绝，不查询后向模型泄露其他群消息正文

#### Scenario: 目标无权限
- **WHEN** 目标为源群自身、不在有效白名单或直连账号不匹配
- **THEN** 不发送源消息或评论，返回具体原因；不能改用任意适配器或其他账号

#### Scenario: 源消息标识无法对应
- **WHEN** 宿主消息 ID 不能可靠对应为同账号下的 OneBot 源消息
- **THEN** 发送前拒绝，不把宿主内部 ID、资源 ID 或猜测值当作平台源消息 ID

### Requirement: 支持消息类型与完整性

工具 MUST 支持可完整发送的普通文字、图片及可定位原资源的合并转发，全部通过插件自己的 SnowLuma 连接执行。普通消息 MUST 保留文字与图片顺序，个人及全体成员提及 MUST 保留对象信息并转成不触发提醒的普通文本，不删除或编造对象、不额外拆消息。原卡片 MUST 复用源消息所指的已有内部资源，保留内部回复、提及及其他原有内容，MUST NOT 逐节点清洗或因插件不支持某种内部段而拒绝；卡片内部提及不再转换成普通文本。外层预览不承诺逐字相同，内部资源的客户端呈现不作未经验证的保证。评论 MUST 为独立消息，不塞入原作者节点。

普通消息的不支持段、丢失媒体和对象不可确认的提及 MUST 在发送前整条拒绝；原卡片缓存或资源不可取得时 MUST 明确拒绝，MUST NOT 自动改走摘要、拆段或节点重建。顶层卡片与其他内容混排仍 MUST 明确拒绝，不悄悄丢弃外层内容。源正文、卡片内部、群名和提及名称 MUST 仅作为数据，不能改变权限或路由。

#### Scenario: 文字和图片
- **WHEN** 合法调用转发可完整取得的普通文字、单图、多图或图文混排
- **THEN** 直连发送对应内容及原顺序，不以描述代替媒体，不调用宿主旧发送通道

#### Scenario: 合并转发卡片
- **WHEN** 可从可信源消息取得原卡片资源，即使宿主未能完整展开内部节点
- **THEN** 复用该资源发送一张卡片，不逐节点重建，不混入工具评论

#### Scenario: 存在无法支持的段
- **WHEN** 普通源消息包含不支持的文件、视频、语音、回复或丢失图片媒体
- **THEN** 发送前整条拒绝；此规则不用于剥除或拒绝原卡片内部已存在的内容

#### Scenario: 普通消息中的个人提及
- **WHEN** 普通文字或图片消息附有可识别的个人提及
- **THEN** 保留对象信息并转为普通文本，与其余内容顺序一致，不产生实际顶层提及

#### Scenario: 全体成员提及
- **WHEN** 普通消息附有可确认的全体成员提及
- **THEN** 仅发送表示全体成员含义的普通文本，不生成提醒全群的段

#### Scenario: 提及缺少显示名称
- **WHEN** 普通消息提及对象明确但没有源显示名称
- **THEN** 使用源对象标识，不虚构昵称或查询目标群成员补全

#### Scenario: 嵌套节点中的提及
- **WHEN** 原卡片内部或嵌套卡片含个人、全体成员提及或回复
- **THEN** 作为原资源的一部分保留，不逐段改写，不将内部提及提取为目标群顶层提醒

#### Scenario: 提及对象不可确认
- **WHEN** 普通消息中的提及既不能确认为全体也没有可用个人标识
- **THEN** 发送前整条拒绝，不把缺失标识猜成全体；不扫描原卡片内部套用此规则

#### Scenario: 显示信息不能变成消息指令
- **WHEN** 普通消息的提及显示名称或本次评论包含协议语法、命令或提示指令
- **THEN** 按普通文本发送，不转成消息段或改变路由

#### Scenario: 原资源不可用
- **WHEN** 源消息缓存缺失、资源标识缺失或可确认资源不可读取
- **THEN** 明确说明不可用，不用源消息 ID 猜造资源 ID，也不退回节点重建

#### Scenario: 顶层卡片混排
- **WHEN** 源消息含原卡片以及额外顶层文字、图片或提及
- **THEN** 明确拒绝不支持的混排，不只发送卡片并声称整条已完整转发

### Requirement: 真实发送与自然上下文

转发与评论 MUST 由插件直连 SnowLuma 执行，并以真实平台投递结果和目标消息 ID 报告给源群 Maisaka；WebSocket 写入成功、动作受理或内部标识 MUST NOT 被视为发送成功。插件 MUST NOT 调用适配器公开 API、独立转发服务或宿主旧发送通道作替代，也不注册第二个同路由发送网关。目标群宿主消息记录及 Maisaka 历史同步不属于本工具保证，MUST 明确公开该限制；MUST NOT 追加摘要、直接写宿主数据库、假造入站消息或重复发送来补偿。平台投递失败 MUST NOT 报告成功。真实目标消息 ID MUST 与源消息及资源 ID 区分。

#### Scenario: 成功发送可读
- **WHEN** 源消息和非空评论获得平台成功回执并完成结果落账
- **THEN** 源群工具结果包含两条真实目标消息的状态与 ID；QQ 目标可见性可独立验收，不将目标群 Maisaka 历史可读性当作已保证事实

#### Scenario: 目标冷会话
- **WHEN** 目标群没有活动 Maisaka 运行时
- **THEN** 不为转发创建或唤起目标 Planner；按合法平台目标发送，明确不保证宿主历史同步

#### Scenario: 服务不可用
- **WHEN** SnowLuma 连接不可用，或发送请求结果不确定
- **THEN** 如实区分发送前拒绝与结果未知，不改用其它通道或另一个平台动作补发

#### Scenario: 自发事件回流
- **WHEN** 所用端点开启上报自身，转发后出现机器人自发事件
- **THEN** 不把该事件单独当作可靠回执，不据此承诺历史同步，也不触发本插件再次转发

### Requirement: 可选评论固定延迟

`comment` 缺省、空或全空白时 MUST 仅转发，不等待评论延迟。非空评论 MUST 经同一受控账号的直连路径发送，内容只来自本次工具参数，按普通文本另发。源消息 MUST 先得到成功回执并持久登记，再等待固定至少 0.5 秒；评论提交前 MUST 重新确认插件未卸载、总开关开启、两级白名单允许、连接与账号仍匹配，并先持久登记评论发送占位。MUST NOT 在重启、重连或重复调用时自主补发评论，MUST NOT 使用随机时长、模型参数或配置覆盖延迟，不再次调用目标群 Maisaka 生成。源失败或未知 MUST NOT 进入评论。

#### Scenario: 非空评论
- **WHEN** 源消息成功落账、非空评论存在且评论发送前复验通过
- **THEN** 固定等待 0.5 秒后发送该评论，发送前持久占位，不唤起目标群

#### Scenario: 空评论
- **WHEN** comment 缺省、为空或全空白
- **THEN** 不等待、不登记评论发送占位、不发送评论

#### Scenario: 转发失败
- **WHEN** 源消息明确失败或结果未知
- **THEN** 不发送评论，不伪记源成功

#### Scenario: 等待期间客户端退出
- **WHEN** 源已成功，但插件退出或连接失效，尚未提交评论发送
- **THEN** 不定时续发评论；源投递事实保留，未完成评论按部分成功报告，重载或重连不补评论

#### Scenario: 等待期间切换连接配置
- **WHEN** 源已发送后直连地址、凭证引用或账号条件发生变化
- **THEN** 本次未提交的评论停止，不移到新的连接身份继续发送，保留原账号的源投递事实

### Requirement: 持久防重与不确定结果

自动判断产生的工具调用和对话调用 MUST 共用本插件自己的持久投递事实，状态只存于宿主授予本插件的数据目录。唯一身份 MUST 仍为账号、源群、源消息 ID、目标群；评论内容、请求标识、连接或进程变化 MUST NOT 绕过防重。源和评论发送前 MUST 各自持久占位，同一投递并发或重启 MUST NOT 导致重复发送。源成功但评论失败 MUST 保留已投递事实，重复工具调用 MUST NOT 重发源消息或自动补评论。只读结果查询 MUST NOT 触发发送。

发送结果不确定、发送后落盘失败、进程中断和网关回执不足 MUST NOT 降级成明确未发送；核实前 MUST 阻止重发，不承诺跨平台发送与本地存储的原子恰好一次。只有已证明未产生发送副作用的失败才允许后续显式新尝试。成功及未知事实 MUST NOT 按时间或容量静默清除。升级 MUST 保留本插件旧成功及待核实记录的阻断作用；本插件只允许单实例持有其账本。账本不可用、恢复失败、服务权威状态尚未核对或升级历史无法确认时 MUST 关闭发送，不读其他插件的账本。历史核对 MUST 只针对状态类证据（服务收据、主库以外的数据库与归档、孤立伴随文件、链接文件及其子目录内同类证据），MUST NOT 因插件自身的源码、文档、配置或缓存文件而关闭发送。

#### Scenario: 跨重启重复调用
- **WHEN** 成功投递后重启插件或重建连接，并以新请求标识或不同评论再次调用同一投递
- **THEN** 返回已有结果，不发送源或评论

#### Scenario: 评论失败
- **WHEN** 源已确认发送而评论失败或未通过发送前复验
- **THEN** 返回部分成功，保留源目标 ID，不重发源消息

#### Scenario: 结果未知
- **WHEN** 请求可能已到 SnowLuma 但回执丢失，或恢复出未完成的源/评论发送记录
- **THEN** 相应阶段保持待核实，阻止重发；源成功事实不因评论未知被抹除，只读查询不发送

#### Scenario: 同消息不同目标
- **WHEN** 源消息已发往 A，随后合法调用请求 B
- **THEN** 使用不同投递身份独立校验，不因 A 的记录阻止 B

#### Scenario: 旧账本迁移
- **WHEN** 本插件原账本仍是完整权威，包含成功或不确定记录
- **THEN** 启用直连前验证并保留其阻断作用，不要求迁移到独立服务，不当作空历史

#### Scenario: 服务历史尚未核对
- **WHEN** 本插件目录存在服务绑定收据、旧账本归档、主库以外的数据库或无法解释的状态类证据，或不能确认原账本是否完整
- **THEN** 关闭发送并提示人工核对，不凭“零迁移”承诺忽略服务投递事实，不创建空库、不自动回迁或删除切换证据

#### Scenario: 插件自身部署文件不构成历史证据
- **WHEN** 状态目录同时存放插件源码、文档、配置或缓存（宿主把 `data_dir` 指向插件目录）
- **THEN** 账本按既有成功与待核实事实正常打开并继续阻断重发，不因这些部署文件而关闭发送

#### Scenario: 发送前后账本失败
- **WHEN** 发送前占位失败，或取得真实成功回执后终态落账失败
- **THEN** 前者不发送；后者报告已知真实目标 ID 和未落账限制、停止后续阶段，已有占位阻止重发，不声称完整成功

#### Scenario: 同一数据目录重复加载
- **WHEN** 另一插件实例仍持有同一账本的独占使用权
- **THEN** 新实例拒绝启用发送，不恢复或修改另一活实例的在途记录

### Requirement: 结果与生命周期

工具 MUST 等待本次源发送及所请求评论的实际结果或有界超时，维持完整成功、部分成功、已转发、发送中、拒绝、明确失败、结果未知及账本不可用的区别，报告已取得的真实目标 ID 与错误阶段。动作仅受理、连接断开或本地任务取消 MUST NOT 被宣称为发送成功或已确定未发送。评论结果未落账时 MUST NOT 声称其结果已可靠保存。

关闭插件、卸载或权限收缩时 MUST 阻止尚未提交的源或评论动作，并在实际提交前按最新配置复验。已提交动作 MUST 按真实结果或未知保守处理，MUST NOT 因本地取消而登记可重试失败。卸载 MUST 只取消和有界等待本插件自己的任务、关闭自己的连接、释放自己的账本；超时 MUST 告警定位未退出工作，不能影响现有适配器或其他 WebSocket 客户端。重启或重连 MUST 不自动续发源或评论。

候选类型移除 MUST 取消尚未发起的失效自动判断；分享标准更新 MUST 不追溯已提交判断。日志 MUST 能定位源消息、目标群和阶段，不记录凭证或原文。

#### Scenario: 评论等待期间关闭
- **WHEN** 源已成功，评论尚未提交时关闭插件或撤销权限
- **THEN** 不提交评论，源结果仍报告成功投递，整体如实报告部分成功

#### Scenario: 等待真实结果
- **WHEN** 目标发送仍在进行
- **THEN** 工具不提前返回完整成功；超时报告实际已知事实或未知，不把动作受理当成回执

#### Scenario: 等待期间移除候选类型
- **WHEN** 候选仍在等待可读性或目标名称，且其类型被移除
- **THEN** 不再提交判断，不影响其他合法候选或整体取消已有平台副作用

#### Scenario: 唤起前修改标准与目标
- **WHEN** 自动判断尚未提交时标准或白名单更新
- **THEN** 唤起前使用最新标准和合法目标，必要时省略旧名称，不携带过期授权

#### Scenario: 已提交的判断不追溯重写
- **WHEN** 判断已经交给宿主后才修改配置
- **THEN** 不宣称旧判断已撤回，也不为同一候选再唤起；之后实际工具调用仍按最新权限校验

#### Scenario: 远端撤销竞态
- **WHEN** 源或评论等待连接、只读核验或发送排队期间发生卸载、关闭或权限收缩
- **THEN** 提交前复验失败就不提交、报告明确未发送；已经进入发送提交且无法证明未发时报告真实结果或未知，不声称已远端撤回

#### Scenario: 卸载与其他客户端并存
- **WHEN** 插件卸载时同一 SnowLuma 服务端还连接了适配器或其他客户端
- **THEN** 仅关闭本插件连接；残留任务按源消息、目标群和阶段告警，不注销 QQ 账号或关闭其他客户端

## ADDED Requirements

### Requirement: 退役实现与活跃路径隔离

旧独立服务及其专属测试 MUST 保留为可追溯历史，并退出插件加载、运行、部署说明及默认验证范围。活跃插件 MUST NOT 导入历史服务控制协议、启动其服务器、连接其 HTTP 接口或将其作为故障备用；历史保留 MUST NOT 被解释为维护两套可部署产品。旧归档的真实联验未完成状态 MUST 保留，不因返工、复制历史或离线测试通过而宣称已联验。操作者 MUST 能区分活跃验证命令与历史资料。

#### Scenario: 新插件正常加载
- **WHEN** 只提供插件声明的依赖和合法直连配置
- **THEN** 插件不要求安装或启动历史独立服务，历史实现缺少运行环境不影响活跃工具注册和验证

#### Scenario: 直连故障
- **WHEN** SnowLuma 直连失败而历史代码仍存在
- **THEN** 如实拒绝或报告未知，不导入或启动历史通道

#### Scenario: 默认验证与历史保存
- **WHEN** 执行公开的活跃测试命令或查看部署入口
- **THEN** 默认只验证和说明直连插件；历史代码与测试可追溯保留，但不被收集为活跃服务功能或暗示仍需部署
