# 直连 SnowLuma 返工执行任务

本文件保存阶段三细化的任务及阶段四执行结果。55项离线任务和八组独立 Spec／Standards 验收均已完成；复选框不表示真实 QQ 联验、部署或主规格同步已完成。需求以本变更三份 delta specs 为准，实现取舍以 `design.md` D1–D10 为准；若后续事实核实改变产品范围、直连可行性或设计，停止相关工作，走需求对齐或规划修订，不在任务中暗改约定。

执行约定：

- 八个 `##` 章节是阶段四执行组，按 **1 → 2 → 3 → 4 → 5 → 6 → 7 → 8** 串行推进；每组验收通过后才进入下一组。任务所列依赖还包括本组开始前所有组已通过，组内按编号执行。
- `seam` 表示公共测试入口：模块导出、插件公共方法、协议或命令入口。同组相同入口合并说明；所有任务继承本组入口，另有说明时使用任务自己的入口。不直接调用 `_call`、`_identity_verdict`、`_send_allowed` 等私有方法来代替行为验收。
- 新模块和测试文件名是设计落点，不声称当前已存在；第 1 组先明确公开接口与证据，再在已确认入口编写行为测试。复用旧实现不等于继续从 `service/` 或历史区导入。
- 第 1 组的只读核实来源按 2026-10-02 用户授权调整为 `arclinux` 部署机上的 MaiBot 宿主源码与已部署适配器源码（`arcwsl:~/github/REFERENCE/` 不可达，不作为阻塞条件）；适配器是客户端实现，其证据不能当作服务端实现。SnowLuma 网关服务端源码不可得，凡只能由其确认的结论必须显式标注「未复核」并进入待确认清单，不得用既有报告转述冒充复核，未复核事实按 design D10 处理。不读取部署机凭证、运行配置、`data/snowluma` 运行目录或真实数据。
- 每项实现包含相应入口测试；只有测试及所列证据通过才勾选。第 1 组是只读契约核实，不要求向真实端点发送探测。测试使用合成消息、假凭证和临时数据目录，不读取真实凭证、运行配置、消息或账本。
- 组内只运行受影响的活跃测试，保持测试入口可加载；未完成组合根切换前，不为让旧服务测试通过而恢复旧发送通道。安装验证依赖前先告知，使用 `uv --no-project`，不安装全局依赖。
- 历史内容在首次改写相关原文件前按 1.7 留存完整基线，第 7 组再完成最终隔离。禁止不可逆删除，禁止 Git 写操作，禁止部署、发群或迁移真实账本。

  - seam：SnowLuma 对外 WebSocket 握手和 OneBot 动作请求/响应协议；仅查只读源码与公开文档，不连接真实端点。

  - seam：OneBot 群发送动作、源消息查询响应与消息段协议。
  - 依赖：1.1、1.2；材料样本只用合成数据，不向真实端点探测。

- [x] 1.4 冻结真实目标回执与失败分类证据（服务端契约未复核）

  - seam：现有 `OneBotTransport`、`SnowLumaGateway.prepare_source/send_source/send_comment`、材料导出、`open_ledger`/`DeliveryLedger`、`deliver_forward`、`render_forward_result` 的活跃继任接口。

## 2. 最小配置与插件依赖

输入：第 1 组契约、D2。输出：受控直连配置、默认安全行为和插件依赖声明。

本组公共 seam：`CourierPlugin.build_default_config()`、配置导出模型、`config.toml`、`_manifest.json`，以及 1.6 确认的连接描述解析导出。测试复用 `tests/test_config.py`、`tests/test_plugin.py`；仅解析配置不建立网络连接。仍被过渡代码导入的旧类型不能提前删除造成测试入口无法加载，最终移除见第 7 组。

- [x] 2.1 增加最小直连配置并保持业务默认值一致
  - 验收：`[snowluma]` 只含默认空的连接地址和凭证环境变量名；模型、样例及配置界面字段一致，配置版本按宿主规则提升。默认总开关关闭、自动开启、候选仅 `forward`、白名单为空、标准原文一致；无新增延迟/概率/超时配置。
  - 依赖：1.6。

- [x] 2.2 校验直连地址的协议与信任范围
  - 验收：合法回环/私有/链路本地 `ws` 与证书保护的 `wss` 可解析（主机名在建连前解析确认，解析出公网地址或失败即拒绝）；公网 IP 字面量的明文 `ws`、非 WebSocket 协议、URL 用户信息/凭证查询/片段、未指定监听地址均拒绝。错误不回显带凭证的输入，测试不真实解析或访问线上端点。
  - 依赖：2.1、1.5。

- [x] 2.3 解析凭证引用而不复制凭证值
  - 验收：连接描述只保存环境变量名；缺失、空值和非法引用有明确原因。假凭证值不出现在配置导出、对象公开表示、日志或工具结果；不读取其他插件文件、不执行消息提供的环境变量名。
  - 依赖：2.1、2.2；真实值只由建连入口按名读取，传输验证见 3.2。

- [x] 2.4 退役旧服务配置而不丢失历史识别线索

  - 依赖：2.1、1.7。

- [x] 2.5 保持插件清单依赖和能力最小化
  - 验收：网络依赖仅在 `_manifest.json` 按既有声明结构提供，版本与 1.5 一致；不新增 `api.call`、`send.*`、`chat.open_session` 或反向监听能力。默认配置与工具声明可读取，未配置直连不要求独立服务依赖流水线。
  - 依赖：2.1–2.4；完整 `on_load` 不联网验收在 6.1，避免提前依赖未接入的组合根。

## 3. 直连传输与响应隔离

输入：已核实协议、最小连接描述、D1–D3。输出：不依赖独立服务的有界传输。

本组公共 seam：活跃 `snowluma_transport.py` 对 `OneBotTransport` 的实现，使用 `get_login_info`、`get_msg`、`get_group_list`、`send_msg` 和公开关闭入口驱动，按 1.6 最终导出为准。通过本地模拟 WebSocket 观察线路动作、连接数及关闭；计划测试落在 `tests/test_snowluma_transport.py`，不从私有接收循环取断言。

- [x] 3.1 提取独立于服务配置的传输与合成测试端点
  - 验收：模块可在无真实 SDK/服务配置下导入，创建对象不联网；公开只读动作能与本地模拟端点匹配请求响应。测试服务器不实现真实 QQ 发送，活跃导入不指向 `service/` 或历史区。
  - 依赖：2.5、1.6；复用现有传输和替身能力，不复制另一套业务状态机。

- [x] 3.2 实现安全握手与凭证失败处理
  - 验收：只连接配置目标，以假环境变量凭证完成本地认证；缺凭证、认证失败、证书不可信均无发送动作。模拟重定向目标收到零请求/零凭证；异常消息含认证头时对外只报告安全类别。
  - 依赖：3.1、1.5。

- [x] 3.3 实现动作关联及事件无副作用处理
  - 验收：群消息/心跳/自发事件先于响应时不完成动作；缺失/错误 `echo`、伪装事件和非法响应不伪报成功。实际线路关联标识区分运行实例、连接和动作；空闲期间持续消费事件而不生成动作或聊天缓存。
  - 依赖：3.1、3.2。

- [x] 3.4 验证多客户端并存与迟到响应隔离
  - 验收：两个本地客户端并存时，动作返回各自预期结果；人为注入另一客户端、已超时动作或旧连接响应不污染当前结果。关闭一个客户端后另一个仍能完成只读请求，未发送注销账号或服务端控制动作。
  - 依赖：3.3；通过公共传输和模拟服务端观测，不把截图当此项测试结果。

- [x] 3.5 实现包含排队和握手的动作绝对期限
  - 验收：注入时钟推进到 10 秒后，排队、握手或等待响应中的动作有界结束；持续无关事件不延长期限，不额外叠加原传输 30 秒。超时前尚未提交和提交后无回执的结果可区分，不使用真实长时间睡眠。
  - 依赖：3.3。

- [x] 3.6 限制帧与待决状态的资源占用
  - 验收：并发公开调用在模拟端点最多出现一个待决动作；超过 4 MiB 的消息按 D3 关闭本连接，可能已发送的动作保持未知。持续事件输入不产生随事件数量增长的待决表或任务数量，其他测试协程仍可推进。
  - 依赖：3.3、3.5；八个在途工具投递的入口限额在 6.7 验证。

- [x] 3.7 区分写入前失败与写入不确定并禁止重放
  - 验收：在公开动作调用下分别注入握手失败、排队取消、开始写入后断线和无响应；仅有证据未提交者报告未提交，可能写出者未知。后续独立只读调用可重建连接，但旧源/评论帧发送计数不增加，旧连接身份失效。
  - 依赖：3.4、3.5；不通过断言私有标志替代线路发送计数。

- [x] 3.8 实现幂等且有界的连接关闭
  - 验收：公开关闭可重复调用，正常关闭结束本实例接收及待决调用；不合作的接收/关闭替身不能导致无界等待。已提交请求取消保持未知，其他客户端不受影响；所有清理路径不打印原始敏感异常。
  - 依赖：3.5–3.7；组合根共享 5 秒总预算在 6.9 验证。

## 4. 可信源准备与统一材料、回执

输入：直连传输、已核实的源/目标/材料协议、D4–D5。输出：活跃直连执行入口及单一材料与回执语义。

本组公共 seam：活跃 `snowluma_client.py` 的 `prepare_source`、`send_source`、`send_comment` 及关闭契约；材料导出复用 `build_send_material`/`is_forward_card`，OneBot 侧按 1.6 确认的 `build_source_material` 继任入口。计划测试落在 `tests/test_snowluma_client.py`，材料回归复用 `tests/test_forward_precheck.py`；网关替身只模拟公开动作返回。

- [x] 4.1 建立可信账号、目标和源消息的只读准备
  - 验收：按 1.2 的对应规则查询同账号源消息；错账号、错群、私聊源、无法映射、目标不在群名册或目标等于源群均拒绝，发送计数为零，不回显越权正文。准备成功也不发送，账本身份不因平台查询标识变化而重写。
  - 依赖：3.8、1.2、1.6。

- [x] 4.2 复用单张原卡片资源而不展开内部内容
  - 验收：唯一顶层卡片形成一个原资源引用；含内部回复/提及/未知段仍不递归清洗或上传节点。资源缺失、缓存缺失、多卡片及卡片与其他顶层内容混排整条拒绝；源消息 ID 不作为资源 ID，评论不混入卡片。
  - 依赖：4.1、1.3。

- [x] 4.3 收敛普通文字与提及的完整转换
  - 验收：个人有名/无名、全体提及按既定文本形式输出，顺序与换行不变、不产生顶层 `at`；压平控制字符而不截断或虚构对象。对象不明和不支持段整条拒绝，源对象不被原地修改，协议样式文本不成为动作。
  - 依赖：4.1；复用共享提及函数，不另写一套显示规则。

- [x] 4.4 保留安全图片重放与图文顺序
  - 验收：1.3 核实的单图、多图及图文混排样本完整形成发送材料，图片不变成描述；缺媒体或非法路径/任意内网地址使整条拒绝，测试观测本机文件及非允许地址访问为零。仅宿主材料可恢复不能替代远端可重放性核验。
  - 依赖：4.1、4.3、1.3；不能以全部图片拒绝作为通过。

- [x] 4.5 统一源与评论的单次固定动作
  - 验收：每次源执行或非空评论只产生一个已核实群发送动作，路由只取可信目标；评论为单个普通文本段，不解析协议语法。空白评论不做平台查询/发送；失败后无替代动作、适配器 API 或旧通道调用。
  - 依赖：4.2–4.4。
