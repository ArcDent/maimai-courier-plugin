## Context

动机与实测依据见 proposal.md - Why 与 ADR 0011（`docs/adr/0011-nested-card-rejection.md`），
行为契约见本变更两份 delta spec。与实现相关的现状：

- `snowluma_client.prepare_source` 的卡片分支已经会按源消息卡片标识做
  `get_forward_msg` 展开查询，再交 `send_material.build_card_nodes` 构造节点；
  嵌套 forward 段目前随节点 content 原样深拷贝提交。
- `auto_entry.run_auto_entry` 只有宿主 `ctx` 能力，没有任何直连通道；预搜索需要
  从组合根注入。
- `plugin.py` 组合根在工具路径惰性创建 `SnowLumaClient`（含连接解析、旧连接替换
  竞裁）；自动路径目前不创建任何客户端。
- 固定七动作、一次投递最多一次源发送、四字段账本键与防重状态机都不变。

## Goals / Non-Goals

**Goals:**

- 发送前类型检查单点判定「卡片内容含嵌套内层卡片」并整条拒绝（固定对外措辞）。
- 自动入口对合并转发候选做只读预识别，命中不唤起；查询失败放行。
- 判定族按「可扩展的一类检查」组织，后续类型沿同一判定点与结果面加入。

**Non-Goals:**

- 不阻断其它已实测有问题的类型（`poke` / `market_face` 拒收、`xml` / `share` /
  `contact` 作节点内容时回执序列为 0）：本轮只收嵌套一种，其余记录待后续变更。
- 不实现「递归展开拍平保内容」路线（未来选项，需重新联验）。
- 不改普通文字 / 图片路径、不加配置开关、不动账本与防重。

## Decisions

### D1 独立类型检查模块，判定族单点定义

新建根模块 `type_check.py`：单点导出卡片内容类型检查（输入为 `get_forward_msg`
展开结果的节点序列，输出为拒绝原因或空），当前只含「节点 content 含其它合并转发
卡片」一种；reason 码与固定对外措辞同模块定义。模块只做纯判断，不 import
transport / client / auto_entry，依赖方向保持单向。

- 备选 A：判定放 `send_material.py`——违背该模块「纯材料构造」的职责，且类型族
  增长会把材料模块撑成检查模块。
- 备选 B：判定放 `snowluma_client.py`——类型知识离开协议材料边界，自动入口的
  预搜索要反向依赖客户端内部，`forward_precheck` 一类的本地模块也无法复用。

### D2 工具路径拒绝点：准备阶段展开之后、节点构造之前

`SnowLumaClient.prepare_source` 卡片分支在展开查询成功后先做类型检查，命中即
`PrepareRejected(reason, 固定措辞)`，不进入 `build_card_nodes`。节点构造保持
「给定素材就构造」；检查属于编排决策，由客户端编排调用，不在材料函数内部拒绝。

### D3 客户端只读缝隙：与工具路径同一读取序列

`SnowLumaClient` 新增只读方法（名如 `card_content_rejection(message_id) -> str | None`）：
`get_msg` 校验并取平台卡片标识 → `get_forward_msg` 展开 → 交 D1 判定。命中返回
原因，未命中或查询失败均返回 `None`（放行）。

- 用 `message_id` 而非宿主载荷里的卡片标识：与工具路径同一序列，标识经平台验证，
  不信任宿主载荷（阶段一决策）。
- 查询失败与「确认无嵌套」都返回 `None`：自动入口只关心是否命中，失败即放行；
  工具路径本来就会独立复判，不会因预搜索放行而漏拒。

### D4 自动入口注入：组合根负责只读客户端

`auto_entry.run_auto_entry` 增加可选参数 `presearch: Callable[[ForwardCandidate], Awaitable[str | None]] | None`；
`None`（测试或未注入）表示跳过预搜索。组合根 `plugin.py` 注入的 callable 内部：
仅对 `message_type == "forward"` 候选调用 D3 方法；需要客户端时复用工具路径的
惰性创建口径（当前配置解析连接、失败即跳过），不新增第二种连接管理。

- 复用同一客户端而非新建只读实例：单端点单会话串行的既有约束不变；自动创建的
  客户端后续工具调用可直接复用（连接相同不触发替换）。
- 生命周期与工具路径创建的客户端一致：卸载只结束在途请求，不新增关闭面。

### D5 预搜索在自动流程中的时机

`run_auto_entry` 顺序：可读性确认 → 配置初检 → **预搜索（新增）** → 目标名称
查询 → 提交前配置复验 → 唤起。命中返回 `WakeOutcome(triggered=False, reason=<可定位原因>)`，
由组合根记录日志。去重登记已在观察 Hook 同步完成，预搜索不改变去重语义；同一
消息在去重窗口内最多触发一次预搜索。

### D6 测试策略

- `type_check` 纯函数：嵌套 / 非嵌套 / 多层 / 畸形结构 / 未来类型扩展位。
- 客户端：prepare 分支嵌套拒绝；只读缝隙命中 / 未命中 / 查询失败放行（假 transport）。
- `auto_entry`：注入命中 → 不唤起；注入失败 → 照常唤起；非 forward 候选不查询；
  无注入 → 跳过。
- 组合根：预搜索 callable 的注入与无客户端时跳过；卸载预算不回归。
- acceptance（真实 aiohttp 回环端点）：嵌套卡片的工具调用全链拒绝 + 自动候选预
  识别跳过；既有卡片全链用例改新契约。

## Risks / Trade-offs

- [自动入口首次依赖直连端点] → 只读、fail-open；端点不可用时行为与现状一致
  （照常给判断机会，发送时由工具路径拒绝）。
- [每个卡片候选多两次只读查询] → 与其它动作共用同一 10 秒有界预算与单实例串行
  锁；去重窗口保证同一消息窗口内最多一次；卡片类消息频率低于普通消息。
- [含嵌套卡片从「发出空壳」变为「明确拒绝」，群友可能感知为功能回退] → 固定
  措辞说明原因，README / CHANGELOG 明示变化；未来拍平路线联验通过可再评估。
- [本轮只覆盖一种类型，其它已实测不可靠类型仍会放行] → 模块按族组织，任务清单
  预留扩展位；不在本次静默扩范围（扩范围需各自联验证据）。
- [预搜索与工具判定分处两个时点] → 源消息不可变，两次判定输入都是平台展开结果，
  无幂等风险；预搜索结论仅用于「是否唤起」，权威判定永远在发送前。

## Migration Plan

无配置、账本与动作迁移：部署即生效。回滚即还原本次代码与文档（行为回到「嵌套
原状提交」）。文档同步（AGENTS.md、README、CHANGELOG、API 目录实测记录、联验
清单 U6）随实现任务一起完成，不单独留尾巴。

delta 中保留的「嵌套卡片原样提交」场景是 openspec 校验规则要求的过渡指针
（MODIFIED 块不得丢弃主规格现存场景名）：本变更归档后主规格即含新场景名，
后续任何触碰该需求的变更可按规则移除该指针，不留永久双场景。
