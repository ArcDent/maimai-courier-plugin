## Context

动机与范围见 proposal.md；行为契约见 specs/cross-group-forward/spec.md。本项目目前只有术语和 ADR，无业务实现。原项目请求路径提供了 Host 发送及授权参考，但不能整包迁移其多轮查看流程。

已核实 MaiBot `a995cc4553c174fe00d2d44f8ce3d11746f920d4` 的 `src/plugin_runtime/capabilities/core.py`：`send.forward` 接收节点及 stream_id，支持 storage_message 和 sync_to_maisaka_history。`src/services/send_service.py` 的历史同步只直接追加到已有运行时，因此冷会话需要实际验证主程序后续历史恢复。SnowLuma 按 ID 转发不是 Host 发送的替代包装，不能据此承诺自然上下文。

## Goals / Non-Goals

**Goals:** 单一实际投递链；纯消息/权限逻辑可单测；源群自动判断只负责唤起；持久防重与评论部分成功不互相混淆。

**Non-Goals:** 复制整个 forwards/request、协议端直发后补注入、修改 Host 或网关源码、跨项目 import、全消息类型无条件支持、后台自动重试或评论恢复队列。

## Decisions

### D1 最小分层与独立运行

使用 plugin.py 承载 SDK 生命周期、一个观察 Hook、一个 Tool；config.py 只含总开关、自动入口开关和源/目标白名单。消息校验/发送准备、投递编排、持久状态分别放少量明确职责模块，不先复制旧包树，不引入多层 runtime/service 包装。默认总开关关闭、自动入口开启、白名单为空；0.5 秒为代码常量，不成为配置。自动去重/等待上限采用内部有界常量，非产品配置。

### D2 自动触发与工具发现

优先观察 chat.receive.after_process，复用可信 session_id；后台以源消息 ID 有限确认消息可读取（建议最多 10 秒），再调用源群 proactive.trigger 一次。保留有界消息去重（建议 10 分钟、最多 4096 项），不引入源群/目标群概率冷却。普通消息不触发，自身消息必排除。

意图只给源消息 ID、合法目标群 ID/可用名称及“判断值得分享才调用工具、可沉默”的说明，不伪造聊天内容。工具描述说明可自行查看，但不截获并改写模型工具调用来强制查看。没有可选目标则不唤起。群名按不可信显示文本处理。目标群不再 proactive.trigger。

### D3 可信来源与工具参数

公开工具仅接收 message_id、target_group_id、comment，ID 使用字符串避免模型/JSON 精度损失。源平台、机器人账号、源群来自宿主真实会话，查询后再次核对源消息归属，不能把 source_stream_id 从公开参数取得。拒绝自群目标、白名单外目标与不可确认路由。

实现前核实 SDK Tool 调用能否直接提供不可伪造的会话上下文；若不能，复用原插件最小的一次性来源绑定 Hook，而不是其查看/续轮状态机。该绑定仅做安全授权，公开参数仍为三个。保留 get_components 顶层 chat_scope 修正直至已验证 SDK 正确传递；不因简化删除授权。

### D4 主程序发送与内容完整性

在 SDK/Host 已支持的能力中选择：纯文字走正常文本发送，图片或混合文字图片走支持对应段的发送，合并转发走 send.forward。所有发送显式开启 storage_message、sync_to_maisaka_history，并请求详细发送结果；如 SDK 布尔归一化丢失 ID，只使用已验证的原始能力调用，不在异常后改走另一路重发。

工具内部按消息 ID 获取消息，发送材料只能用可验证的原文/媒体/节点，不能拿 processed_plain_text 描述冒充原图。合并转发逐节点递归预检，完整支持后再产生发送副作用；不支持的段使整个源消息拒绝，不能只丢掉该段。普通消息保持原形态，comment 独立为机器人文本消息。

群路由优先使用 Host 可信活动会话信息，并核实 platform、account、group 一致；禁止把首个历史 stream 当作当前路由。实现前完成发送契约验证：文字、图片、完整合并转发、陈旧 stream、目标冷运行时的存储/历史可见性均需证据。若现有 Host 无法满足最低支持范围或自然上下文，停止相关实现并报告兼容阻塞，不改成直发补注入、不私自扩展宿主范围。发送材料不全时明确拒绝是已定义的正常错误，而非宣称所有媒体已支持。

### D5 固定延迟评论与结果

有效发送顺序：权限/材料预检 → 持久登记发送中 → 源消息发送 → 立即保存源消息真实回执 → 非空 comment 等待 0.5 秒 → 重验总开关及目标权限 → 发送 comment → 保存评论结果并返回。

空白评论视为空。评论按普通文本发送；不执行内容，不额外生成。固定 sleep 从源发送成功之后开始，其他 IO 导致实际间隔更长不违反契约。源发送失败不进入评论段；评论失败返回部分成功，重复调用不重发源消息、也不补发评论。结果至少包含状态、源发送成功标志、可用的目标消息 ID、评论状态、错误阶段与中文原因；不把已排队当作完成。

### D6 持久防重与崩溃窗口

采用 Python 标准库 SQLite 在 ctx.paths.data_dir 下保存最小投递账本，无额外数据库服务。键为账号 + 源群 + 源消息 ID + 目标群；唯一约束配合短事务防并发。所有 SQL 参数化，不在网络等待期间持有事务。状态至少区分 sending、sent、failed、unknown；评论结果附属于源发送记录。

发送前先持久登记 sending，成功回执后立即登记 sent；明确“未发送”的失败才能登记 failed 并允许未来显式重试。超时、取消、回执丢失或重启遗留 sending 归入待核实，不能盲目重发；不自动重试。发送前持久化失败不发送，发送后持久化失败停止后续评论并报告待核实。该策略偏向避免重复，可能需要人工核实不确定记录；不能承诺外部协议和本地数据库的原子恰好一次。

成功记录不按 TTL 或容量静默清除。启动若状态库损坏/不可读，关闭发送并清晰报错，不能当作空库继续发送。备份/人工核对流程只文档化，自动化不删除用户数据。

### D7 生命周期与默认安全

插件持有并等待所有后台任务；卸载/总开关关闭取消尚未发送工作，发送结果未知保留状态，已成功发送不回滚。白名单热更新后在源发送前和评论发送前重新检查权限。自动入口关闭只停止自动唤起，不禁用工具。不要复用其他插件的任务集合、配置或持久状态。

### D8 工程与同步边界

实现阶段创建 manifest、三生命周期入口、中文 README、测试和类型检查；只声明实际能力，不凭空声明新 API。不安装全局依赖，验证使用 uv 临时依赖。AGENTS 写本插件规则，CLAUDE 必须软链接至 AGENTS。

实现阶段同步获准的 `.local/runbooks/maibot-plugin.md` 和清理失效链接/无关运维记录的 INDEX.md，注明原说明采集日期及需要重新核实的版本假设。加入私有排除后才能交给用户提交；本工作流不初始化 Git、不修改 Git 索引。若尚无仓库，记录待用户初始化后配置本地排除，不生成含敏感信息的材料。

## Risks / Trade-offs

- [Host 发送成功但历史同步未生效] → 单独验收活跃/冷会话与真实目标 ID；无法保证则阻塞发布，不增设注入后门。
- [媒体在源消息入库后丢失] → 只发送可完整恢复的材料，整条拒绝不支持内容，验收不得只靠 fake SDK。
- [崩溃后账本无法确认外部发送] → 持久发送中标记与人工核对，宁可暂停该键也不自动重复。
- [自动触发与原生 Planner 同时调用工具] → 同一持久唯一键统一防重，而非依赖 Planner 串行。
- [白名单群内容中的提示注入] → 不可信内容不获得调用上下文或目标权限；源消息归属与白名单始终由程序校验。

## Migration Plan

1. 两项目分别实施和测试；本变更不编辑旧仓库。新插件初始保持关闭。
2. 用户备份旧配置与状态，明确旧状态不自动导入；切换后新账本只覆盖新插件观测的投递，不能承诺识别旧插件历史所有发送。
3. 部署已完整移除转发的复读插件，并确认旧独立转发插件同样停用；再启用麦麦搬运喵并填白名单。
4. 经用户授权在测试群验证转发、0.5 秒评论、两消息历史可见和重启防重。未经授权不实际发群消息。
5. 回滚先停新插件再恢复旧版本；同时运行新旧转发路径不属于可接受回滚。保留账本不自动删除。
