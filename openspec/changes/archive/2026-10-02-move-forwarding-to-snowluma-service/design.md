## Context

动机与范围见 `proposal.md`。依据已接受的 ADR 0004、0005：全部源发送和评论迁移到独立服务；宿主和现有 QQ 适配器不改；自动入口只唤起源群 Planner；原卡片内部不清洗；普通消息提及规则保留；不承诺目标群 Maisaka 历史。

当前可复用资产是三参数工具、一次性来源凭据、白名单判断、自动入口、注入时钟、结果渲染与 SQLite 防重语义。已有四字段投递身份不变。既有 `send.forward` 重建节点和 `host_send.py` 四通路不适用于新卡片执行。

核实基线与原文见两份研究报告：Host `a995cc4`、SDK `4d8e577`、SnowLuma `7726a38`；完整提交及源码指纹以研究报告为准。实现第一组必须重新固定准确版本，不凭缩写推断接口。网关确认存在 `get_msg`、普通 `send_msg` 的资源引用段和 `forward_group_single_msg`；当前部署版本及普通图片重放能力仍需只读核实与合成契约测试，禁止用线上发群来探路。

## Goals / Non-Goals

**Goals:**

- 让网络边界落在可信工具调用之后，保持模型决策、授权、原材料和平台发送的职责清楚。
- 以服务端唯一持久事实解决请求重放与进程重启；保留旧记录的防重作用，不追求平台与数据库间原子恰好一次。
- 对源和评论分别提交阶段授权，明确准备、已授权在途、已撤销和未知的区别；不把本地取消解释为远端已停止。
- 最大限度复用现有纯类型、时钟、普通提及转换和账本逻辑；服务进程不导入 MaiBot SDK。

**Non-Goals:**

- 通用 MCP 工具平台、任意 OneBot 代理、模型参数携带凭证或网络地址。
- 新增同账号发送网关、劫持现有适配器路由、直接写宿主数据库、发送后注入聊天历史。
- 多服务实例共享 SQLite、跨账号自动选择网关、自动重建失效卡片、自动重新发送未知结果。
- 迁移其他插件历史、默认执行部署或平台实测。

## Decisions

### D1. 专用异步 HTTP/JSON 客户端与服务，而非新增通用工具协议

MaiBot 侧仍注册静态三参数 `forward_message`；新增客户端把可信请求发送到同仓库的独立 Python 服务。服务通过自己的固定 OneBot WebSocket 连接访问 SnowLuma，不经现有适配器 API，也不要求现有适配器改配置。服务没有 Planner 或候选观察职责。

协议选 HTTP/JSON v1，客户端与服务器拟统一使用项目级锁定的 `aiohttp`，避免手写 HTTP 或新增第二种网络栈。新依赖只声明于项目环境，插件依赖实际装载机制在实施前核实；无法通过受支持机制装载时阻塞该实现，不退回全局安装。服务器入口放在本仓库 `service/`，HTTP 客户端放在 `remote_client.py`，纯协议/账本/材料共用代码按实际依赖迁入 `shared/`。这些是计划新增路径，不声称已经存在。

可选替代：复用适配器公开 API 不满足“新增独立服务器/客户端”的已确认选择；通用 MCP 会增加工具发现和授权面，本轮只有固定转发工具，无需引入。

### D2. 保留本地可信来源绑定，服务端重新核对源身份

`source_binding.py` 的宿主 Hook 凭据继续只在客户端消费，模型参数始终只有三项。客户端检查当前总开关、群聊来源、源/目标白名单和宿主可读的源记录，不再要求目标宿主会话具备正常发送路由，也不对卡片内部逐段预检。

服务端通过自身账号的 `get_msg` 重新定位源消息，核对实际源群、源消息 ID 和顶层内容。账号由部署绑定及网关登录身份决定，不采用模型输入。源已在宿主缓存但网关缓存失效时拒绝，不把宿主展开节点交给服务器重建。客户端不能提交任意正文、资源 ID 或媒体路径；只有本次 `comment` 是额外文本。

服务端拥有独立的源/目标许可上限，客户端白名单可进一步收窄，两者取交集。修改客户端白名单不能扩大服务端许可上限。已创建投递的认证所有者即使之后权限收缩，仍可只读查询其结果；查询权限不恢复发送权限。

### D3. 原卡片和普通消息采用不同材料策略，但都由服务发送

- 原卡片：从网关源消息中取得唯一顶层 `forward.data.id`，只接受该卡片单独存在的源形态。服务端固定调用普通群 `send_msg`，消息为单一 `forward` 资源引用段。内部资源不下载、不解析、不清洗、不重新上传；宿主原节点缺失或超过原插件递归上限不构成拒绝理由。顶层混排仍拒绝。
- 选择资源 ID 普通发送而不是直接调用 `forward_group_single_msg`：先固定并核实源资源，发送时不再次依赖按消息 ID 读取缓存，可以明确排除顶层额外提及或其他内容；网关仍重新编码外层预览，不保证外层展示完全相同。
- 普通文字/图片：服务器读取 OneBot 源段，验证仅有受支持的文字、图片及提及附属内容，保留段序；复用现有普通提及文本化的格式、控制字符压平和相邻文字归并语义。通过固定 `send_msg` 发送明确构造的文字/图片段，不直接整条重放带实际 `at` 的原消息。
- 普通图片使用网关已核实可重新发送的缓存媒体描述或受支持的可恢复材料。第一组核实具体字段及转发时效；不接受任意 URL、`file://` 或调用者本地路径，不自行实现通用下载器。不能安全恢复则整条拒绝；必须以单图、多图、图文和带提及图片契约测试证明最低支持范围。
- 评论固定为单个 OneBot `text` 段，不把字符串重新解析为协议段；不允许工具调用选择其他动作或消息类型。

选择重新发送文字/图片段，是为保持普通提及不提醒的既有行为；原卡片不应用这一转换。禁止“先走资源直转、失败后换重建或其他动作”的补发策略。

### D4. 准备、源授权、评论授权分离

以下均为本项目拟新增接口，不是声称宿主或 SnowLuma 已提供同名 API：

- `POST /v1/sessions`：建立认证客户端运行会话，返回服务启动代次、会话 ID、绑定账号及账本身份；同一认证主体同时只允许一个活动客户端实例。
- `POST /v1/sessions/{session_id}/heartbeat`：只续当前会话有效期，不更新权限、不激活准备或发送。
- `DELETE /v1/sessions/{session_id}`：注销会话并撤销其未消费阶段授权；已在途阶段仍保留结果处理。
- `PUT /v1/sessions/{session_id}/policy`：更新单调递增的客户端发送权限代次、总开关及源/目标许可集合；旧代次不能覆盖新代次，服务端仍与自己的权限上限取交集。仅自动分享标准或候选类型变化不属于发送权限代次更新。
- `POST /v1/forwards/prepare`：接收投递四字段、客户端请求 ID、会话/权限代次和本次评论。校验与取得材料后返回投递 ID、尝试 ID、有限有效的源授权挑战；不发送。
- `POST /v1/forwards/{delivery_id}/source`：客户端再次读取最新配置，确认仍允许后，提交绑定尝试和源阶段的单次挑战；服务器在进入平台调用前完成持久占位与最后校验。
- `POST /v1/forwards/{delivery_id}/comment`：仅当前尝试的发起客户端在源确认持久成功、等待至少 0.5 秒并复验最新配置后提交评论阶段挑战；不是重复工具调用可以自行补发的接口。
- `GET /v1/forwards/{delivery_id}`：返回权威状态及已知目标 ID；不执行或重试发送，不返回消息正文。
- `POST /v1/forwards/{delivery_id}/cancel`：撤销指定尚未消费的尝试/阶段授权，或返回已经开始/已完成的状态。注销客户端会话时同样撤销该会话全部未消费授权。

投递 ID 是四字段规范编码的稳定摘要；请求 ID、尝试 ID、会话 ID 与阶段挑战均不是投递唯一键。准备先在授权范围内检查既有阻断记录：已有成功、在途或未知时直接返回其状态，不因缓存失效而允许新发送。源与评论授权绑定不同阶段，包含尝试、会话、权限代次和到期时间，不能互用。服务端只接受已登记且内容匹配的单次挑战，重复执行请求返回原尝试结果，不开启新尝试。挑战正文和准备材料仅在内存短期存在。

准备有效期固定 30 秒、客户端会话心跳间隔 5 秒/失联到期 15 秒、已提交阶段挑战可开始发送的有效窗口固定 2 秒，均为代码常量、用注入时钟测试，不作为用户调概率或延迟的配置。评论挑战在源成功后生成；其准备有效期同为 30 秒，客户端提交时才进入短执行窗口。源已成功而客户端未提交评论时，服务器不自主续发。

源成功至评论提交之间，客户端按现有注入时钟等待固定 0.5 秒；服务端也用源回执时间检查最短间隔，过早提交拒绝而非排队定时发送。额外网络及落盘耗时只会延长间隔。服务重启使所有旧会话和未消费挑战失效，不能靠重新连接自动补齐评论。

### D5. 认证、传输与服务会话

客户端只持有专用服务凭证；OneBot 连接凭证仅在服务器环境中。客户端配置保存服务地址、凭证环境变量名及预期账本身份，不保存密钥明文。Bearer 凭证按客户端主体绑定单个账号和权限上限；所有投递/查询/控制接口均认证，并限制字段长度、请求体大小、并发及准备队列容量。

默认监听回环地址；跨主机使用校验证书的 TLS 或运维提供的受控加密隧道，不关闭证书校验。禁止 HTTP 重定向转交认证头。OneBot 连接地址固定配置，不来自请求。服务连接/重连后核实账号；账号改变立即使旧会话及未消费授权失效。

准备队列有容量上限，达到上限返回明确繁忙且不创建平台发送。限制常量在实施时依据合成负载测试确定，不能以静默逐出发送中/成功账本换取容量。返回结果及异常只包含安全错误码和阶段，不返回底层响应中的正文、URL 或凭证。

### D6. 远端撤销的线性化点与不可消除的网络竞态

客户端权限收缩先设置本地关闭/新权限代次，立即停止新授权，再发送策略更新与撤销；服务端按每个投递的锁对“撤销”与“开始平台发送”排序。

“开始平台发送”的边界是：平台连接可用、准备材料仍有效、源/目标权限与授权均通过最终复验，服务端已持久登记 `sending`，即将提交唯一平台 RPC。最终检查和开始交付必须在同一受控临界区；不能先校验、长期排队、之后不再复验。临界区内不持有 SQLite 事务等待网络回执。

- 撤销先完成：撤销未消费授权，记录明确未发送；迟到旧请求不能激活。
- 平台调用先开始：已属在途，不能因本地关闭假定未发。只读取得实际回执，失败证据不足即未知。
- 控制请求失联：客户端有界等待后报告“撤销未确认”，不伪称已取消；会话/挑战到期阻止尚未开始的工作。已进入平台调用的不因授权到期而抹去事实。

**这是分布式边界的公开语义，不承诺本地配置改变瞬间远端无在途副作用。** 无源授权、无评论授权的准备状态始终不发送；配置关闭后新提交授权被本地禁止。不得用更长后台自动重试掩盖控制失败。

客户端及服务器各自仅管理自己的任务，沿用有界退出和定位告警；HTTP 客户端断开不直接取消服务端已经开始的平台 RPC，服务端仍尝试完成落账。服务器退出时未能确定结束的 `sending` 留待下次启动恢复为未知。

### D7. 服务端唯一投递账本与尝试状态

服务端使用独占状态目录中的 SQLite，进程独占锁确保单实例；网络客户端不共享访问该文件。沿用 `DeliveryKey` 的账号、源群、源消息、目标群身份和 `LedgerStatus` 四态：`sending`、`sent`、`failed`、`unknown`。准备与会话属于有限控制状态，不伪装成已发送事实。

账本区分投递与尝试：投递表保存该唯一键的当前阻断事实及真实回执；尝试表保存尝试 ID、发起客户端、源/评论阶段状态、评论摘要及原执行结果。新尝试只可由新的合法工具调用在旧投递已明确未发送时创建。重复旧尝试无论请求 ID 如何重放都只返回旧结果。评论变化不能改变投递身份，成功投递不能开启新尝试。

源与评论均在平台调用前分别占位；评论阶段使用 `not_requested`、`pending`、`sending`、`sent`、`failed`、`unknown`、`skipped` 等封闭值，状态转换集中定义，不散落字符串判断。一次性评论挑战只发给源尝试所有者；重复工具调用不能获得补评论挑战。

启动恢复：源 `sending` → `unknown`；评论 `sending` → `unknown`；未提交的评论准备 → `skipped`；未消费的普通准备全部失效。`sent` 与 `unknown` 不按 TTL 清理。每次数据库写入独立短事务并明确回滚，不跨网络等待持有事务。

发送前占位失败绝不发送；源成功落账失败停止评论，保留本次内存回执供响应，同时永久阻断该在途键。若评论已知结果落盘失败，响应不能声称评论状态已经可靠保存。任意契约外结果或可能已发的失败均归未知，不因异常名称判断可重试。

客户端不再维护第二份新投递真相：`ctx.paths.data_dir` 仅保留旧账本归档与迁移绑定收据等本插件状态；服务端拥有自己的数据目录，这是独立服务对旧“所有投递数据只在 ctx.data_dir”假设的明确调整。账本核心和协议类型移入共享纯模块后复用，不能复制成客户端/服务器各一套状态机。

### D8. 回执证据与结果面

保留现有工具结果语义：`sent`、`partial`、`already_forwarded`、`sending`、`rejected`、`failed`、`unknown`、`ledger_unavailable`，以及 `success`、源 `sent/delivered`、`comment_status`、真实目标 ID 和 `stage`。传输受理成功不是工具成功；HTTP 超时与 OneBot 模糊失败不是明确未发。

研究发现网关在缺群序列时也可能返回本地不透明 `message_id`。网关接缝必须结合成功响应和受支持的只读目标消息查询，核实目标群、机器人身份及可证明的平台消息身份/群序列。所需具体字段在首组固定源码契约；缺失、查询不可核实或超出有界查询期则未知，不把非空任意 ID 当成证据。源确认后立即落账，再向客户端返回带评论挑战的结果。

SDK 工具 RPC 和插件调用等待都必须有界。客户端执行请求响应丢失后，仅查询同一投递/尝试；不得再次提交发送作为探测。已知服务端终态可返回，查询仍不可达则报告未知。查询可向同一活动工具调用返回此前已签发且未过期的评论挑战，但不为新的重复工具调用或新会话重新生成挑战；挑战已失效则报告源成功、评论未完成。未授权评论过期后登记为 `skipped`，不形成永久待发送队列。结果查询本身不发送、不自动补评论，也不从源资源 ID 推断目标 ID。

### D9. 最小变更与可测试边界

- 保留 `source_binding.py` 的凭据隔离、三参数声明和 `get_components()` 顶层群聊作用域修正。
- 保留 `auto_entry.py` 的候选分类、去重、有限等待、最新标准和源群主动判断行为；卡片分类与实际原资源可用性仍分离。
- `forward_precheck.py` 保留本地授权，但不再构建卡片节点或要求宿主目标发送会话；账号及目标平台可用性以认证服务核验为准。
- `forward_delivery.py` 改为客户端阶段授权/结果编排，复用时钟与结果渲染。源和评论仍只有两个发送接缝，真实平台发送只在服务端网关模块；`host_send.py` 原实现退出调用图，无 fallback。
- `send_material.py` 中普通消息的提及转换等纯逻辑按需复用；原卡片递归发送材料构建从该工具路径移除。不能因为卡片内部免检而放宽普通消息不支持段检查。
- `service/` 拆为协议入口、控制/投递协调和 SnowLuma 接缝；共享层只放实际共用的纯模型、账本核心与转换，不依赖 SDK。
- 测试复用既有 fake SDK、时钟与可控回执；新增 fake HTTP/OneBot 传输和实际服务本地回环测试，覆盖网络两端而不向真实群发送。生产静态检查扩展到新增服务、客户端与共享模块。

### D10. 配置与兼容边界

保留现有 `plugin.enabled`、`auto.*`、两级白名单；新增独立 `[service]` 连接配置（地址、客户端身份、密钥环境变量名、预期账本 ID、迁移确认标识）。服务端配置绑定 OneBot 地址、凭证环境变量名、账号、认证主体许可上限和独立数据目录。字段最终命名属于本项目设计，不冒充 SDK 已有元数据。

客户端配置版本随新增字段递增；旧配置补默认值不自动启用或扩大白名单。服务端只有在账号、账本、迁移状态和协议版本均一致时宣告可发送就绪。连接/准备控制超时用代码常量和注入时钟，不新增概率、随机延迟或业务冷却配置。

## Risks / Trade-offs

- [旧资源过期或源缓存丢失] → 明确不可用，不重建；平台调用之后才发现的模糊失败按未知处理，不伪称一定没发。
- [原卡片内提及行为无法修改] → 保留原内容，公开该变化，不额外产生顶层提及；普通消息仍文本化。
- [目标群麦麦未看到这次分享] → 属于已接受的不保证范围，不追加上下文或伪造入站记录。
- [本地关闭时远端已有在途授权] → 阶段授权、短有效期、撤销确认与未知结果共同表达，不承诺瞬时跨进程取消。
- [用户误连新的空服务器账本] → 预期账本身份与迁移绑定不一致即关闭发送，禁止按 URL 自动信任新数据集。
- [普通图片重放字段与版本不同] → 首组源码核实、合成载荷及最小媒体测试；验证失败阻塞对应实现和发布，不扩大下载能力补洞。
- [服务新增认证面与依赖] → 认证主体绑定账号、专用接口、TLS/隧道、环境变量密钥、项目级锁定；不向模型公开网络或动作选择权。

## Migration Plan

1. 在既有发送关闭、任务退出后，为本插件旧 SQLite 制作一致性快照；保留原库及备份，不读取其他插件数据，不复制运行凭证。
2. 服务首次初始化必须显式选择 `fresh` 或 `migrate`。已有安装只允许 `migrate`；缺旧库、状态来源不明或快照损坏均阻塞，不自动退回 `fresh`。
3. 离线导入工具以只读方式检查旧库完整性、schema、四字段键、记录数量和状态：`sent` 保留目标/评论回执；`unknown` 保留阻断；`sending` 转未知；明确 `failed` 保留为新显式尝试可用。与已存在服务记录冲突时不降低安全状态，无法无损合并则停止，不覆盖。
4. 服务保存生成的数据集 ID、schema 版本、快照摘要与导入统计；客户端在自身 data_dir 保存对应非敏感迁移收据，并将预期数据集 ID 配入连接设置。服务开启发送前同时校验绑定和权限。不得将完整历史通过普通发送接口随意上传。
5. 先在模拟环境验证旧成功/未知阻断、新请求重放、网络异常、源及评论状态；实际部署和 QQ 发群联验等待用户单独授权。升级后旧 `ctx.send.*` 投递路径完全禁用。
6. 备份整个服务状态目录的持久数据库与数据集元数据；临时材料不作为恢复后可自动发送的队列。恢复后失效所有会话/挑战，在途归未知。
7. 回滚先停止新客户端与服务器发送，离线导出包含新结果的旧 schema 兼容快照：所有不确定源状态保守阻断，源已发保留为已发，评论不自动补齐。核验数量和键覆盖后由用户切换；无法完成安全导出时保持关闭，绝不直接启用仅含迁移前历史的旧库。
