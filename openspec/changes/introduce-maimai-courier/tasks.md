## 3. 工具权限与完整内容预检

本组行为测试统一通过 `forward_message` 公共工具入口，观察宿主查询/发送调用和工具返回；工具声明通过注册入口检验，不直接测试私有函数。

- [ ] 3.1 声明 forward_message 的三个公开参数及群聊作用域。
  - 验收：声明仅含必填字符串 message_id、target_group_id 和默认空字符串的可选 comment；缺失、非法 ID 及不合类型输入返回具体原因且不发送，长字符串 ID 不经数值转换丢失精度。
- [ ] 3.2 绑定可信源会话并验证源消息归属。
  - 验收：私聊、非 QQ 范围、源群不在白名单、不同账号/源群消息、不可定位消息均被拒绝；伪造平台、会话及内部授权字段不能覆盖宿主来源，拒绝结果不泄露越权消息正文。
- [ ] 3.3 校验单一目标授权和可信路由。
  - 验收：自群目标、白名单外目标、不可验证或账号/平台不匹配路由均不发送；合法调用只选择指定群，不广播，陈旧历史 stream 不被直接当作当前路由。
- [ ] 3.4 实现普通文字、图片及混合内容的完整发送预检。
  - 验收：完整材料保持原有消息形态；缺失媒体、无法发送的段和仅有描述文本的图片在任何发送副作用前整条拒绝，原因可定位到内容或类型。
- [ ] 3.5 实现合并转发节点递归预检。
  - 验收：所有节点可恢复时准备完整聊天记录卡片；任一嵌套节点含不可用媒体或不支持的文件、视频、语音段时整条拒绝，不丢段、不以摘要替代，不把 comment 塞入原作者节点。
- [ ] 3.6 隔离正文、节点和评论中的不可信内容。
  - 验收：带伪造授权或路由指令的正文/节点无法改变源群与目标选择；comment 中命令或消息段样式按普通文本处理，不执行、不解析为可执行消息段。

## 4. 持久账本与并发防重

账本测试通过持久状态模块的导出接口执行，发送次数和返回状态通过 `forward_message` 验证；模块接口复用第 2 组的存储边界，具体签名在实现时确认，不为私有 SQL 辅助函数建立测试。

- [ ] 4.1 建立 data_dir 内的 SQLite 最小投递账本与唯一键。
  - 验收：键包含账号、源群、源消息 ID、目标群，不包含 comment；状态区分 sending、sent、failed、unknown 并保存评论结果；SQL 使用参数绑定，网络等待期间不持有数据库事务。
- [ ] 4.2 实现发送前持久占位和同键并发排他。
  - 验收：并发同键调用最多一次进入源发送，其余返回发送中或已存在结果；不同目标独立；发送前持久化失败时发送次数为零。
- [ ] 4.3 实现成功回执持久化及跨重启防重。
  - 验收：真实回执成功后立即保存 sent 和目标消息 ID；重开账本后同键即使 comment 改变也不发送源消息或评论；成功记录不因 TTL 或容量限制静默清除。
- [ ] 4.4 区分明确未发送失败与结果未知。
  - 验收：只有明确未发送的失败可标记 failed 并允许后续显式调用重试；可能发送成功的超时、取消或丢失回执返回待核实且阻止重发；两类情况均不启动后台自动重试。
- [ ] 4.5 恢复遗留 sending 并处理发送后落盘失败。
  - 验收：模拟进程中断后重启，遗留 sending 进入待核实而非可重试失败；发送成功后落盘失败不发送评论，保留已知回执用于报告，重复调用及重启均不盲目重发。
- [ ] 4.6 对损坏或不可读状态库实施安全关闭。
  - 验收：加载不可读/损坏数据库时关闭发送并输出明确原因，不视为空库继续、不覆盖或自动删除状态数据。

## 5. 正常发送、固定评论与真实结果

本组统一以 `forward_message` 为测试入口，检查 Host 正常发送调用、可控时钟、账本和返回结果；自然上下文的真实宿主验证在第 8 组执行。

- [ ] 5.1 接通唯一源发送链并保存真实详细回执。
  - 验收：权限和内容预检通过、持久占位成功后才发送；文字、图片和卡片使用第 1 组确认的对应通路，显式开启存储及历史同步；取得真实目标消息 ID，不以源 ID、资源 ID 或 bool 充当成功证据，不额外 context.append。
- [ ] 5.2 实现非空评论成功后固定等待 0.5 秒。
  - 验收：可控时钟证明先收到源发送成功回执并保存，再固定等待 0.5 秒，随后独立发送本次 comment；不在源发送前等待，不受配置或模型参数覆盖，不调用目标群 Maisaka 生成评论。
- [ ] 5.3 实现空评论及源发送失败的短路。
  - 验收：comment 缺省、空字符串或全空白时只发源消息且不调用评论等待；源发送明确失败或未知时均不发评论，明确失败不登记源发送成功。
- [ ] 5.4 保存评论结果并返回部分成功。
  - 验收：评论明确失败、取消或权限撤销时仍保留源消息 sent 和目标消息 ID，说明评论未完成的原因；评论回执未知不伪报成功；重复调用不重发源消息，也不补发评论。
- [ ] 5.5 统一真实工具结果并等待本次执行结束。
  - 验收：可区分完整成功、部分成功、已转发、发送中、拒绝、明确失败、结果未知；包含源发送成功标志、已取得的真实目标消息 ID、评论状态、错误阶段及中文原因；发送或评论尚未完成时不提前返回全部成功。
- [ ] 5.6 记录可定位且不含凭证的失败信息。
  - 验收：拒绝、源发送、持久化、评论各阶段故障均能定位源消息和目标群；日志与工具结果不输出凭证，失败发送不被记为成功历史，不生成额外摘要或评论副本。

## 6. 源群自动判断

本组统一通过处理后消息观察 Hook 输入事件，观察消息查询、源群 `proactive.trigger` 及工具调用；只使用第 1 组已核实的宿主公共契约。

- [ ] 6.1 筛选自动入口候选并保留原处理链。
  - 验收：仅白名单源群的非自身、非通知 QQ 合并转发成为候选；普通文字、图片、非 QQ 或非白名单来源不唤起；观察 Hook 不拦截或改写原消息处理。
- [ ] 6.2 实现消息可读取后的有限等待触发。
  - 验收：候选可读后才提供判断机会；未就绪时有限等待，超出内部上限后退出并记录可定位原因；不无限等待或伪造摘要，等待边界用可控时钟验证。
- [ ] 6.3 实现有界自动去重和无目标短路。
  - 验收：同一候选重复/并发上报只唤起一次；去重状态有内部时间和容量上限且不影响持久已投递记录；没有合法且不同于源群的目标时不唤起。
- [ ] 6.4 向源群提供可沉默的分享判断信息。
  - 验收：意图仅包含源消息 ID、合法目标 ID/可用名称及自主判断说明，群名作为不可信显示文本；可保持沉默或调用同一 forward_message，未展开卡片也可进入判断；不掷骰、不签目标群决策票、不强制查看续轮、不唤起目标群评论。
- [ ] 6.5 验证自动判断与群友请求共用投递防重。
  - 验收：自动判断和显式请求同时调用相同消息/目标时最多一次源发送；普通文字/图片虽不触发自动入口，仍能通过合法工具调用发送。

## 7. 生命周期、取消与热更新

本组通过 SDK 生命周期、配置更新入口、观察 Hook 和 `forward_message` 验证，不直接操纵私有任务集合。

- [ ] 7.1 跟踪并等待本插件创建的全部后台任务。
  - 验收：卸载取消尚未发送的自动等待/投递工作并等待任务退出；不存在卸载后继续发送的孤立任务，不操作其他插件任务。
- [ ] 7.2 实现总开关和自动入口开关的独立语义。
  - 验收：关闭总开关停止自动判断和工具发送并取消未发送工作；仅关闭自动入口会停止待执行自动唤起，但总开关开启时合法显式工具仍可发送。
- [ ] 7.3 在源发送前重验最新配置和授权。
  - 验收：预检后、实际源发送前撤销源/目标白名单或关闭总开关时发送次数为零；白名单热更新取消已失效的待执行工作，不依赖开始时的旧配置快照。
- [ ] 7.4 在评论发送前重验权限并保留已发送事实。
  - 验收：0.5 秒等待中关闭插件、撤销目标权限或卸载时不发送评论，源成功记录与目标消息 ID 仍保留；发送进行中取消若结果不确定则保持待核实，不降为可安全重试。
