## MODIFIED Requirements

### Requirement: 同账号查询与源材料可信性

直连实际登录账号 MUST 与可信宿主调用账号一致；目标 MUST 为该账号可确认的合法目标。群目标 MUST 经同账号群名册确认；私聊目标 MUST 经同账号好友名册确认为该账号的好友，未在名册内的 QQ 号 MUST 在发送前拒绝。好友名册 MUST 由固定只读动作查询，条目字段（QQ 号、备注、昵称）MUST 只作为数据使用：插件 MUST NOT 依据备注或昵称匹配、排序或收敛目标，MUST NOT 把名册条目写入日志、账本或投递结果。插件 MUST 先验证宿主源消息归属，再按已核实的标识对应关系查询同账号源消息并验证群归属，不能仅凭可解析的 ID 就认定对应关系成立。合并转发卡片的发送材料 MUST 来自按该源消息卡片标识的展开查询结果：插件只提交平台返回的节点序列（发送者标识与显示名经压平限长，内容段按查询结果原样），MUST NOT 向平台提交调用者提供的卡片资源 ID、消息正文或媒体地址，也 MUST NOT 递归展开或重建节点。展开结果含嵌套内层卡片（节点内容含其它合并转发卡片）时 MUST NOT 提交节点序列，按发送前类型检查整条拒绝；该类型检查的判定口径 MUST 单点定义，与自动入口的只读预识别共用同一判定。卡片节点内容中的媒体引用 MUST 取自该展开查询结果，MUST NOT 接受模型或调用者指定的任意 URL、本机路径或内网地址。请求中断或账号变化 MUST 使旧核验失效，不得在核验后静默切换账号发送。

#### Scenario: 错误账号
- **WHEN** 服务端实际登录账号与可信工具调用账号不同
- **THEN** 在源查询或发送前拒绝，不切换账本键规避差异，不使用另一个端点或账号重试

#### Scenario: 查询返回另一群
- **WHEN** 查询响应中的源群与可信源群不符
- **THEN** 不发送、不把响应正文泄露给模型、不使用其资源构造消息

#### Scenario: 标识对应不足
- **WHEN** 只有宿主内部消息标识，且无法确认对应的平台源消息标识
- **THEN** 明确拒绝，不能截取、重编码或猜测标识后发送

#### Scenario: 嵌套卡片不提交
- **WHEN** 按源消息卡片标识的展开查询结果显示节点内容含其它合并转发卡片
- **THEN** 不提交节点序列、不发送，报告明确的发送前拒绝原因；不递归展开、不改写或摘要有嵌套内容的节点

#### Scenario: 私聊目标非好友
- **WHEN** 私聊目标 QQ 号不在当前账号好友名册内（平台侧同样以业务失败拒绝非好友发送）
- **THEN** 在发送前拒绝并给出可定位原因，不把请求发往平台，不改发到其他目标或换动作重试

#### Scenario: 名册形状不可识别
- **WHEN** 好友名册查询成功但返回形状或条目字段不可识别
- **THEN** 按查询失败处理并拒绝本次私聊投递，不猜测条目、不静默放行

#### Scenario: 核验后连接重建
- **WHEN** 已核对账号的核验完成后，发送前发生请求超时、连接中断、端点配置变化或插件退出
- **THEN** 该阶段不自动继续发送；旧核验失效，只有后续合法新调用在重新核验并通过账本防重后才可能发送

#### Scenario: 卡片资源由平台重建
- **WHEN** 转发合并转发卡片消息
- **THEN** 插件提交按源消息卡片标识展开查询取得的节点序列，不提交、不猜测卡片内部资源 ID；卡片资源由平台按目标群上下文重建（含重新上传卡片内媒体），与旧通道「按标识重建时下载旧签名 URL」的失败模式无关

### Requirement: 有界动作与不重放

动作排队、账号及消息查询、发送等待、回执核验 MUST 有代码常量规定的有限上界，在途请求与后台工作 MUST 不无限积压。插件 MUST 只在固定动作集内执行查询与发送：`get_login_info`、`get_group_list`、`get_msg`、`get_forward_msg`、`get_friend_list`、`send_msg`、`send_forward_msg`、`send_group_forward_msg` 与 `close`；好友名册查询 MUST 与其它只读查询共用同一有界预算，MUST NOT 提交任何发送动作。私聊目标 MUST 复用既有发送动作按目标形态路由：卡片与文字走 `send_forward_msg`（`message_type` 为私聊并带对端账号），图片与评论走 `send_msg` 同参数；MUST NOT 为此新增发送动作，MUST NOT 改用具名私聊发送动作或更换动作 fallback。一次投递 MUST 最多为源提交一个发送动作、为评论提交一个发送动作；请求超时、取消或响应丢失 MUST NOT 触发同一动作重发、切换动作或切换通道探测结果。自动入口的只读预识别查询 MUST 与其它动作共用同一有界预算，MUST NOT 提交任何发送动作；查询失败 MUST NOT 重试，也 MUST NOT 阻断本次自动判断机会。尚未进入发送提交且可以证明未提交的操作 MUST 报告明确未发送；已提交或无法证明未提交的操作 MUST 按真实证据或待核实处理。

#### Scenario: 断线前后
- **WHEN** 发送请求可能已到达平台但响应超时丢失，或连接中断
- **THEN** 当前阶段保持待核实，不重发该请求；同一投递的后续工具调用被账本阻断

#### Scenario: 排队期间撤销权限
- **WHEN** 动作仍在等待发送资格时总开关关闭、权限收缩、分组私聊开关关闭或插件卸载
- **THEN** 该动作在取得执行机会后仍须复验，不提交已失效发送，明确报告未发送

#### Scenario: 私聊复用既有发送动作
- **WHEN** 一次投递的目标是私聊对端
- **THEN** 卡片与文字以 `send_forward_msg` 的私聊路由参数提交，图片与评论以 `send_msg` 的私聊路由参数提交，不引入具名私聊发送动作、不因目标形态更换动作

#### Scenario: 自动入口预搜索有界只读
- **WHEN** 自动入口对合并转发候选项执行嵌套预识别查询
- **THEN** 查询与其它动作共用有界预算、只读、不提交发送；查询失败不阻断本次自动判断机会，也不触发同一查询之外的重试

#### Scenario: 好友名册查询有界只读
- **WHEN** 工具为核验或展示查询好友名册
- **THEN** 查询与其它只读动作共用同一预算与序列化约束，不提交发送、不重试、不改写任何持久状态

#### Scenario: 事件持续到达
- **WHEN** 平台响应缓慢、其他在途工作持续占用或无关请求持续到达
- **THEN** 动作仍按原总期限结束，在途工作不无限积积、不阻止卸载退出

#### Scenario: 并发容量耗尽
- **WHEN** 本插件在途或等待工作达到代码规定的容量上限
- **THEN** 新工作在提交前明确拒绝，不挤掉已知成功记录或强制重发在途动作

### Requirement: 真实回执与安全结果分类

一次源或评论发送 MUST 最多提交一个发送动作。只有合法动作响应与可核实的真实平台目标消息身份一致时，才允许确认发送成功；仅有非空消息 ID、资源 ID 或受理标志 MUST NOT 视为成功。平台目标消息 ID MAY 为负值，核验 MUST 按返回原值逐字比对，MUST NOT 假设其为正整数。回执核验 MUST 确认目标、发送账号及平台消息证据（含正整数平台消息序列），且 MUST 按目标形态比对：群目标 MUST 核验 `message_type` 为群且目标群号与请求一致；私聊目标 MUST 核验 `message_type` 为私聊、对端账号与请求的私聊目标一致且发送账号为机器人自身。查询次数 MUST 有限且仅针对该次返回的目标标识，MUST NOT 通过再次发送来核实。业务失败响应（如查询目标不存在、非好友发送被平台拒绝）属明确业务结果，不改变「未提交即明确未发送、已提交无证据即待核实」的分类。模糊失败、未知返回状态、缺失关键证据、查询超时、取消及无法判断是否已提交的异常 MUST 保守归为待核实，不能用通用错误码猜成可重试失败。

#### Scenario: 成功响应但标识不足
- **WHEN** 动作报告成功但没有可核实的真实目标消息标识
- **THEN** 不报告完整成功，不自动重试，源未知时不发送评论

#### Scenario: 回执不属于本次投递
- **WHEN** 查询所得目标、发送账号或平台消息证据与本次请求不匹配
- **THEN** 保持待核实，不把其他群、其他对端或其他账号的消息记为本次成功

#### Scenario: 负数目标消息 ID
- **WHEN** 发送动作返回负值消息 ID（群与私聊路径都实测出现过）
- **THEN** 按原值回查并核验对应形态的目标证据，不因符号拒绝，也不改写为其他形式

#### Scenario: 私聊回执按对端核验
- **WHEN** 一次私聊目标的源或评论发送返回目标消息 ID
- **THEN** 回查确认 `message_type` 为私聊、对端账号等于本次请求的私聊目标、发送账号为机器人自身，并有正整数平台消息序列，才可确认成功

#### Scenario: 平台拒绝非好友发送
- **WHEN** 私聊目标在名册核验后仍被平台以业务失败拒绝（如好友关系已变更）
- **THEN** 按明确业务失败归类，不重试、不改发其他目标、不换动作

#### Scenario: 额外资源标识不是证据
- **WHEN** 卡片发送动作在目标消息 ID 之外返回资源类标识（res_id / forward_id）
- **THEN** 资源类标识 MUST NOT 作为成功证据、不入账、不进工具结果；成功判定只认目标消息 ID与目标证据

#### Scenario: 发送后查询失败
- **WHEN** 发送请求可能成功，但有限回执查询无法完成
- **THEN** 保留已知候选回执信息但不伪称已验证成功，禁止重发和后续评论

#### Scenario: 明确未提交
- **WHEN** 发送前校验失败，或能证明尚未进入发送提交
- **THEN** 明确报告未发送；后续只有新的合法工具调用才可能重新尝试，不自动重试
