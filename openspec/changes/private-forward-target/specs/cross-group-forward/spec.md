## ADDED Requirements

### Requirement: 好友名册只读查询

插件 MUST 向群聊 Maisaka 暴露只读工具 `list_forward_friends`，公开参数 MUST 为空。它 MUST 与 `forward_message` 共用同一条一次性来源凭据链（凭据只由宿主 Planner 输出载荷签发、首次消费作废），不接受模型自报的会话、平台、账号或授权字段。工具 MUST 仅在调用来源群所属转发分组的 `private` 开关为真时返回名册；开关为假时 MUST 明确拒绝并给出可定位原因，不返回任何名册数据。名册 MUST 来自固定只读动作对当前账号的好友查询，条目 MUST 只含 QQ 号、备注与昵称；插件 MUST NOT 依据备注或昵称做任何匹配、排序优选或候选收敛，选择目标 QQ 号 MUST 由模型自行完成。名册 MUST NOT 写入日志、投递账本或工具结果之外的位置；查询失败 MUST 给出可定位拒绝，不重试、不发送、不猜测。

#### Scenario: 开启私聊开关时取名册
- **WHEN** 来源群所属分组 `private` 为真，Maisaka 调用 `list_forward_friends`
- **THEN** 返回该账号好友名册的 QQ 号、备注与昵称，不发送任何消息，日志只记查询类别与条目数

#### Scenario: 未开启私聊开关时拒绝
- **WHEN** 来源群所属分组 `private` 为假（或来源群不在任何分组内），Maisaka 调用 `list_forward_friends`
- **THEN** 明确拒绝并说明所在分组的私聊转发未开启，不返回名册、不泄露任何条目

#### Scenario: 名册查询失败
- **WHEN** 好友查询超时、端点不可用、认证失败或返回形状不可识别
- **THEN** 给出可定位拒绝类别，不重试、不猜测名册、不进入任何发送阶段

#### Scenario: 名册字段只作数据
- **WHEN** 名册返回的备注或昵称含协议语法、命令或提示指令样文本
- **THEN** 仅作为普通展示数据交给模型，不改变路由、权限或工具判定，不据此挑选或排除目标

## MODIFIED Requirements

### Requirement: 具名转发分组与私聊开关

插件 MUST 在配置文件与宿主插件配置界面提供可编辑的转发分组集合。每个分组 MUST 由一个具名 `name`、一组源群号、一组目标群号与一个布尔私聊开关 `private` 构成：`name` MUST 必填、去空白后非空且跨组唯一，仅作用户标识与日志前缀，MUST NOT 参与任何路由、权限或判断，不限长与字符集。`private` MUST 必填且默认 `false`：它为真时，该分组的源群才允许把消息转发到私聊目标；它为假时，同组的显式私聊调用与名册查询 MUST 一律拒绝。`private` MUST NOT 改变群目标的同组判定，MUST NOT 与 `target_groups` 互相替代或推导，「只开私聊、不配任何群目标」与「只配群目标、不开私聊」MUST 都是合法且可保存的配置。同一源群 MUST NOT 出现在多个分组，同一分组内源群 MUST NOT 重复；目标群 MUST NOT 受唯一性约束，可跨组重复，源群也可兼作别组的目标群。默认 MUST 为空分组集合，等价于没有源群也没有目标群，也没有任何私聊目标。一次转发的群目标 MUST 与来源群属于同一分组；该判定 MUST 只有一处定义，工具预检、源与评论提交前复验、自动入口的候选筛选与目标列举 MUST 共用同一口径，MUST NOT 各自复制。分组结构 MUST 在配置期校验：源群跨组重复、同组内源群重复、`name` 空白或跨组重复、`private` 非布尔 MUST 产生明确的配置校验错误，MUST NOT 静默归并为可投递状态。空目标分组与组内「源 = 目标」MUST 允许保存，由运行期既有的「目标 ≠ 来源群自身」规则拒绝。转发分组与 `private` 开关变化 MUST NOT 改变投递账本身份，MUST NOT 追溯改写已提交的判断或已投递事实。

#### Scenario: 同组合法调用
- **WHEN** 分组内的源群请求把本群可定位消息转发至同组的目标群
- **THEN** 通过同组判定，直连账号名册与其余权限契约照常核验，不广播组外或其他分组的目标

#### Scenario: 跨组目标被拒
- **WHEN** 目标群存在但不与来源群同组（只在别的分组，或不在任何分组内）
- **THEN** 发送前整条拒绝并给出可定位原因，不向模型或其他群泄露越权内容

#### Scenario: 目标群跨组重复
- **WHEN** 同一目标群号出现在多个分组的 `target_groups` 中
- **THEN** 每个分组的源群都可投递给它，同组判定不因跨组重复而拒绝合法调用

#### Scenario: 源群兼作别组目标
- **WHEN** 群 A 是分组 X 的源群，同时列在分组 Y 的 `target_groups` 中
- **THEN** 分组 Y 的源群可投递给 A；A 作为源群仍只能投本组（X）的目标，「目标 ≠ 来源群自身」规则不变

#### Scenario: 分组结构校验拒绝
- **WHEN** 配置中源群出现在两个分组、同一分组内源群重复、`name` 为空白或跨组重复，或 `private` 不是布尔值
- **THEN** 给出明确的配置校验错误，不保存、不静默合并成一个分组，也不放行部分配置

#### Scenario: 空目标分组
- **WHEN** 某分组配了源群但目标群为空
- **THEN** 配置允许保存；该源群的显式群目标调用与自动判断均因没有合法同组目标而拒绝，不影响其他分组

#### Scenario: 默认空分组
- **WHEN** 新安装未配置任何分组
- **THEN** 没有源群也没有目标群，私聊开关一律为假：不触发自动判断，显式调用得到拒绝，不产生任何发送

#### Scenario: 私聊开关默认关闭
- **WHEN** 某分组已配置源群与目标群但未设置 `private`
- **THEN** 按关闭处理：该分组的私聊目标调用与名册查询一律拒绝，群目标行为不受影响

#### Scenario: 只开私聊不放群目标
- **WHEN** 某分组 `private` 为真且 `target_groups` 为空
- **THEN** 该分组的源群可合法发起私聊目标显式调用；自动判断仍因没有同组合法目标群而不唤起

#### Scenario: 私聊开关不改变群目标判定
- **WHEN** 某分组 `private` 为真，其源群请求一个不在该分组的群目标
- **THEN** 仍按同组判定拒绝，私聊开关不放宽任何群目标权限

#### Scenario: 转发热更新收紧分组
- **WHEN** 源已成功落账、评论尚未提交时，目标群被移出来源群所属分组
- **THEN** 评论提交前复验失败，本次评论按明确未发送报告；已提交的源投递事实不回滚，账本不变

#### Scenario: 热更新关闭私聊开关
- **WHEN** 源已成功落账、私聊评论尚未提交时，来源群所属分组的 `private` 被改为假
- **THEN** 评论提交前复验失败，本次评论按明确未发送报告；已提交的源投递事实不回滚，账本不变

### Requirement: 群聊转发工具与双形态目标权限

插件 MUST 向群聊 Maisaka 暴露 `forward_message`。公开参数 MUST 为：必填字符串 `message_id`；两个目标参数 `target_group_id`（群目标）与 `target_user_id`（私聊目标）中 MUST 恰好提供一个，二者同时缺失或同时提供 MUST 在发送前拒绝；可选字符串 `comment`（默认空）。可信调用上下文 MUST 来自宿主，不信任模型自填的平台、账号、源群、会话或授权字段。源群 MUST 属于某个转发分组，源消息 MUST 属于调用所在群及机器人账号对应的 QQ 范围。群目标 MUST 与源群属于同一转发分组、不同于源群，并经直连查询确认账号及平台目标可用。私聊目标 MUST 满足：来源群所属分组的 `private` 为真；目标 QQ 号经直连只读好友名册确认为同一账号的好友；插件 MUST NOT 依据昵称或备注匹配目标。缺失、非法 ID、来源为私聊、越权、源不可定位 MUST 在发送前拒绝，且不泄露越权消息内容。评论 MUST 按普通文本发送，随目标形态分别送达原目标群或同一私聊对端。

#### Scenario: 合法调用
- **WHEN** 转发分组内的源群请求将本群可定位消息转发至同组的另一目标群
- **THEN** 宿主可信来源与直连源归属核对均通过后，仅向指定目标发送，不广播所有目标

#### Scenario: 私聊目标合法调用
- **WHEN** 来源群所属分组 `private` 为真，模型提交本群可定位消息的 `message_id`、名册内好友的 QQ 号作为 `target_user_id`
- **THEN** 与群目标相同的来源、账号、内容完整性与防重核验通过后，仅向该私聊对端发送，不向任何群广播，也不向名册外的人发送

#### Scenario: 目标参数缺失或重复
- **WHEN** 模型同时省略 `target_group_id` 与 `target_user_id`，或同时提供两者
- **THEN** 发送前整条拒绝并说明必须二选一，不默认选群、不默认选私聊，不产生任何发送

#### Scenario: 非好友私聊目标
- **WHEN** `target_user_id` 提交的 QQ 号不在当前账号好友名册内（含名册外真人、已删除好友与不存在的账号）
- **THEN** 发送前整条拒绝并给出可定位原因，不把请求发往平台，不按昵称或备注猜测替代目标

#### Scenario: 私聊开关关闭
- **WHEN** 来源群所属分组 `private` 为假，模型提交 `target_user_id`
- **THEN** 发送前整条拒绝并说明该分组未开启私聊转发；群目标调用不受影响

#### Scenario: 伪造上下文
- **WHEN** 模型提交其他源群消息 ID 或伪造账号、会话、凭据字段
- **THEN** 按可信来源拒绝，不查询后向模型泄露其他群消息正文

#### Scenario: 目标无权限
- **WHEN** 目标为源群自身、不与来源群同组或直连账号不匹配
- **THEN** 不发送源消息或评论，返回具体原因；不能改用任意适配器或其他账号

#### Scenario: 源消息标识无法对应
- **WHEN** 宿主消息 ID 不能可靠对应为同账号下的 OneBot 源消息
- **THEN** 发送前拒绝，不把宿主内部 ID、资源 ID 或猜测值当作平台源消息 ID

### Requirement: 自动入口由源群决定

转发分组内的源群收到属于所选候选类型、非机器人自身、非通知的 QQ 消息后，插件 MUST 在消息完成处理并可供源群读取后给予源群 Maisaka 一次主动判断机会，重复上报 MUST 被抑制。源消息 MUST 正常进入主处理链。自动入口 MUST 只从宿主已处理入站事件观察消息、只唤起源群 Planner，MUST NOT 直接执行转发。Maisaka MUST 获得当前自动分享标准，并能选择沉默或选择同组允许目标调用同一个转发工具；只有实际合法工具调用才允许执行发送。自动入口 MUST NOT 把私聊纳入范围：意图与合法目标列举 MUST 只含来源群所属分组的同组目标群，MUST NOT 提供好友名册、MUST NOT 举荐任何私聊目标。模型在自动唤起后自行提交私聊目标调用时，MUST 按与显式调用完全相同的权限口径判定（来源群所属分组 `private` 为真且目标为账号好友），插件 MUST NOT 因「本次判断由主动唤起触发」额外放行或额外拒绝。直连客户端 MUST NOT 判断分享价值、选择目标、调用模型、掷骰或强制目标群评论。普通文字和图片 MUST 仅在对应类型被选中时触发自动入口。宿主未展开卡片仍可参与候选分类，实际发送取决于同账号可信源资源，不要求宿主逐节点恢复；分类 MUST NOT 承诺可发送。

对分类为合并转发的候选，插件 MUST 在可读性确认与配置初检之后、目标名称查询之前，以只读查询预识别卡片内容是否含嵌套内层卡片：按与工具路径相同的两步只读查询（源消息查询取平台卡片标识、按卡片标识展开查询）判定，命中 MUST NOT 提供判断机会并记录可定位原因；查询失败、取不到卡片标识或结果不可判定时 MUST 照常提供判断机会，由工具路径在发送前权威拒绝。预搜索 MUST NOT 发送任何消息、MUST NOT 改变候选分类口径与同组目标列举，MUST NOT 替代发送前类型检查。

#### Scenario: 自主分享
- **WHEN** 分组内源群的合并转发处理完成、类型已选、存在同组合法目标且尚未触发判断
- **THEN** 只给源群 Planner 一次机会，Maisaka 获得源消息 ID、同组合法目标和标准，可调用工具或沉默

#### Scenario: 自动意图不含私聊
- **WHEN** 一次自动判断机会被提交给源群 Planner
- **THEN** 意图只列同组目标群与可用群名，不含任何私聊目标或好友名册信息，不把私聊说成可选目标

#### Scenario: 主动唤起后模型自行选择私聊目标
- **WHEN** 自动唤起后 Maisaka 从别处获得一个 QQ 号并以其作为 `target_user_id` 调用工具
- **THEN** 按显式口径核验分组私聊开关与好友关系，不放行也不额外拒绝；插件不举荐、不补全、不记住该来源差异

#### Scenario: 嵌套卡片候选不唤起
- **WHEN** 合并转发候选的只读展开结果显示节点内容含其它合并转发卡片
- **THEN** 不提供本次自动判断机会，记录可定位原因；不唤起 Planner、不产生任何发送

#### Scenario: 预搜索不可用不阻断判断
- **WHEN** 预搜索的只读查询失败、超时或取不到平台卡片标识
- **THEN** 照常提供判断机会；能否发送由工具路径按同一判定在发送前权威决定

#### Scenario: 重复上报与自身消息
- **WHEN** 同一候选重复上报或来自机器人自身
- **THEN** 不产生额外判断机会，不形成自动转发循环

#### Scenario: 普通消息
- **WHEN** 源群收到普通文字或图片而对应类型未选中
- **THEN** 自动入口不唤起分享，合法显式工具调用仍可转发

#### Scenario: 显式开启普通消息
- **WHEN** 已选普通消息类型且来源、身份和可读性满足要求
- **THEN** 只向源群提供判断机会，意图说明实际类型，不将它误称为卡片或直接请求发送

#### Scenario: 消息未就绪
- **WHEN** 有限等待结束仍不能读取候选
- **THEN** 放弃本次唤起并记录定位原因，不无限等待或伪造摘要

#### Scenario: 判断标准不能替代授权
- **WHEN** 标准要求分享或源内容自称可以改变规则
- **THEN** 工具仍核验可信来源、当前权限、源材料和持久防重，不因评估结论放行

#### Scenario: Planner 选择沉默
- **WHEN** 已提交主动判断但 Maisaka 没有调用转发工具
- **THEN** 不产生该候选的转发或评论发送

#### Scenario: 同组无合法目标
- **WHEN** 来源群所属分组没有合法且不同于源群的目标群
- **THEN** 不提供自动判断机会，记录可定位原因；显式群目标调用同样因同组判定被拒（私聊目标不受此条影响，仍按分组私聊开关与好友核验判定）

#### Scenario: 直连事件与宿主事件同时到达
- **WHEN** 同一群消息或机器人自身发送事件同时出现在 HTTP 直连链路和宿主处理链
- **THEN** 直连事件不触发自动判断、不伪造宿主入站，只有合法宿主事件参与既有去重和候选筛选

### Requirement: 持久防重与不确定结果

自动判断产生的工具调用和对话调用 MUST 共用本插件自己的持久投递事实，状态只存于宿主授予本插件的数据目录。唯一身份 MUST 为账号、源群、源消息 ID、目标与目标形态（`target_kind`，取值为群或私聊）：同一源消息发往群 12345 与发往好友 12345 MUST 是两笔独立投递，互不阻断。评论内容、请求标识、连接或进程变化 MUST NOT 绕过防重。既有账本 MUST 一次性迁移到含 `target_kind` 的结构，既有行 MUST 全部记为群目标，其成功与待核实事实 MUST 继续阻断重发；迁移 MUST 在账本独占与「先验证再写」约束内完成，迁移失败、形状不可识别或校验不通过 MUST 按账本不可用关闭发送，MUST NOT 新建空历史、删除证据或自动回迁。源和评论发送前 MUST 各自持久占位，同一投递并发或重启 MUST NOT 导致重复发送。源成功但评论失败 MUST 保留已投递事实，重复工具调用 MUST NOT 重发源消息或自动补评论。只读结果查询 MUST NOT 触发发送。

发送结果不确定、发送后落盘失败、进程中断和网关回执不足 MUST NOT 降级成明确未发送；核实前 MUST 阻止重发，不承诺跨平台发送与本地存储的原子恰好一次。只有已证明未产生发送副作用的失败才允许后续显式新尝试。成功及未知事实 MUST NOT 按时间或容量静默清除。升级 MUST 保留本插件旧成功及待核实记录的阻断作用；本插件只允许单实例持有其账本。账本不可用、恢复失败、升级历史无法确认或迁移未完成时 MUST 关闭发送。历史核对 MUST 只针对状态类证据，MUST NOT 因插件自身的源码、文档、配置或缓存文件而关闭发送。

#### Scenario: 跨重启重复调用
- **WHEN** 成功投递后重启插件或重建连接，并以新请求标识或不同评论再次调用同一投递
- **THEN** 返回已有结果，不发送源或评论

#### Scenario: 同号群与私聊互不阻断
- **WHEN** 同一源消息已成功发往群 12345，随后合法调用请求以好友 12345 为 `target_user_id`
- **THEN** 按不同目标身份独立校验并允许投递，不因群投递记录判定重复

#### Scenario: 私聊改投同名群
- **WHEN** 同一源消息已成功发给好友 12345，随后合法调用请求群目标 12345
- **THEN** 按不同目标身份独立校验并允许投递，不因私聊记录判定重复

#### Scenario: 既有账本迁移保留阻断
- **WHEN** 打开含成功与待核实记录的旧四字段账本
- **THEN** 在独占与验证通过后完成一次性迁移，旧行全部记为群目标并继续阻断重发；迁移前后的记录数与状态一致，不新建、不删除、不改写状态

#### Scenario: 迁移失败关闭发送
- **WHEN** 迁移过程中校验不通过、形状不可识别、独占失败或写入未确认
- **THEN** 按账本不可用关闭发送并给出可定位原因，不降级为四字段继续运行，不假装迁移成功

#### Scenario: 评论失败
- **WHEN** 源已确认发送而评论失败或未通过发送前复验
- **THEN** 返回部分成功，保留源目标 ID，不重发源消息

#### Scenario: 结果未知
- **WHEN** 请求可能已到 SnowLuma 但回执丢失，或恢复出未完成的源/评论发送记录
- **THEN** 相应阶段保持待核实，阻止重发；源成功事实不因评论未知被抹除，只读查询不发送

#### Scenario: 同消息不同目标
- **WHEN** 源消息已发往 A，随后合法调用请求 B
- **THEN** 使用不同投递身份独立校验，不因 A 的记录阻止 B

#### Scenario: 旧账本迁移
- **WHEN** 本插件原账本仍是完整权威，包含成功或不确定记录
- **THEN** 启用直连前验证并保留其阻断作用，不要求迁移到独立服务，不当作空历史

#### Scenario: 服务历史尚未核对
- **WHEN** 本插件目录存在服务绑定收据、旧账本归档、主库以外的数据库或无法解释的状态类证据，或不能确认原账本是否完整
- **THEN** 关闭发送并提示人工核对，不凭「零迁移」承诺忽略服务投递事实，不创建空库、不自动回迁或删除切换证据

#### Scenario: 插件自身部署文件不构成历史证据
- **WHEN** 状态目录同时存放插件源码、文档、配置或缓存（宿主把 `data_dir` 指向插件目录）
- **THEN** 账本按既有成功与待核实事实正常打开并继续阻断重发，不因这些部署文件而关闭发送

#### Scenario: 发送前后账本失败
- **WHEN** 发送前占位失败，或取得真实成功回执后终态落账失败
- **THEN** 前者不发送；后者报告已知真实目标 ID 和未落账限制、停止后续阶段，已有占位阻止重发，不声称完整成功

#### Scenario: 同一数据目录重复加载
- **WHEN** 另一插件实例仍持有同一账本的独占使用权
- **THEN** 新实例拒绝启用发送，不恢复或修改另一活实例的在途记录

### Requirement: 结果与生命周期

工具 MUST 等待本次源发送及所请求评论的实际结果或有界超时，维持完整成功、部分成功、已转发、发送中、拒绝、明确失败、结果未知及账本不可用的区别，报告已取得的真实目标 ID 与错误阶段。结果 MUST 标明目标形态（群或私聊）与目标标识（目标群号或私聊对端 QQ 号），使源群可核对自己投到了哪里；MUST NOT 在结果或日志中夹带好友名册其它条目、备注或昵称。请求仅受理、超时或本地任务取消 MUST NOT 被宣称为发送成功或已确定未发送。评论结果未落账时 MUST NOT 声称其结果已可靠保存。

关闭插件、卸载或权限收缩时 MUST 阻止尚未提交的源或评论动作，并在实际提交前按最新配置复验：群目标复验同组判定，私聊目标复验来源群所属分组的 `private` 开关。已提交动作 MUST 按真实结果或未知保守处理，MUST NOT 因本地取消而登记可重试失败。卸载 MUST 只取消和有界等待本插件自己的任务、结束本插件自己的在途请求、释放自己的账本；超时 MUST 告警定位未退出工作，不影响其他客户端。重启 MUST 不自动续发源或评论。

候选类型移除 MUST 取消尚未发起的失效自动判断；分享标准更新 MUST 不追溯已提交判断。`private` 开关关闭 MUST 在源与评论提交前复验时使尚未提交的私聊阶段按明确未发送报告。日志 MUST 能定位源消息、目标与阶段，不记录凭证、名册或原文。

#### Scenario: 评论等待期间关闭
- **WHEN** 源已成功，评论尚未提交时关闭插件或撤销权限
- **THEN** 不提交评论，源结果仍报告成功投递，整体如实报告部分成功

#### Scenario: 等待真实结果
- **WHEN** 目标发送请求仍在进行
- **THEN** 工具不提前返回完整成功；超时报告实际已知事实或未知，不把受理当成回执

#### Scenario: 等待期间关闭私聊开关
- **WHEN** 私聊目标源已成功、评论尚未提交时所在分组 `private` 被改为假
- **THEN** 评论提交前复验失败，本次评论按明确未发送报告，不补发、不降级为待核实

#### Scenario: 私聊结果可读
- **WHEN** 一次私聊目标转发与评论获得平台成功回执并落账
- **THEN** 工具结果标明私聊形态与对端 QQ 号及两条真实目标消息 ID，不含名册其它条目

#### Scenario: 等待期间移除候选类型
- **WHEN** 候选仍在等待可读性或目标名称，且其类型被移除
- **THEN** 不再提交判断，不影响其他合法候选或整体取消已有平台副作用

#### Scenario: 唤起前修改标准与目标
- **WHEN** 自动判断尚未提交时标准或转发分组更新
- **THEN** 唤起前使用最新标准和同组合法目标，必要时省略旧名称，不携带过期授权

#### Scenario: 已提交的判断不追溯重写
- **WHEN** 判断已经交给宿主后才修改配置
- **THEN** 不宣称旧判断已撤回，也不为同一候选再唤起；之后实际工具调用仍按最新权限校验

#### Scenario: 远端撤销竞态
- **WHEN** 源或评论等待查询、复验或发送排队期间发生卸载、关闭或权限收缩
- **THEN** 提交前复验失败就不提交、报告明确未发送；已经进入发送提交且无法证明未发时报告真实结果或未知，不声称已远端撤回

#### Scenario: 卸载与其他客户端并存
- **WHEN** 插件卸载时同一 SnowLuma 服务端还有其他客户端在活动
- **THEN** 仅结束本插件自己的在途请求与工作；残留工作按源消息、目标和阶段告警，不注销 QQ 账号或影响其他客户端
